Método de Disparo · Práctica (Haskell)

Nota Práctica
Leyendo en: — (cambiar)
← Nota conceptual · ← Implementación · Autoevaluación →

Aquí no se trata de leer, sino de ejecutar. Vas a convertir un problema de frontera (ψ(0)=ψ(L)=0) en la búsqueda del cero de una función escalar f(E) — el método de disparo, que es la composición de integrar, leer el extremo y bisecar. El computador hace exactamente lo que escribes: si la ventana de energía no encierra un cero, la bisección te dará cualquier cosa. Al final entregarás la evidencia de tu criterio: por qué cuantizar es, en el fondo, encontrar raíces.

Cómo ejecutar. Entra al entorno del curso con nix develop y corre cada ejercicio con runghc ejercicio.hs. Binario optimizado: ghc -O2 ejercicio.hs -o ej && ./ej. Locale UTF-8: LANG=C.UTF-8 runghc ejercicio.hs.

Ejercicio 1 · Los niveles son ceros de f(E)

shoot E integra desde 0 con energía E y devuelve ψ(L). Los valores de E que anulan ψ(L) son los niveles permitidos. Compón integrar + bisección y recupera E₁ del pozo infinito, comparándolo con π²/2.

import Data.List (unfoldr)

numerov :: (Double->Double) -> Double -> Double -> (Double,Double) -> [Double]
numerov f h x0 (p0,p1) = p0:p1:unfoldr step (p0,p1,x0+h)
  where w x = 1 - h*h/12*f x
        step (pm1,q0,x) = let q1=(2*q0*(1+5*h*h/12*f x) - pm1*w (x-h))/w (x+h) in Just (q1,(q0,q1,x+h))

-- f(E) = ψ(L): integra el pozo (V=0, f=−2E) y devuelve el extremo. Arranque ψ₁=sin(√(2E)·h).
shoot :: Double -> Int -> Double -> Double
shoot l ng e = let h = l/fromIntegral ng; k = sqrt (2*e)
               in last (take (ng+1) (numerov (\_ -> -2*e) h 0 (0, sin (k*h))))

-- bisección sobre E: busca un cero de shoot en [lo,hi]
bisectE :: Double -> Int -> Double -> Double -> Double
bisectE l ng lo0 hi0 = go lo0 hi0
  where f = shoot l ng
        go lo hi | hi-lo < 1e-12 = (lo+hi)/2
                 | otherwise = let m = (lo+hi)/2
                               in if signum (f lo) == signum (f m) then go m hi else go lo m

main :: IO ()
main = do
  let l = 1.0; ng = 2000; exact n = fromIntegral (n*n)*pi*pi/(2*l*l)
  putStrLn $ "E1 shoot = " ++ show (bisectE l ng (exact 1*0.8) (exact 1*1.05))
  putStrLn $ "E1 exact = " ++ show (exact 1)
Resultado esperado 
E1 shoot = 4.93480220073986
E1 exact = 4.934802200544679
Pista (ábrela solo si te atascas)

E₁ = 4.9348 = π²/2 a nueve cifras. Toda la física vive en shoot; bisectE es un buscador de raíces genérico que no sabe de cuántica. La clave es que la ventana [0.8·E_exacto, 1.05·E_exacto] encierre el cero con un cambio de signo: si tomas una ventana que contenga dos niveles, la bisección se confunde. El arranque ψ₁ = sin(√(2E)·h) (en vez de un h cualquiera) evita contaminar el espectro con error de arranque.

Ejercicio 2 · Sube de nivel (tu turno)

Cada nivel Eₙ = n²π²/2 es un cero distinto de f(E). La semilla halla E₁. Tu turno: cambia la ventana para capturar E₂ (alrededor de 4·E₁) y verifica contra 4π²/2. Documenta cómo elegiste la ventana para no atrapar el nivel equivocado.

-- (mismas numerov, shoot, bisectE del Ejercicio 1)

main :: IO ()
main = do
  let l = 1.0; ng = 2000; exact n = fromIntegral (n*n)*pi*pi/(2*l*l)
  -- ← TU TURNO: cambia el índice a n=2 (E₂ ≈ 4·E₁). Ajusta la ventana alrededor de exact 2.
  let n = 1
  putStrLn $ "E" ++ show n ++ " shoot = " ++ show (bisectE l ng (exact n*0.8) (exact n*1.05))
  putStrLn $ "E" ++ show n ++ " exact = " ++ show (exact n)
Resultado esperado (con n=2) 
E2 shoot = 19.739208802693792
E2 exact = 19.739208802178716
Pista (ábrela solo si te atascas)

E₂ = 19.739 = 4·(π²/2): el segundo nivel, con una función de onda que tiene un nodo interior. La ventana [0.8·E₂, 1.05·E₂] funciona porque encierra solo a E₂. Si usaras [0, E₂·1.05] atraparías también a E₁ y la bisección podría converger a cualquiera de los dos (o fallar, si hay número par de ceros). Para barrer todo el espectro, lo robusto es localizar primero los cambios de signo de f(E) sobre una rejilla fina de E, y bisecar dentro de cada uno — combínalo con el conteo de Sturm de u4/t2.

⬡ Enseña al estudiante obtuso

La IA hará exactamente lo que le pidas — incluso lo equivocado. Úsala como banco de pruebas de tu criterio: pídele que justifique, que rompa, que proponga la alternativa que descartaste. Si no sabes por qué su respuesta es buena o mala, aún no dominas el tema.

  • «Barre f(E) sobre una rejilla y localízame automáticamente los primeros cuatro cambios de signo, luego biseca cada uno. ¿Recuperas n²π²/2?»
  • «Cámbiame el pozo por un oscilador armónico (V=x²/2) y dispárame sus niveles. ¿Salen E_n = n+½?»
  • «En la región evanescente ψ desborda double. Reescríbeme el disparo con la derivada logarítmica (Riccati) y muéstrame que evita el overflow.»
  • «Explícame por qué cuantizar (energías discretas) emerge de una condición de frontera continua, sin postular nada discreto de entrada.»
