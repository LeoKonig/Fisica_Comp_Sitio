Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con Idris2 0.7.0.

Hay dos tipos de bloque:

  • Definiciones (sin prompt): van en un archivo U1T1.idr.
  • Consultas (con el prompt U1T1>): se escriben en el REPL, sin el prompt. Abre el REPL con idris2 U1T1.idr y usa :r para recargar el archivo cuando añadas algo.

El módulo Exacto.idr

La biblioteca base de Idris2 no trae números racionales. Para tener “la verdad exacta” contra la cual comparar a la máquina, usaremos en toda la unidad un módulo pequeño, Exacto.idr. Cópialo una sola vez en la misma carpeta que tus notas. Ofrece estas funciones:

Nombre Qué es
Racional Fracciones exactas de enteros, \(\mathbb{Q}\). El REPL las muestra como MkR n d, que significa \(n/d\).
n // d La fracción exacta \(n/d\).
aRacional x El valor exacto, en \(\mathbb{Q}\), que guarda el Double x.
fl q El redondeo de \(\mathbb{Q}\) al Double más cercano, con empates al par.
aDouble q Lo mismo que fl; lo usamos para leer un resultado exacto, por ejemplo un error relativo.
flSimple q El redondeo a precisión simple (24 bits); lo usaremos en u1t2.

No hace falta leer su código para usarlo. Si te interesa, está aquí:

El código de Exacto.idr (opcional)

Archivo Exacto.idr:

||| Aritmética exacta para comparar con Double.
||| Racional: fracciones de enteros sin redondeo (ℚ).
||| aRacional: el valor EXACTO que guarda un Double.
||| fl: redondeo de ℚ al Double más cercano (empates al par).
||| flSimple: lo mismo, pero a precisión simple (24 bits).
module Exacto

%default total

-- ── Racionales ───────────────────────────────────────────────────

||| n / d con d > 0 y la fracción reducida.
public export
record Racional where
  constructor MkR
  num : Integer
  den : Integer

mcd : Integer -> Integer -> Integer
mcd a 0 = abs a
mcd a b = assert_total (mcd b (a `mod` b))

||| Construye n / d ya reducida.
export
racional : Integer -> Integer -> Racional
racional n d =
  let g = mcd n d
      s = if d < 0 then -1 else 1
  in if g == 0 then MkR 0 1 else MkR (s * (n `div` g)) (s * (d `div` g))

export infixl 9 //

||| n // d es la fracción exacta n/d.
export
(//) : Integer -> Integer -> Racional
n // d = racional n d

export
Num Racional where
  (MkR a b) + (MkR c d) = racional (a * d + c * b) (b * d)
  (MkR a b) * (MkR c d) = racional (a * c) (b * d)
  fromInteger n = MkR n 1

export
Neg Racional where
  negate (MkR a b) = MkR (negate a) b
  (MkR a b) - (MkR c d) = racional (a * d - c * b) (b * d)

export
Abs Racional where
  abs (MkR a b) = MkR (abs a) b

export
Fractional Racional where
  (MkR a b) / (MkR c d) = racional (a * d) (b * c)

export
Eq Racional where
  (MkR a b) == (MkR c d) = a * d == c * b

export
Ord Racional where
  compare (MkR a b) (MkR c d) = compare (a * d) (c * b)

export
Show Racional where
  show (MkR n 1) = show n
  show (MkR n d) = show n ++ "/" ++ show d

-- ── Potencias de dos ─────────────────────────────────────────────

export
pot2 : Nat -> Integer
pot2 Z     = 1
pot2 (S k) = 2 * pot2 k

-- ── Double → ℚ, exacto ───────────────────────────────────────────

||| Multiplica por 2 (operación exacta) hasta que x sea entero.
||| Como todo Double finito es m·2^e, a lo más 1074 pasos bastan.
decodificar : Nat -> Double -> Nat -> (Double, Nat)
decodificar Z     x k = (x, k)
decodificar (S f) x k = if x == floor x then (x, k) else decodificar f (2.0 * x) (S k)

||| El valor exacto, en ℚ, que guarda un Double finito.
export
aRacional : Double -> Racional
aRacional x =
  if x < 0.0 then negate (aRacional' (negate x)) else aRacional' x
  where
    aRacional' : Double -> Racional
    aRacional' y = let (m, k) = decodificar 1100 y 0
                   in racional (cast m) (pot2 k)

-- ── ℚ → Double: fl, redondeo al más cercano, empates al par ─────

||| Número de bits de un entero positivo.
bits : Integer -> Nat
bits n = go 2100 n 0
  where
    go : Nat -> Integer -> Nat -> Nat
    go Z     _ acc = acc
    go (S f) m acc = if m <= 0 then acc else go f (m `div` 2) (S acc)

||| Redondea un racional positivo a un formato binario con
||| p bits de mantisa y último bit de valor mínimo 2^qmin
||| (qmin = −1074 en doble precisión, −149 en simple).
redondearPos : (p : Nat) -> (qmin : Integer) -> Racional -> Double
redondearPos p qmin (MkR n d) =
  let e0 = cast {to = Integer} (bits d) - cast (bits n) + cast p
      e  = if e0 > negate qmin then negate qmin else e0   -- subnormales
      -- q = ⌊ n·2^e / d ⌋ y su resto
      (a, b) = escalar e
      q0 = a `div` b
      r0 = a `mod` b
      -- si q0 tiene un bit de más, lo quitamos
      (q, r, b', e') = if q0 >= pot2 p
                         then (q0 `div` 2, r0 + (q0 `mod` 2) * b, 2 * b, e - 1)
                         else (q0, r0, b, e)
      -- redondeo al más cercano; en empate, al par
      qr = if 2 * r > b' || (2 * r == b' && q `mod` 2 == 1) then q + 1 else q
  in cast {to = Double} qr * pow 2.0 (cast (negate e'))
  where
    escalar : Integer -> (Integer, Integer)
    escalar e = if e >= 0 then (n * pot2 (cast e), d) else (n, d * pot2 (cast (negate e)))

redondear : Nat -> Integer -> Double -> Racional -> Double
redondear p qmin maximo r@(MkR n _) =
  if n == 0 then 0.0
  else let v = redondearPos p qmin (abs r)
           w = if v > maximo then 1.0 / 0.0 else v      -- overflow: ∞
       in if n < 0 then negate w else w

||| fl : ℚ → Double. Redondea al Double más cercano (empates al par).
export
fl : Racional -> Double
fl = redondear 53 (-1074) 1.7976931348623157e308

||| Redondea al número de PRECISIÓN SIMPLE más cercano (24 bits de mantisa).
||| El resultado se guarda en un Double, pero solo tiene 24 bits significativos.
export
flSimple : Racional -> Double
flSimple = redondear 24 (-149) 3.4028234663852886e38

||| De ℚ a Double para LEER un resultado (por ejemplo, un error relativo).
export
aDouble : Racional -> Double
aDouble = fl

Dos ideas sostienen el módulo:

  • Todo Double finito es una fracción \(m/2^k\). aRacional multiplica por \(2\) (una operación exacta) hasta obtener un entero y cuenta cuántas veces lo hizo.
  • fl sigue la definición de redondeo. Escala la fracción hasta que su parte entera \(q\) tenga \(53\) bits y mira el resto: si es mayor que la mitad, sube; si es exactamente la mitad, sube solo cuando \(q\) es impar (empate al par). La misma función, redondear, recibe el número de bits y el exponente mínimo: con \(53\) bits da fl (doble precisión, subnormales incluidos) y con \(24\) da flSimple (precisión simple), que usaremos en /u1/t2.

%default total le pide a Idris que compruebe que toda función termina. Por eso los ciclos llevan un contador de “combustible” (1100, 2100): un número de pasos que basta siempre y que garantiza que el ciclo acaba.

Archivo U1T1.idr:

module U1T1

import Exacto

%default total
  • fl: de lo que escribes a lo que se guarda
  • Épsilon de máquina
  • Aritmética en 𝔽: ⊕ = fl ∘ +
  • Absorción y asociatividad
  • Acumulación de errores
  • Overflow y underflow
  • Redondeo al par

Idea. Cada vez que escribes un número decimal y le dices a Idris que es un Double, la máquina lo redondea a \(\mathbb{F}\). Con Exacto podemos ver exactamente qué se guardó.

Idris2 no adivina tipos numéricos: hay que decir si 0.1 es un Double. En el REPL se hace con the Double (…). Esta exigencia no es un capricho: obliga a distinguir siempre entre \(\mathbb{Q}\) (exacto) y \(\mathbb{F}\) (redondeado).

¿Por qué ℚ y no ℝ?

En la nota conceptual, \(\text{fl}:\mathbb{R}\to\mathbb{F}\) es el modelo matemático. La máquina no puede ejecutarlo tal cual, porque para escribir un número en un programa hay que dar una descripción finita de él.

  • 1 // 10 es una descripción finita y exacta: el par de enteros \((1, 10)\).
  • \(\pi\) y \(\sqrt 2\) no tienen descripción racional. Por eso pi en Idris ya es un Double (3.141592653589793).

fl : Racional -> Double no convierte reales a flotantes. Es la parte de \(\text{fl}\) que la máquina sí puede ejecutar: redondear algo que se puede escribir exactamente. Y la escribimos nosotros, siguiendo la definición de la nota conceptual.

Predice. ¿Se guarda \(1/10\) exactamente en un Double?

Ejecuta.

U1T1> fl (1 // 10) == 0.1
True
U1T1> aRacional 0.1
MkR 3602879701896397 36028797018963968
U1T1> aRacional 0.1 - 1 // 10
MkR 1 180143985094819840
U1T1> pot2 55
36028797018963968

Lee.

  • fl (1 // 10), nuestro redondeo escrito a mano, da exactamente lo que se guarda al escribir 0.1.
  • aRacional muestra la fracción exacta que quedó guardada: \(3602879701896397/36028797018963968\). El denominador es \(2^{55}\): todo Double es un entero dividido entre una potencia de \(2\). Es la función encode de la nota conceptual.
  • La diferencia con \(1/10\) no es cero, sino \(1/180143985094819840 \approx 5.6\times10^{-18}\).

El error aparece al guardar \(0.1\), antes de hacer cualquier operación.

Tu turno. Compara aRacional (fl (1 // 3)) == 1 // 3 con aRacional (fl (1 // 4)) == 1 // 4. Uno da False y otro True. ¿Por qué? Piensa en qué denominadores tienen expansión binaria finita.

Idea. Hay dos cantidades parecidas que conviene no confundir: el espaciado entre \(1\) y el siguiente Double, y el épsilon \(\varepsilon_{mach} = 2^{-53}\) del curso, que es la mitad del espaciado.

Esta definición busca el espaciado. Empieza en e = 1.0 y lo divide entre \(2\) mientras e/2 todavía cambie a 1 + e/2. El contador 1100 es el combustible que exige %default total. Añade a U1T1.idr:

espaciado : Double
espaciado = buscar 1100 1.0
  where
    buscar : Nat -> Double -> Double
    buscar Z     e = e
    buscar (S k) e = if 1.0 + e / 2.0 == 1.0 then e else buscar k (e / 2.0)

Devuelve el último e que todavía cambia a 1 + e.

Predice. ¿Obtendrás \(2^{-52}\approx2.2\times10^{-16}\) o \(2^{-53}\approx1.1\times10^{-16}\)?

Ejecuta.

U1T1> espaciado
2.220446049250313e-16
U1T1> espaciado == pow 2.0 (-52.0)
True
U1T1> the Double (1.0 + espaciado)
1.0000000000000002
U1T1> the Double (1.0 + espaciado / 2.0)
1.0

Lee.

  • La función devuelve el espaciado, \(2^{-52}\). Nuestro \(\varepsilon_{mach} = 2^{-53}\) es la mitad.
  • 1 + espaciado/2 vuelve a dar \(1\): \(1 + 2^{-53}\) es un empate entre \(1\) y \(1 + 2^{-52}\), y se resuelve hacia \(1\) (ver la pestaña del redondeo al par).

Ahora comprobamos la cota \(|\text{fl}(x)-x| \le \varepsilon_{mach}|x|\) calculando el error relativo de forma exacta, en \(\mathbb{Q}\). Añade a U1T1.idr:

errorRelativoDeFl : Racional -> Double
errorRelativoDeFl x = aDouble (abs (aRacional (fl x) - x) / abs x)
U1T1> errorRelativoDeFl (1 // 10)
5.551115123125783e-17

El error relativo de guardar \(0.1\) es \(\approx 5.6\times10^{-17}\), menor que \(\varepsilon_{mach}\approx1.11\times10^{-16}\), como exige la cota.

Tu turno. Evalúa the Double (1.0 + 1.0e-15) y the Double (1.0 + 1.0e-16). ¿Cuál de los dos sumandos queda por debajo de medio espaciado?

Idea. La nota conceptual afirma que \(a \oplus b = \text{fl}(a+b)\): primero la suma exacta, luego un redondeo. Con Racional como “la verdad” y nuestra fl como el redondeo, esa afirmación se puede comprobar.

Añade a U1T1.idr:

a : Double
a = 0.1

b : Double
b = 0.2

Predice. Si sumas exactamente los dos números guardados y redondeas una sola vez con nuestra fl, ¿obtienes lo mismo que el hardware?

Ejecuta.

U1T1> a + b
0.30000000000000004
U1T1> a + b == 0.3
False
U1T1> fl (aRacional a + aRacional b) == a + b
True

Lee. La última línea es la definición de la nota conceptual, comprobada por la máquina: sumar en Double es exactamente sumar en \(\mathbb{Q}\) los valores guardados y redondear una vez. Y el redondeo lo hizo una función que escribimos nosotros siguiendo la definición, no el hardware. Que coincidan bit a bit no es casualidad: la comprobamos en \(20\,000\) pares de números al azar, para la suma, el producto y el cociente.

Que el resultado no coincida con 0.3 se debe a los tres redondeos: \(0.1\), \(0.2\) y la suma.

El modelo estándar

Según el modelo estándar, \(\text{fl}(a+b) = (a+b)(1+\delta)\) con \(|\delta| \le \varepsilon_{mach}\). Añade a U1T1.idr:

-- δ = (fl(a+b) − (a+b)) / (a+b), calculado en ℚ
deltaSuma : Double -> Double -> Double
deltaSuma x y =
  let exacta = aRacional x + aRacional y
  in aDouble ((aRacional (x + y) - exacta) / exacta)
U1T1> deltaSuma 0.1 0.2
9.25185853854297e-17

\(\delta \approx 9.3\times10^{-17}\), que es menor que \(\varepsilon_{mach}\approx1.11\times10^{-16}\).

Tu turno. Calcula deltaSuma 0.3 0.6. ¿Sigue cumpliéndose \(|\delta| \le \varepsilon_{mach}\)? ¿Qué significa que \(\delta\) salga negativo?

Idea. Del modelo estándar salen dos consecuencias: un sumando pequeño puede desaparecer frente a uno grande, y el orden de las sumas cambia el resultado.

Cerca de \(10^{16}\), el espaciado entre Double consecutivos ya no es \(2^{-52}\) sino \(2\), porque el espaciado crece con la magnitud.

Predice. ¿Qué devuelve \(10^{16} + 1\)? ¿Y \(10^{16} + 2\)?

Ejecuta.

U1T1> the Double (1.0e16 + 1.0)
1e16
U1T1> the Double (1.0e16 + 2.0)
1.0000000000000002e16
U1T1> the Double (1.0e16 + 100.0)
1.00000000000001e16

Lee.

  • \(10^{16}+1\) cae justo a la mitad entre dos Double vecinos, \(10^{16}\) y \(10^{16}+2\). Es un empate, y gana \(10^{16}\). El \(1\) fue absorbido.
  • \(10^{16}+2\) y \(10^{16}+100\) sí son representables, y sobreviven.

Esto es particularmente relevante en física computacional: una contribución pequeña, por ejemplo una corrección a una energía grande, puede perderse sin ningún aviso.

No asociatividad

En \(\mathbb{R}\), \((a+b)+c = a+(b+c)\). En Double:

U1T1> the Double ((1.0e16 + (-1.0e16)) + 1.0)
1.0
U1T1> the Double (1.0e16 + ((-1.0e16) + 1.0))
0.0

Matemáticamente, las dos expresiones valen \(1\). En la segunda, el \(1\) se absorbe al sumarse con \(-10^{16}\) antes de que este se cancele.

La aritmética de punto flotante no es la aritmética de \(\mathbb{R}\): el orden de las operaciones es parte del algoritmo.

Tu turno. Haz las mismas dos sumas con Racional: (aRacional 1.0e16 + aRacional (-1.0e16)) + 1 y aRacional 1.0e16 + (aRacional (-1.0e16) + 1). ¿Importa ahora el orden?

Idea. Cada operación aporta un factor \((1+\delta_i)\). Con muchas operaciones, esos errores pequeños se acumulan.

Añade a U1T1.idr:

-- suma de izquierda a derecha: (((0 ⊕ x) ⊕ x) ⊕ x) …
sumarMuchasVeces : Nat -> Double -> Double
sumarMuchasVeces n x = acumular n 0.0
  where
    acumular : Nat -> Double -> Double
    acumular Z     s = s
    acumular (S k) s = acumular k (s + x)

Predice. ¿Cuánto da sumar 0.1 diez veces?

Ejecuta.

U1T1> sumarMuchasVeces 10 0.1
0.9999999999999999
U1T1> sumarMuchasVeces 100 0.1
9.99999999999998
U1T1> sumarMuchasVeces 1000000 0.1
100000.00000133288

(La última tarda unos segundos en el REPL.)

Lee. Ni siquiera diez sumas dan \(1\). Con un millón de sumas, la diferencia aparece ya en el sexto decimal.

¿Cuánto error, comparado con lo esperado?

Comparamos con la suma exacta del valor guardado, \(n\cdot\text{fl}(0.1)\), calculada en \(\mathbb{Q}\). Así solo queda el error que añaden las sumas, no el de guardar 0.1. La comparamos con la cota pesimista \(n\,\varepsilon_{mach}\,|S|\), que supone que todos los redondeos empujan en la misma dirección. Añade a U1T1.idr:

-- (error real, cota pesimista)
errorDeSuma : Nat -> Double -> (Double, Double)
errorDeSuma n x =
  let calculada = sumarMuchasVeces n x
      exacta    = fromInteger (natToInteger n) * aRacional x
      errorReal = abs (aRacional calculada - exacta)
      cota      = fromInteger (natToInteger n) * (1 // pot2 53) * exacta
  in (aDouble errorReal, aDouble cota)
U1T1> errorDeSuma 1000000 0.1
(1.3328771242271387e-6, 1.1102230246251565e-5)

Lee. El error real (\(1.3\times10^{-6}\)) es menor que la cota (\(1.1\times10^{-5}\)). La cota es de peor caso: supone que el millón de redondeos va en la misma dirección, y eso casi nunca ocurre del todo. Pero tampoco se cancelan por completo: el resultado quedó por encima de \(100000\).

Tu turno. Con diez veces más sumas, el REPL tardaría demasiado. Usa :exec printLn (errorDeSuma 10000000 0.1), que compila la expresión antes de ejecutarla. Antes de hacerlo, predice: si los errores se cancelaran al azar, el error crecería como \(\sqrt{n}\), unas \(3\) veces; si se acumularan sin cancelarse, crecería como \(n\), unas \(10\) veces.

Idea. \(\mathbb{F}\) tiene un elemento máximo y uno positivo mínimo. Más allá del máximo, el resultado es \(\infty\). Por debajo del mínimo normal hay una zona de números subnormales donde la cota del épsilon deja de valer.

Predice. ¿Qué devuelve \(10^{308}\times10\)? ¿Y \(10^{-308}/10^{100}\)?

Ejecuta.

U1T1> the Double (1.0e308 * 10.0)
+inf.0
U1T1> the Double (1.0e-308 / 1.0e100)
0.0
U1T1> the Double (0.0 / 0.0)
+nan.0

Lee.

  • El producto excede el máximo (≈ \(1.8\times10^{308}\)) y da +inf.0: es un desbordamiento.
  • El cociente cae por debajo incluso del subnormal más pequeño y da 0.0: es un subdesbordamiento total.
  • \(0/0\) no tiene valor definido: IEEE 754 devuelve +nan.0 (not a number).

Los subnormales, a la vista

Entre \(0\) y el mínimo normal (\(\approx 2.2\times10^{-308}\)) están los subnormales, con espaciado fijo \(2^{-1074}\). El REPL de Idris (que usa Chez Scheme por dentro) los imprime con una marca muy útil:

U1T1> the Double (2.2250738585072014e-308 / 2.0)
1.1125369292536007e-308|52
U1T1> the Double 5.0e-324
5e-324|1
U1T1> the Double (5.0e-324 / 2.0)
0.0

El número después de | es la cantidad de bits significativos que le quedan a la mantisa. Un Double normal tiene \(53\).

  • La mitad del mínimo normal ya es subnormal: le quedan \(52\) bits.
  • \(5\times10^{-324} = 2^{-1074}\), el Double positivo más pequeño, tiene un solo bit de mantisa.
  • Su mitad es un empate entre \(0\) y \(2^{-1074}\), y el redondeo al par elige \(0\).

Con menos bits, el error relativo crece. Para medirlo comparamos el Double que se guarda al escribir \(10^{-320}\) con el valor exacto \(1/10^{320}\). Añade a U1T1.idr:

pow10 : Nat -> Integer
pow10 Z     = 1
pow10 (S k) = 10 * pow10 k
U1T1> the Double 1.0e-320
1e-320|11
U1T1> aDouble (abs (aRacional 1.0e-320 - 1 // pow10 320) / (1 // pow10 320))
1.1132817316994587e-5

Con solo \(11\) bits de mantisa, guardar \(10^{-320}\) cuesta un error relativo de \(\approx 1.1\times10^{-5}\), unas \(10^{11}\) veces mayor que \(\varepsilon_{mach}\). El underflow gradual evita saltar a cero, pero a costa de perder precisión relativa.

Tu turno. ¿Cuántos bits de mantisa le quedan a the Double 1.0e-310? Mide su error relativo de la misma manera, con pow10 310. Compara con the Double 1.0e-300.

Idea. Cuando un valor cae exactamente a la mitad entre dos elementos de \(\mathbb{F}\), IEEE 754 elige el vecino cuya mantisa termina en \(0\).

Como analogía decimal: con la regla “empate al par”, \(0.5 \to 0\), \(1.5 \to 2\), \(2.5 \to 2\) y \(3.5 \to 4\). La mitad de los empates sube y la otra mitad baja.

Predice. Los vecinos de \(1\) son \(1+2^{-52}\) y \(1+2\cdot2^{-52}\). ¿A dónde van \(1+2^{-53}\) y \(1+3\cdot2^{-53}\), que son empates?

Ejecuta.

U1T1> the Double (1.0 + pow 2.0 (-53.0)) == 1.0
True
U1T1> the Double (1.0 + 3.0 * pow 2.0 (-53.0))
1.0000000000000004

Lee. Es exactamente el ejemplo de la nota conceptual:

  • \(1 + 2^{-53}\) se redondea hacia abajo, a \(1\).
  • \(1 + 3\cdot2^{-53}\) se redondea hacia arriba, a \(1+2\cdot2^{-52} = 1.0000000000000004\).

En ambos casos gana el vecino de mantisa par. Nuestra fl hace lo mismo, porque la escribimos con esa regla:

U1T1> fl (aRacional 1.0e16 + 1)
1e16
U1T1> fl (aRacional 1.0e16 + 3)
1.0000000000000004e16

\(10^{16} + 3\) es un empate entre \(10^{16}+2\) y \(10^{16}+4\), y gana \(10^{16}+4\), de mantisa par.

Lo que el redondeo al par no hace

El redondeo al par elimina el sesgo en los empates. No garantiza que los errores se cancelen en general: la mayoría de los resultados no son empates.

Si hiciste el “Tu turno” de la pestaña de acumulación, ya lo viste. Al pasar de \(10^6\) a \(10^7\) sumas de 0.1, el error crece de \(1.3\times10^{-6}\) a \(1.6\times10^{-4}\), más de cien veces. No crece como \(\sqrt{n}\), como pasaría si los errores se cancelaran al azar: los redondeos tienden a ir en la misma dirección. En /u1/t5 verás la suma de Kahan, un algoritmo que recupera casi todo ese error.

Tu turno. Busca otro empate cerca de \(2\): los vecinos de \(2\) están separados por \(2^{-51}\). Predice a dónde va the Double (2.0 + pow 2.0 (-52.0)) y compruébalo.
