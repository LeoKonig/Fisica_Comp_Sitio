Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con Idris2 0.7.0.

Las definiciones (bloques sin prompt) van en un archivo U3T2.idr. Las consultas (con el prompt U3T2>) se escriben en el REPL, sin el prompt. Abre el REPL con idris2 U3T2.idr y usa :r para recargar el archivo cuando añadas algo. Necesitas el archivo Exacto.idr de la implementación de /u1/t1 en la misma carpeta.

El estado de esta nota. Todos los ejemplos son ecuaciones escalares \(\dot y = f(t, y)\), así que el estado de un método de un paso es el par \((t, y)\). Un campo es una función de dos argumentos.

Idea. Un paso de Euler implícito es la raíz de \(G(Y) = Y - y_n - h\,f(t_{n+1}, Y)\). Lo construimos componiendo dos piezas que ya conocemos: la predicción de Euler explícito, como punto de partida, y el método de Newton de /u2/t6, como resolvedor.

Añade a U3T2.idr:

-- Newton, como sucesión infinita de aproximaciones (ver /u2/t6)
newtonIter : (Double -> Double) -> (Double -> Double) -> Double -> Stream Double
newtonIter g dg x0 = iterate (\x => x - g x / dg x) x0

-- consume la sucesión: primer valor que ya no cambia (o el 50º, si no converge)
resolver : (Double -> Double) -> (Double -> Double) -> Double -> Double
resolver g dg x0 = buscar (take 50 (newtonIter g dg x0))
  where
    buscar : List Double -> Double
    buscar (a :: resto@(b :: _)) = if abs (b - a) <= 1.0e-14 * abs b then b else buscar resto
    buscar [a] = a
    buscar []  = x0

eulerExplicito : Double -> CampoT -> (Double, Double) -> (Double, Double)
eulerExplicito h f (t, y) = (t + h, y + h * f t y)

-- Euler implícito: dfdy es ∂f/∂y, necesaria para Newton
eulerImplicito : Double -> CampoT -> CampoT -> (Double, Double) -> (Double, Double)
eulerImplicito h f dfdy (t, y) = (t1, resolver g dg prediccion)
  where
    t1 : Double
    t1 = t + h
    prediccion : Double
    prediccion = y + h * f t y          -- Euler explícito como predictor
    g : Double -> Double
    g yy = yy - y - h * f t1 yy         -- G(Y)
    dg : Double -> Double
    dg yy = 1 - h * dfdy t1 yy          -- G'(Y)

eulerImplicito no despeja nada: le pasa la ecuación \(G(Y) = 0\) a resolver, que a su vez consume la sucesión de Newton. Es la composición de la nota conceptual. En buscar, el patrón resto@(b :: _) le da el nombre resto a la cola de la lista sin dejar de mirar su primer elemento; como buscar se llama a sí misma con una lista más corta, Idris acepta que termina.

El caso lineal

Predice. Para \(\dot y = -50y\) con \(h = 0.1\), Euler explícito multiplica por \(1 - 5\) en cada paso, e implícito por \(\frac16\). ¿Qué le pasa a cada uno en 4 pasos?

Ejecuta. Cada tripleta es \(\big((1-5)^n,\ (\tfrac16)^n,\ e^{-5n}\big)\).

U3T2> [ (pow (-4) n, pow (1 / 6) n, exp (-5 * n)) | n <- [1, 2, 3, 4] ]
[(-4.0, (0.16666666666666666, 0.006737946999085467)), (16.0, (0.027777777777777776, 4.5399929762484854e-5)), (-64.0, (0.0046296296296296285, 3.059023205018258e-7)), (256.0, (7.716049382716048e-4, 2.061153622438558e-9))]

Lee. Es la tabla de la nota conceptual: el explícito oscila y explota (\(-4, 16, -64, 256\)), el implícito decae (\(0.17, 0.028, \ldots\)), como la solución exacta, aunque sin mucha precisión con este \(h\).

El caso no lineal, con Newton

Añade a U3T2.idr:

-- y' = −y³ y su derivada respecto a y
cubico : CampoT
cubico _ y = - (y * y * y)

dcubico : CampoT
dcubico _ y = -3 * y * y

-- la ecuación del primer paso con h = 0.5: G(Y) = Y + 0.5 Y³ − 1
gCubica : Double -> Double
gCubica yy = yy + 0.5 * yy * yy * yy - 1

dgCubica : Double -> Double
dgCubica yy = 1 + 1.5 * yy * yy

Predice. Para \(\dot y = -y^3\), \(y_0 = 1\), \(h = 0.5\), la ecuación del paso es \(G(Y) = Y + 0.5\,Y^3 - 1 = 0\). Desde el predictor \(0.5\), ¿cuántas iteraciones de Newton hacen falta? ¿Y con la iteración de punto fijo \(Y \leftarrow 1 - 0.5\,Y^3\)?

Ejecuta.

[-0.4375, 0.0920360631104431, 0.00253981468225728, 2.0805734513018592e-6]
U3T2> eulerImplicito 0.5 cubico dcubico (0, 1)
(0.5, 0.7709169970592481)
U3T2> take 8 (iterate (\yy => 1 - 0.5 * yy * yy * yy) 0.5)

  • Son las columnas de la tabla de Newton de la nota conceptual: el residuo pasa de \(10^{-1}\) a \(10^{-3}\) a \(10^{-6}\), el doble de dígitos en cada iteración.
  • eulerImplicito hace todo el proceso y entrega \(y_1 = 0.770917\).
  • El punto fijo oscila alrededor de la solución y se acerca muy despacio: \(|g'| \approx 0.89\), casi \(1\).

Euler implícito en el oscilador: la geometría

En el oscilador, \(\dot q = p\), \(\dot p = -q\), cada paso implícito es un sistema lineal \(2\times2\), que se despeja a mano. Escribimos los tres pasos para cualquier tipo numérico, así que funcionan también con Racional. Añade a U3T2.idr:

-- Euler explícito e implícito en el oscilador; el implícito resuelve q' = q + h p', p' = p − h q'
eulerExplicitoOsc : (Fractional t, Neg t) => t -> (t, t) -> (t, t)
eulerExplicitoOsc h (q, p) = (q + h * p, p - h * q)

eulerImplicitoOsc : (Fractional t, Neg t) => t -> (t, t) -> (t, t)
eulerImplicitoOsc h (q, p) = ((q + h * p) / (1 + h * h), (p - h * q) / (1 + h * h))

-- punto medio implícito: y' = y + h f((y + y')/2), despejado con a = h/2
puntoMedioOsc : (Fractional t, Neg t) => t -> (t, t) -> (t, t)
puntoMedioOsc h (q, p) =
  let a = h / 2
  in (((1 - a * a) * q + 2 * a * p) / (1 + a * a), ((1 - a * a) * p - 2 * a * q) / (1 + a * a))

-- determinante de un mapa lineal del plano (ver /u3/t1) y energía del oscilador
determinante : Neg t => ((t, t) -> (t, t)) -> t
determinante paso =
  let (a, c) = paso (1, 0)
      (b, d) = paso (0, 1)
  in a * d - b * c

energiaOsc : (Double, Double) -> Double
energiaOsc (q, p) = (q * q + p * p) / 2

Predice. Euler explícito multiplica las áreas por \(1 + h^2\). La nota conceptual dice que Euler implícito las multiplica por \(\frac{1}{1+h^2}\) y que el punto medio, que es medio paso implícito seguido de medio paso explícito, las conserva. Con \(h = \frac1{10}\) exacto, ¿qué fracciones saldrán? ¿Qué energía queda tras 1000 pasos de cada uno con \(h = 0.1\)?

Ejecuta.

U3T2> map determinante [eulerExplicitoOsc (1 // 10), eulerImplicitoOsc (1 // 10), puntoMedioOsc (1 // 10)]
[MkR 101 100, MkR 100 101, MkR 1 1]
U3T2> [ energiaOsc (final 1000 paso (1, 0)) | paso <- [eulerExplicitoOsc 0.1, eulerImplicitoOsc 0.1, puntoMedioOsc 0.1] ]
[10479.577818906859, 2.3855922854922222e-5, 0.500000000000106]
U3T2> (puntoMedioOsc (1 // 10) (1, 0), eulerExplicitoOsc (1 // 20) (eulerImplicitoOsc (1 // 20) (1, 0)))
((MkR 399 401, MkR -40 401), (MkR 399 401, MkR -40 401))

Lee.

  • Los determinantes son exactamente \(\frac{101}{100}\), \(\frac{100}{101}\) y \(1\): el explícito infla las áreas, el implícito las encoge por el mismo factor, y el punto medio las conserva.
  • Tras 1000 pasos, la energía explota a \(10\,480\) con el explícito, se apaga a \(2.4\times10^{-5}\) con el implícito, y se queda en \(0.5\) con el punto medio. Ninguno de los dos Euler está en el grupo de los mapas simplécticos de /u3/t1; el punto medio, sí.
  • La última consulta comprueba la composición, en \(\mathbb{Q}\): medio paso de Euler implícito seguido de medio paso de Euler explícito da exactamente el punto medio implícito. Sus errores opuestos se cancelan, como en Verlet.

Idea. El predictor-corrector AB2/trapecio predice con Adams-Bashforth, evalúa \(f\) en la predicción y corrige con la regla del trapecio. Su estado guarda los dos últimos puntos, porque AB2 necesita \(f_n\) y \(f_{n-1}\).

Añade a U3T2.idr:

-- un paso de predictor-corrector; el estado es la ventana (t₀, y₀, t₁, y₁)
ab2pc : Double -> CampoT -> (Double, Double, Double, Double) -> (Double, Double, Double, Double)
ab2pc h f (t0, y0, t1, y1) =
  let f0 = f t0 y0
      f1 = f t1 y1
      t2 = t1 + h
      yp = y1 + h * (3 / 2 * f1 - 1 / 2 * f0)     -- predecir (AB2)
      y2 = y1 + h / 2 * (f1 + f t2 yp)            -- evaluar y corregir (trapecio)
  in (t1, y1, t2, y2)

decaimiento : CampoT
decaimiento _ y = - y

-- error en t = 1 con n pasos, arrancando con el valor exacto y₁ = e^(−h)
errorPC : Nat -> Double
errorPC n =
  let h = 1 / cast n
      (_, _, _, y) = final (minus n 1) (ab2pc h decaimiento) (0, 1, h, exp (- h))
  in abs (y - exp (-1))

La salida de ab2pc tiene la misma forma que la entrada: el punto más viejo sale, el nuevo entra. Esa es la ventana deslizante de la nota conceptual. (minus n 1 es la resta de naturales, \(n - 1\): la ventana inicial ya trae el primer paso.)

Predice. La nota conceptual hace un paso a mano para \(\dot y = -y\) con \(h = 0.1\) y obtiene \(y_2 = 0.818640\). ¿Qué orden tendrá el método?

Ejecuta.

U3T2> ab2pc 0.1 decaimiento (0, 1, 0.1, exp (-0.1))
(0.1, (0.9048374180359595, (0.2, 0.8186399568676332)))
U3T2> exp (-0.2)
0.8187307530779818
U3T2> map errorPC [10, 20, 40]
[3.6801196285257687e-4, 8.432068039387897e-5, 2.0119529428208605e-5]
U3T2> orden errorPC 20
2.067289945682643

Lee.

  • Idris escribe la 4-tupla como pares anidados, (t₁, (y₁, (t₂, y₂))). El último número, \(y_2 = 0.818640\), es el valor de la nota conceptual: error \(9.1\times10^{-5}\), sin resolver ninguna ecuación.
  • El orden medido es \(2\): el de la regla del trapecio, aunque se haya usado la predicción en lugar del valor exacto de \(f_{n+1}\).
  • Cada paso evalúa \(f\) dos veces: f t1 y1 y f t2 yp. (f t0 y0 se recalcula aquí por simplicidad; una implementación cuidadosa la guardaría en la ventana.)

Idea. AB4 necesita una ventana de 4 puntos. La representamos con una 4-tupla, de modo que el tipo dice el tamaño. El problema del arranque es construir la primera ventana a partir de \(y_0\), con un método de un paso que se pasa como argumento.

Recuerda: el orden global resultante es \(\min(p,\ q+1)\), donde \(q\) es el orden del arrancador.

Añade a U3T2.idr:

-- la ventana de AB4: exactamente 4 puntos (t, y)
Ventana : Type
Ventana = ((Double, Double), (Double, Double), (Double, Double), (Double, Double))

ab4 : Double -> CampoT -> Ventana -> Ventana
ab4 h f ((t0, y0), (t1, y1), (t2, y2), (t3, y3)) =
  let y4 = y3 + h / 24 * (55 * f t3 y3 - 59 * f t2 y2 + 37 * f t1 y1 - 9 * f t0 y0)
  in ((t1, y1), (t2, y2), (t3, y3), (t3 + h, y4))

-- el arranque: tres pasos de un método de un paso llenan la ventana
arrancar : ((Double, Double) -> (Double, Double)) -> (Double, Double) -> Ventana
arrancar paso p0 =
  let p1 = paso p0
      p2 = paso p1
  in (p0, p1, p2, paso p2)

rk4T : Double -> CampoT -> (Double, Double) -> (Double, Double)
rk4T h f (t, y) =
  let k1 = f t y
      k2 = f (t + h / 2) (y + h / 2 * k1)
      k3 = f (t + h / 2) (y + h / 2 * k2)
      k4 = f (t + h) (y + h * k3)
  in (t + h, y + h / 6 * (k1 + 2 * k2 + 2 * k3 + k4))

heunT : Double -> CampoT -> (Double, Double) -> (Double, Double)
heunT h f (t, y) =
  let k1 = f t y
      k2 = f (t + h) (y + h * k1)
  in (t + h, y + h / 2 * (k1 + k2))

-- y' = −y + sin t, y(0) = 1, y su solución exacta
forzado : CampoT
forzado t y = - y + sin t

exactaForzado : Double -> Double
exactaForzado t = (sin t - cos t) / 2 + 1.5 * exp (- t)

-- error de AB4 en t = 2 con n pasos, usando el arrancador dado
errorAB4 : (Double -> CampoT -> (Double, Double) -> (Double, Double)) -> Nat -> Double
errorAB4 arrancador n =
  let h = 2 / cast n
      (_, _, _, (_, y)) = final (minus n 3) (ab4 h forzado) (arrancar (arrancador h forzado) (0, 1))
  in abs (y - exactaForzado 2)

arrancar es la estrategia 1 de la nota conceptual en una línea de tipos: recibe un mapa de un paso y un punto, y devuelve una Ventana. Es imposible empezar a iterar ab4 sin pasar por ella, porque ab4 no acepta otra cosa. Las 3 llamadas de arrancar más los \(n-3\) pasos de AB4 dan \(n\) pasos en total. El arrancador se pasa sin aplicar (rk4T, heunT, eulerExplicito), y errorAB4 le da el paso y el campo.

Predice. Con arranques de RK4 (\(q = 4\)), Heun (\(q = 2\)) y Euler (\(q = 1\)), ¿qué orden global medirás para AB4?

  • Son las columnas de la tabla de la nota conceptual, en orden: RK4, Heun, Euler, cada una para \(n = 40, 80, 160\).
  • Los órdenes son \(4\), \(3\) y \(2\): \(\min(4,\ q+1)\). Con arranque de Euler, AB4 se comporta como un método de orden 2 durante toda la integración, aunque solo 3 de los pasos usaron Euler.

Idea. BDF2 es implícito y multipaso a la vez: su estado es una ventana de 2 puntos, y cada paso resuelve una ecuación con Newton. Lo comparamos con Euler explícito en el problema rígido de la nota conceptual.

Añade a U3T2.idr:

-- y' = −1000 (y − cos t) − sin t, con solución exacta y = cos t
rigido : CampoT
rigido t y = -1000 * (y - cos t) - sin t

drigido : CampoT
drigido _ _ = -1000

-- BDF2: y₂ = 4/3 y₁ − 1/3 y₀ + 2/3 h f(t₂, y₂), resuelto con Newton
bdf2 : Double -> CampoT -> CampoT -> ((Double, Double), (Double, Double)) -> ((Double, Double), (Double, Double))
bdf2 h f dfdy ((t0, y0), (t1, y1)) = ((t1, y1), (t2, resolver g dg prediccion))
  where
    t2 : Double
    t2 = t1 + h
    prediccion : Double
    prediccion = y1 + h * f t1 y1
    g : Double -> Double
    g yy = yy - 4 / 3 * y1 + 1 / 3 * y0 - 2 / 3 * h * f t2 yy
    dg : Double -> Double
    dg yy = 1 - 2 / 3 * h * dfdy t2 yy

-- la primera ventana de BDF2: y₀ y un paso de BDF1 (Euler implícito)
ventanaInicial : Double -> ((Double, Double), (Double, Double))
ventanaInicial h = ((0, 1), eulerImplicito h rigido drigido (0, 1))

[1.3280686162497558e90, 5.2979468932524305e13, 5.140598764441506e-7]

Lee.

  • Euler explícito: \(10^{90}\), \(5\times10^{13}\) y \(5\times10^{-7}\). El umbral entre explotar y funcionar está entre \(0.0021\) y \(0.0019\), en \(2/1000\).
  • BDF1 y BDF2, con solo 10 pasos de \(h = 0.1\), dan errores de \(2.8\times10^{-5}\) y \(2.7\times10^{-6}\), los de la nota conceptual.
  • La ventana inicial de BDF2 se llenó con un paso de BDF1: la estrategia 2 del arranque (la propia familia, a orden creciente). Por eso BDF2 da 9 pasos y no 10.

Idea. Los coeficientes de cualquier BDF salen de las diferencias hacia atrás, y se pueden calcular exactamente con el Racional de Exacto.idr. Con ellos medimos el factor de amplificación de BDF1 a BDF6 sobre la ecuación de prueba \(\dot y = \lambda y\), con números complejos.

Recuerda: un método es estable para \(z = h\lambda\) si su factor de amplificación es \(\le 1\).

BDF\(k\) es \(\sum_{j=1}^{k} \frac1j \nabla^j y_{n+1} = h\,f_{n+1}\), donde \(\nabla y_{n+1} = y_{n+1} - y_n\) es la diferencia hacia atrás. Desarrollando con el binomio, el coeficiente de \(y_{n+1-i}\) es \(c_i = \sum_j \frac1j(-1)^i\binom{j}{i}\). Aplicado a \(\dot y = \lambda y\), el método se vuelve la recurrencia

\[(c_0 - z)\,y_{n+1} = -\sum_{i\ge1} c_i\, y_{n+1-i}.\]

Los números complejos. Como \(z = h\lambda\) puede ser complejo, necesitamos el tipo de los números \(a + bi\), con \(i^2 = -1\). Basta con guardar el par \((a, b)\) y enseñarle a Idris las operaciones:

  • suma por componentes;
  • producto \((a + bi)(c + di) = (ac - bd) + (ad + bc)\,i\), que sale de desarrollar y usar \(i^2 = -1\);
  • división multiplicando arriba y abajo por el conjugado \(c - di\), para que el denominador sea el real \(c^2 + d^2\);
  • módulo \(|a + bi| = \sqrt{a^2 + b^2}\), la distancia al origen en el plano complejo.

Añade a U3T2.idr:

-- el número complejo a + b i
record Complejo where
  constructor MkC
  re : Double
  im : Double

Num Complejo where
  MkC a b + MkC c d = MkC (a + c) (b + d)
  MkC a b * MkC c d = MkC (a * c - b * d) (a * d + b * c)
  fromInteger n = MkC (fromInteger n) 0

Neg Complejo where
  negate (MkC a b) = MkC (negate a) (negate b)
  MkC a b - MkC c d = MkC (a - c) (b - d)

Fractional Complejo where
  MkC a b / MkC c d = let m = c * c + d * d in MkC ((a * c + b * d) / m) ((b * c - a * d) / m)

-- |a + b i|, escalando para no elevar al cuadrado números diminutos
modulo : Complejo -> Double
modulo (MkC a b) =
  let m = max (abs a) (abs b)
  in if m == 0 then 0 else m * sqrt ((a / m) * (a / m) + (b / m) * (b / m))

real : Double -> Complejo
real x = MkC x 0

Con estas tres implementaciones, +, *, - y / funcionan con Complejo como con cualquier número, y MkC 0 1 es \(i\). El módulo se calcula escalado: tras 400 pasos los valores rondan \(10^{-160}\), y su cuadrado, \(10^{-320}\), caería en la zona subnormal de /u1/t1 y perdería cifras. Dividir primero entre el mayor de \(|a|\) y \(|b|\) lo evita.

Añade a U3T2.idr:

-- coeficiente binomial, con el triángulo de Pascal
binom : Nat -> Nat -> Integer
binom _     Z     = 1
binom Z     (S r) = 0
binom (S n) (S r) = binom n r + binom n (S r)

-- (−1)ⁱ
signo : Nat -> Integer
signo Z     = 1
signo (S i) = - signo i

-- coeficientes c₀ … c_k de BDFk, exactos
coeficientesBDF : Nat -> List Racional
coeficientesBDF k =
  [ sum [ (1 // natToInteger j) * fromInteger (signo i * binom j i) | j <- [1 .. k], i <= j ] | i <- [0 .. k] ]

primero : List Complejo -> Complejo
primero []       = 0
primero (x :: _) = x

-- factor de amplificación de BDFk en z: tras muchos pasos, |y_{n+1}| / |y_n|
factorBDF : Nat -> Complejo -> Double
factorBDF k z =
  let c = map (real . aDouble) (coeficientesBDF k)
      v = final 400 (paso c) (replicate k 1)
  in modulo (primero (paso c v)) / modulo (primero v)
  where
    -- la ventana es [y_n, y_{n−1}, …]; entra el nuevo, sale el más viejo
    paso : List Complejo -> List Complejo -> List Complejo
    paso []         ventana = ventana
    paso (c0 :: cs) ventana =
      let nuevo = negate (sum (zipWith (*) cs ventana)) / (c0 - z)
      in nuevo :: take (minus (length ventana) 1) ventana

binom usa la regla de Pascal, \(\binom{n+1}{r+1} = \binom{n}{r} + \binom{n}{r+1}\), que Idris acepta como total porque n baja en cada llamada. Tras 400 pasos, el modo dominante (el de mayor factor) ha dejado atrás a todos los demás, y el cociente de dos valores consecutivos es su factor.

Predice. En \(z = i\), una oscilación pura, el factor exacto es \(1\). La nota conceptual dice que BDF1 y BDF2 amortiguan y que BDF3 a BDF6 amplifican. ¿Lo confirmarás?

Lee.

  • BDF1 es \(y_{n+1} - y_n = h f_{n+1}\) (Euler implícito), y BDF2, \(\frac32 y_{n+1} - 2y_n + \frac12 y_{n-1} = h f_{n+1}\) (MkR 3 2 es \(\frac32\)). Dividiendo entre \(\frac32\), es la fórmula \(y_{n+1} = \frac43 y_n - \frac13 y_{n-1} + \frac23 h f_{n+1}\) de la nota conceptual.
  • En \(z = i\): \(0.707\), \(0.933\), y luego \(1.044\), \(1.106\), \(1.135\), \(1.155\). BDF3 a BDF6 hacen crecer una oscilación que debería conservarse.
  • En \(z = -0.5 + 2i\), a \(76°\) del eje real negativo: BDF3 (\(\alpha \approx 86°\)) da \(0.848\), estable; BDF4 (\(\alpha \approx 73°\)) da \(1.024\), inestable. Son los valores de la nota conceptual.
  • La regla del trapecio da exactamente \(1\) sobre el eje imaginario.
