Integración Numérica: Trapecio, Simpson, Cuadratura Gaussiana · Implementación (Idris2)

Nota Implementacional
🜂 Implementación en: Idris2
← Nota conceptual · Práctica →

Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con Idris2 0.7.0.

Las definiciones (bloques sin prompt) van en un archivo U2T4.idr. Las consultas (con el prompt U2T4>) se escriben en el REPL, sin el prompt. Abre el REPL con idris2 U2T4.idr y usa :r para recargar el archivo cuando añadas algo. Necesitas el archivo Exacto.idr de la implementación de /u1/t1 en la misma carpeta.

Una sola función para toda la nota. La nota conceptual dice que un método de cuadratura queda determinado por sus nodos y sus pesos, y que cambiar de método es cambiar esas listas, no el procedimiento. En Idris lo hacemos literal: una regla es una lista de pares (nodo, peso), y una sola función la aplica a cualquier \(f\).

Archivo U2T4.idr:

module U2T4

import Exacto
import Data.List
import Data.Stream

%default total

-- una regla de cuadratura: pares (nodo xᵢ, peso wᵢ)
Regla : Type -> Type
Regla a = List (a, a)

-- Q[f] = Σ wᵢ f(xᵢ)
integrarCon : Num a => Regla a -> (a -> a) -> a
integrarCon regla f = sum [ w * f x | (x, w) <- regla ]

Regla es una función que recibe un tipo y devuelve otro: Regla Double es una lista de pares de Double, y Regla Racional, de pares exactos. integrarCon regla (con un solo argumento) es una función de orden superior: recibe \(f\) y devuelve un número. Todas las reglas de esta nota, incluso Monte Carlo, pasan por ella.

  • Trapecio y Simpson
  • Cuadratura gaussiana
  • Monte Carlo

Idea. El trapecio y Simpson usan los mismos nodos equiespaciados y distintos pesos. Construimos las dos reglas como listas y comprobamos los órdenes \(2\) y \(4\).

Añade a U2T4.idr:

-- n + 1 nodos equiespaciados en [a, b]
nodos : (Fractional t, Neg t) => t -> t -> Nat -> List t
nodos a b n = [ a + fromInteger (natToInteger i) * (b - a) / fromInteger (natToInteger n) | i <- [0 .. n] ]

-- pesos h · (½, 1, 1, …, 1, ½)
reglaTrapecio : (Fractional t, Neg t) => t -> t -> Nat -> Regla t
reglaTrapecio a b n = zip (nodos a b n) [ h * c | c <- coeficientes ]
  where
    h : t
    h = (b - a) / fromInteger (natToInteger n)
    coeficientes : List t
    coeficientes = [1 / 2] ++ replicate (minus n 1) 1 ++ [1 / 2]

-- Simpson con m PARES de subintervalos (n = 2m): pesos (h/3) · (1, 4, 2, 4, …, 2, 4, 1)
reglaSimpson : (Fractional t, Neg t) => t -> t -> (m : Nat) -> Regla t
reglaSimpson a b m = zip (nodos a b (2 * m)) [ h / 3 * c | c <- coeficientes m ]
  where
    h : t
    h = (b - a) / fromInteger (natToInteger (2 * m))
    coeficientes : Nat -> List t
    coeficientes Z     = [1]
    coeficientes (S k) = [1] ++ concat (replicate k [4, 2]) ++ [4, 1]

trapecio : (Fractional t, Neg t) => (t -> t) -> t -> t -> Nat -> t
trapecio f a b n = integrarCon (reglaTrapecio a b n) f

simpson : (Fractional t, Neg t) => (t -> t) -> t -> t -> (m : Nat) -> t
simpson f a b m = integrarCon (reglaSimpson a b m) f

Usamos t como nombre del tipo porque a y b ya son los extremos del intervalo. Simpson necesita un número par de subintervalos. En vez de comprobarlo al ejecutar y tener que decidir qué hacer con un \(n\) impar, pedimos el número de pares, \(m\): con \(n = 2m\), el caso imposible ni siquiera se puede escribir. En esta nota, simpson f a b 2 es Simpson con \(n = 4\).

Las dos reglas, lado a lado

Predice. Para \([0, 1]\) con \(n = 4\), ¿qué nodos y qué pesos tendrá cada regla? ¿Cuánto suman los pesos?

Ejecuta.

U2T4> reglaTrapecio (the Racional 0) 1 4
[(MkR 0 1, MkR 1 8), (MkR 1 4, MkR 1 4), (MkR 1 2, MkR 1 4), (MkR 3 4, MkR 1 4), (MkR 1 1, MkR 1 8)]
U2T4> reglaSimpson (the Racional 0) 1 2
[(MkR 0 1, MkR 1 12), (MkR 1 4, MkR 1 3), (MkR 1 2, MkR 1 6), (MkR 3 4, MkR 1 3), (MkR 1 1, MkR 1 12)]
U2T4> sum (map snd (reglaSimpson (the Racional 0) 1 2))
MkR 1 1

Lee.

  • En Racional, los nodos y los pesos son fracciones exactas. Los nodos son idénticos: \(0, \frac14, \frac12, \frac34, 1\). Solo cambian los pesos: \(\frac18, \frac14, \frac14, \frac14, \frac18\) para el trapecio y \(\frac1{12}, \frac13, \frac16, \frac13, \frac1{12}\) para Simpson.
  • Los pesos suman exactamente \(1 = b - a\): las dos reglas integran exactamente la función constante \(1\).

Los órdenes, medidos

Predice. La nota conceptual da \(Q^T_4 = 1.896119\) y \(Q^S_4 = 2.004560\) para \(\int_0^\pi \sin x\,dx = 2\). Al duplicar \(n\), ¿entre cuánto se divide cada error?

Ejecuta.

U2T4> trapecio sin 0 pi 4
1.8961188979370398
U2T4> simpson sin 0 pi 2
2.0045597549844207
U2T4> [ (n, abs (trapecio sin 0 pi n - 2), abs (simpson sin 0 pi (n `div` 2) - 2)) | n <- [4, 8, 16] ]
[(4, (0.1038811020629602, 0.0045597549844207386)), (8, (0.025768398054449193, 2.6916994838721564e-4)), (16, (0.006429656227660896, 1.6591047935499148e-5))]
U2T4> [ abs (trapecio sin 0 pi n - 2) / abs (trapecio sin 0 pi (2 * n) - 2) | n <- [4, 8] ]
[4.031337215586981, 4.007741182738742]
U2T4> [ abs (simpson sin 0 pi m - 2) / abs (simpson sin 0 pi (2 * m) - 2) | m <- [2, 4] ]
[16.940059660231025, 16.2238063221603]

Lee.

  • Son los valores de la tabla de la nota conceptual.
  • Los cocientes se acercan a \(4 = 2^2\) para el trapecio y a \(16 = 2^4\) para Simpson: órdenes \(2\) y \(4\). En /u2/t5 convertiremos estos cocientes en una medida sistemática del orden.

Simpson es exacto para cúbicas

Predice. Con un solo par de subintervalos en \([0, 1]\), ¿qué dará Simpson para \(\int_0^1 x^3\,dx = \frac14\) y para \(\int_0^1 x^4\,dx = \frac15\)?

Ejecuta.

U2T4> simpson (\x => x * x * x) (the Racional 0) 1 1
MkR 1 4
U2T4> simpson (\x => x * x * x * x) (the Racional 0) 1 1
MkR 5 24

Lee. En \(\mathbb{Q}\), el resultado para \(x^3\) es exactamente \(\frac14\), aunque Simpson se construye con parábolas: el grado extra viene de la simetría de la regla. Con \(x^4\) ya falla: \(\frac5{24} = 0.2083\) en lugar de \(\frac15\), como en la nota conceptual. Aquí no hay ningún redondeo: es el error del método, puro.

Tu turno. Calcula sum (map snd (reglaSimpson 0 pi 8)): ¿qué número esperas antes de ejecutarlo? Después intenta escribir Simpson con \(n = 5\) subintervalos. ¿Por qué no se puede con esta reglaSimpson?

Idea. En Gauss–Legendre los nodos y los pesos se eligen juntos, en \([-1, 1]\). Una regla de Gauss es otra Regla Double: no hace falta ningún código nuevo para aplicarla, solo una función que la traslade a \([a, b]\).

Recuerda: con \(n\) nodos libres y \(n\) pesos libres, una regla tiene \(2n\) parámetros, y Gauss los usa para integrar exactamente hasta el grado \(2n - 1\).

Añade a U2T4.idr:

-- reglas de Gauss–Legendre en [−1, 1]: nodos = raíces de Pₙ
gauss2, gauss3, gauss5 : Regla Double
gauss2 = [ (-1 / sqrt 3, 1), (1 / sqrt 3, 1) ]
gauss3 = [ (-sqrt (3 / 5), 5 / 9), (0, 8 / 9), (sqrt (3 / 5), 5 / 9) ]
gauss5 = [ (-x2, w2), (-x1, w1), (0, 128 / 225), (x1, w1), (x2, w2) ]
  where
    x1, x2, w1, w2 : Double
    x1 = sqrt (5 - 2 * sqrt (10 / 7)) / 3
    x2 = sqrt (5 + 2 * sqrt (10 / 7)) / 3
    w1 = (322 + 13 * sqrt 70) / 900
    w2 = (322 - 13 * sqrt 70) / 900

-- traslada una regla de [−1, 1] a [a, b]:  x = m + r t,  peso r w
enIntervalo : Double -> Double -> Regla Double -> Regla Double
enIntervalo a b regla = [ (m + r * t, r * w) | (t, w) <- regla ]
  where
    m, r : Double
    m = (a + b) / 2
    r = (b - a) / 2

gauss2 es la regla que la nota conceptual deduce a mano: nodos \(\pm 1/\sqrt3\) y pesos \(1\). Los nodos y pesos de gauss5 tienen forma cerrada; los escribimos así en lugar de copiar decimales de una tabla. El factor \(r = \frac{b-a}{2}\) de enIntervalo es el del cambio de variable de la nota conceptual.

El límite de exactitud

Predice. gauss2 debería integrar exactamente \(x^2\) y \(x^3\) en \([-1, 1]\) y fallar con \(x^4\) (da \(\frac29\) en vez de \(\frac25\)). Con gauss5, ¿en qué grado empieza a fallar?

Ejecuta.

U2T4> integrarCon gauss2 (\x => x * x)
0.6666666666666669
U2T4> integrarCon gauss2 (\x => x * x * x)
0.0
U2T4> integrarCon gauss2 (\x => x * x * x * x)
0.22222222222222235
U2T4> [ integrarCon gauss5 (\x => pow x k) | k <- [8, 9, 10] ]
[0.22222222222222218, 0.0, 0.17888636936255978]
U2T4> the (List Double) [2 / 9, 0, 2 / 11]
[0.2222222222222222, 0.0, 0.18181818181818182]

Lee.

  • gauss2 integra \(x^2\) (\(\frac23\)) y \(x^3\) (\(0\)) salvo el último dígito, y con \(x^4\) da \(\frac29\): falla justo en el grado \(2n = 4\).
  • gauss5 acierta en \(x^8\) y \(x^9\) y falla en \(x^{10}\): exacta hasta el grado \(2\cdot5 - 1 = 9\).
  • Los últimos dígitos distintos son redondeo de los nodos irracionales, no error del método.

Gauss contra trapecio y Simpson

Predice. Con 5 evaluaciones de \(\sin\), ¿superará Gauss a Simpson con 17?

Ejecuta.

U2T4> enIntervalo 0 pi gauss2
[(0.6638966446777875, 1.5707963267948966), (2.4776960089120057, 1.5707963267948966)]
U2T4> [ integrarCon (enIntervalo 0 pi r) sin | r <- [gauss2, gauss3, gauss5] ]
[1.9358195746511366, 2.001388913607743, 2.0000001102844718]
U2T4> [ abs (integrarCon (enIntervalo 0 pi r) sin - 2) | r <- [gauss2, gauss3, gauss5] ]
[0.06418042534886337, 0.0013889136077431807, 1.102844717770779e-7]

Lee.

  • Los nodos trasladados ya no son “bonitos” (\(0.66\) y \(2.48\)), y los pesos son \(\pi/2\).
  • Son las filas de Gauss de la tabla de la nota conceptual. Con 5 evaluaciones, el error es \(1.1\times10^{-7}\), más de cien veces menor que el de Simpson con 17 (\(1.7\times10^{-5}\)).

Tu turno. Aplica gauss5 a \(\int_0^1 \sqrt{x}\,dx = \frac23\). ¿Sigue siendo tan precisa? (La pista está en \(\sqrt{x}\) cerca de \(0\); volveremos a esta función en /u2/t5.)

Idea. Monte Carlo también es una Regla: nodos aleatorios uniformes en \([a, b]\), todos con peso \((b-a)/N\). En dimensión \(d\), el promedio se hace sobre puntos de \([0,1]^d\), y el error típico \(\sigma/\sqrt N\) se estima con las mismas muestras.

Números pseudoaleatorios reproducibles

Para que tus resultados coincidan con los de esta nota (y con los de las versiones en otros lenguajes), escribimos un generador congruencial lineal: una función siguiente que, aplicada repetidamente a una semilla, produce una sucesión de enteros de 64 bits que “parecen” aleatorios. Añade a U2T4.idr:

-- generador congruencial lineal: x ↦ a·x + c  (mód 2⁶⁴)
siguiente : Bits64 -> Bits64
siguiente x = 6364136223846793005 * x + 1442695040888963407

-- de un estado a un número uniforme en [0, 1): sus 53 bits altos
aUniforme : Bits64 -> Double
aUniforme x = cast (x `div` 2048) / 9007199254740992.0     -- 2¹¹ = 2048, 2⁵³ = 9007199254740992

-- stream infinito de uniformes a partir de una semilla
uniformes : Bits64 -> Stream Double
uniformes semilla = map aUniforme (tail (iterate siguiente semilla))

Bits64 es un entero sin signo de 64 bits: sus operaciones se hacen módulo \(2^{64}\), así que el desbordamiento no es un error sino parte del generador. Dividir entre \(2^{11}\) descarta los 11 bits bajos y deja 53, los de la mantisa de un Double (/u1/t1). uniformes devuelve un Stream, el tipo de las sucesiones infinitas de Idris: a diferencia de una List, no tiene final, y Idris acepta su definición como total porque cada elemento se produce en un número finito de pasos.

U2T4> take 3 (uniformes 42)
[0.5682303266439076, 0.2254634289477513, 0.41283831882951183]
U2T4> take 3 (uniformes 43)
[0.913230842638327, 0.6331721115346789, 0.4558743901677089]

La misma semilla da siempre la misma lista; otra semilla, otra lista.

Monte Carlo en una dimensión

Añade a U2T4.idr:

-- N nodos aleatorios uniformes en [a, b], todos con peso (b − a)/N
reglaMonteCarlo : Bits64 -> Double -> Double -> Nat -> Regla Double
reglaMonteCarlo semilla a b n = [ (a + (b - a) * u, (b - a) / cast n) | u <- take n (uniformes semilla) ]

Predice. Para \(\int_0^\pi \sin x\,dx = 2\), Gauss con 5 puntos dio 7 cifras. ¿Cuántas dará Monte Carlo con \(N = 10^6\)?

Ejecuta. Con un millón de puntos usamos :exec, que compila la expresión antes de ejecutarla.

U2T4> :exec printLn [ integrarCon (reglaMonteCarlo 42 0 pi n) sin | n <- [100, 10000, 1000000] ]
[2.0317487842856043, 2.007373519185554, 1.998599715162712]
U2T4> :exec printLn [ integrarCon (reglaMonteCarlo 7 0 pi n) sin | n <- [100, 10000, 1000000] ]
[1.9808962625239876, 1.9968979829503097, 2.001096977386755]

Lee.

  • Con un millón de evaluaciones, Monte Carlo da unas 3 cifras. En una dimensión es un mal método: Gauss logró 7 con cinco.
  • Con otra semilla salen otros números. \(\hat I_N\) es una variable aleatoria: lo que se controla es su error típico, no su valor exacto.

Diez dimensiones

Para \(I = \int_{[0,1]^{10}} (x_1^2 + \cdots + x_{10}^2)\,d\mathbf{x} = \frac{10}{3}\) tomamos los uniformes de \(10\) en \(10\): cada grupo es un punto del hipercubo. Para no guardar millones de números en memoria, el estado del generador viaja dentro del ciclo. Añade a U2T4.idr:

-- (estimación, error típico estimado σ/√N) en [0, 1]^d
monteCarlo : Nat -> (List Double -> Double) -> Bits64 -> Nat -> (Double, Double)
monteCarlo d f semilla n =
  let (s, s2) = acumular n semilla 0 0
      media   = s / cast n
      varianza = s2 / cast n - media * media
  in (media, sqrt (varianza / cast n))
  where
    -- sortea un punto de j coordenadas a partir del estado x
    punto : Nat -> Bits64 -> (List Double, Bits64)
    punto Z     x = ([], x)
    punto (S j) x = let x1 = siguiente x
                        (resto, x') = punto j x1
                    in (aUniforme x1 :: resto, x')
    -- suma de los valores y de sus cuadrados, en una sola pasada
    acumular : Nat -> Bits64 -> Double -> Double -> (Double, Double)
    acumular Z     _ s s2 = (s, s2)
    acumular (S k) x s s2 = let (p, x') = punto d x
                                v = f p
                            in acumular k x' (s + v) (s2 + v * v)

sumaCuadrados : List Double -> Double
sumaCuadrados xs = sum [ x * x | x <- xs ]

La varianza se calcula como \(\overline{f^2} - \bar f^{\,2}\) con las mismas muestras, así que el error típico no requiere conocer \(I\). Las dos funciones auxiliares recorren un Nat que baja de uno en uno, así que Idris comprueba que terminan.

Predice. La nota conceptual calcula \(\sigma = \sqrt{40/45} \approx 0.943\). ¿Qué errores típicos esperas para \(N = 10^2, 10^4, 10^6\)?

Ejecuta.

U2T4> sqrt (40 / 45)
0.9428090415820634
U2T4> :exec printLn [ monteCarlo 10 sumaCuadrados 42 n | n <- [100, 10000, 1000000] ]
[(3.4122910210968094, 0.0936175340269981), (3.329424963126183, 0.009513155527633745), (3.3326918175871443, 9.432832208770461e-4)]
U2T4> :exec printLn [ abs (fst (monteCarlo 10 sumaCuadrados 42 n) - 10 / 3) | n <- [100, 10000, 1000000] ]
[0.07895768776347589, 0.003908370207150291, 6.415157461892029e-4]

Lee.

  • El error típico estimado es \(\approx 0.94/\sqrt N\): \(0.094\), \(0.0095\), \(0.00094\). Multiplicar \(N\) por \(100\) lo divide entre \(10\), la tasa \(N^{-1/2}\).
  • El error real (\(0.079\), \(0.0039\), \(0.00064\)) fluctúa alrededor del error típico, como en la tabla de la nota conceptual; con nuestra semilla los números son otros, pero el comportamiento es el mismo.
  • La dimensión no apareció en ninguna parte del cálculo del error. Con \(10^6\) puntos hay tres cifras en \(d = 10\); una malla de \(10^6\) puntos tendría apenas \(4\) puntos por eje.

Tu turno. Repite el experimento en \(d = 100\) con :exec printLn (monteCarlo 100 sumaCuadrados 42 10000) (ahora \(I = 100/3\)). ¿Cambió la tasa \(N^{-1/2}\)? ¿Cambió \(\sigma\)? Compara con \(\sqrt{400/45}\).

Para saber más: ¿qué tan aleatorio es un generador congruencial?

La sucesión \(x_{k+1} = a x_k + c \pmod{2^{64}}\) es completamente determinista: conocida la semilla, se conoce toda la lista. Se llama pseudoaleatoria porque pasa muchas pruebas estadísticas de aleatoriedad. Las constantes de siguiente son las del generador MMIX de Knuth; con ellas el período es \(2^{64}\), el máximo posible.

Los bits bajos de un generador congruencial módulo una potencia de \(2\) son poco aleatorios (el último bit alterna \(0, 1, 0, 1, \ldots\)), por eso aUniforme descarta los \(11\) bits bajos. Para simulaciones serias se usan generadores mejores (PCG, xoshiro, Mersenne Twister); la idea, una función de estado a estado aplicada con iterate, es la misma.
