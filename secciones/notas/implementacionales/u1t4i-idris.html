Nota Implementacional
🜂 Implementación en: Idris2
← Nota conceptual · Práctica →

Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con Idris2 0.7.0.

Las definiciones (bloques sin prompt) van en un archivo U1T4.idr. Las consultas (con el prompt U1T4>) se escriben en el REPL, sin el prompt. Abre el REPL con idris2 U1T4.idr y usa :r para recargar el archivo cuando añadas algo. Necesitas el archivo Exacto.idr de la implementación de /u1/t1 en la misma carpeta. Recuerda que el REPL muestra un racional \(n/d\) como MkR n d.

Archivo U1T4.idr:

module U1T4

import Data.Vect
import Exacto

%default total
  • Condición de un problema
  • Condición de una matriz
  • Estabilidad hacia atrás
  • Bien condicionado, algoritmo inestable

Idea. La condición es del problema: si \(\kappa\) es grande, un error en los datos se amplifica con cualquier algoritmo. Lo comprobamos perturbando la entrada a propósito.

Añade a U1T4.idr:

-- κ(f, x) = |x f'(x) / f(x)|, con la derivada dada a mano
condicion : (Double -> Double) -> (Double -> Double) -> Double -> Double
condicion f df x = abs (x * df x / f x)

-- cambio relativo de f cuando x cambia en un factor (1 + r)
cambioRelativo : (Double -> Double) -> Double -> Double -> Double
cambioRelativo f x r = abs ((f (x * (1 + r)) - f x) / f x)

Predice. Para \(\ln x\), la nota conceptual da \(\kappa = 1/|\ln x|\). Si cambias \(x\) en un \(10^{-10}\) relativo, ¿cuánto cambia \(\ln x\) en \(x = 10\)? ¿Y en \(x = 1.001\)?

Ejecuta.

U1T4> condicion log (\y => 1 / y) 10
0.43429448190325176
U1T4> condicion log (\y => 1 / y) 1.001
1000.499916708417
U1T4> cambioRelativo log 10 1.0e-10
4.342945178369383e-11
U1T4> cambioRelativo log 1.001 1.0e-10
1.0004991989489441e-7

Lee.

  • En \(x = 10\), el cambio de salida es \(0.43\) veces el de entrada.
  • En \(x = 1.001\), es \(1000\) veces mayor: un cambio de \(10^{-10}\) en \(x\) produce uno de \(10^{-7}\) en \(\ln x\).

Coincide con \(\kappa\) en ambos casos. Fíjate que no cambiamos el algoritmo, sino solo los datos. La sensibilidad estaba en el problema.

Tu turno. Haz lo mismo con \(f(x) = x - 1\), cuya derivada es \_ => 1, en \(x = 1.1\) y \(x = 1.001\). Antes de ejecutar, predice \(\kappa\) con la fórmula \(|x/(x-1)|\).

Idea. \(\kappa_2(A) = \sigma_{\max}/\sigma_{\min}\). Para matrices simétricas \(2\times2\), los valores singulares se calculan con una fórmula cerrada, y podemos comprobar tanto el ejemplo de la nota conceptual como la matriz de rigidez \(K\).

Una matriz \(2\times2\) es un vector de dos filas de dos entradas: Vect 2 (Vect 2 t). El tipo de las entradas, t, queda como parámetro, para poder usar Double o Racional. Añade a U1T4.idr:

Matriz2 : Type -> Type
Matriz2 t = Vect 2 (Vect 2 t)

-- Matriz simétrica 2×2: σᵢ = |λᵢ|.
-- λ_max con la fórmula usual; λ_min por Vieta (λ_max · λ_min = det),
-- para no restar dos números casi iguales.
valoresSingulares : Matriz2 Double -> (Double, Double)
valoresSingulares [[p, q], [_, s]] = (abs lMax, abs (det / lMax))
  where
    lMax : Double
    lMax = (p + s + sqrt ((p - s) * (p - s) + 4 * q * q)) / 2
    det : Double
    det = p * s - q * q

kappa2 : Matriz2 Double -> Double
kappa2 m = let (sMax, sMin) = valoresSingulares m in sMax / sMin

-- matriz de rigidez de dos osciladores acoplados
rigidez : Double -> Double -> Matriz2 Double
rigidez k k12 = [[k + k12, negate k12], [negate k12, k + k12]]

a : Matriz2 Double
a = [[1, 1], [1, 1.001]]

La fórmula usual para el valor propio pequeño, \((p+s-\sqrt{\cdots})/2\), resta dos números casi iguales. Por eso lo obtenemos con la relación de Vieta: el mismo truco que usa la fórmula cuadrática estable de la última pestaña.

Predice. La nota conceptual dice \(\kappa_2(A) \approx 4000\) y \(\kappa_2(K) = (k+2k_{12})/k\).

Ejecuta.

U1T4> valoresSingulares a
(2.0005001249999923, 4.998750000077575e-4)
U1T4> kappa2 a
4002.0007501254254
U1T4> kappa2 (rigidez 1 100)
201.0
U1T4> kappa2 (rigidez 1 1)
3.0

Lee.

  • \(A\) aplasta la bola unitaria en un elipsoide con semiejes \(\approx 2\) y \(\approx 5\times10^{-4}\): \(\kappa_2 \approx 4002\).
  • Para \(K\), el resultado numérico coincide con \((k + 2k_{12})/k\): \(201\) con \(k_{12} = 100\), y \(3\) con \(k_{12} = 1\).

El efecto en la solución de Ax = b

Estas tres funciones funcionan con cualquier tipo t que sepa sumar, restar, multiplicar y dividir: eso es lo que dicen las restricciones (Neg t, Fractional t) =>. Añade a U1T4.idr:

inversa : (Neg t, Fractional t) => Matriz2 t -> Matriz2 t
inversa [[p, q], [r, s]] =
  let det = p * s - q * r
  in [[s / det, negate q / det], [negate r / det, p / det]]

multiplica : Num t => Matriz2 t -> Vect 2 t -> Vect 2 t
multiplica m v = map (\fila => sum (zipWith (*) fila v)) m

soluciona : (Neg t, Fractional t) => Matriz2 t -> Vect 2 t -> Vect 2 t
soluciona m b = multiplica (inversa m) b

-- la misma matriz, con entradas exactas
aExacta : Matriz2 Racional
aExacta = [[1, 1], [1, 1001 // 1000]]

Predice. Con \(b = (2, 2.001)\) la solución es \((1,1)\). Si cambias \(b_2\) a \(2.002\), un cambio relativo de \(3.5\times10^{-4}\), ¿cuánto cambia \(x\)? ¿Y si haces todo el cálculo en \(\mathbb{Q}\)?

Ejecuta.

U1T4> soluciona a [2, 2.001]
[1.0, 1.0]
U1T4> soluciona a [2, 2.002]
[0.0, 2.0]
U1T4> soluciona aExacta [2, 2001 // 1000]
[MkR 1 1, MkR 1 1]
U1T4> soluciona aExacta [2, 2002 // 1000]
[MkR 0 1, MkR 2 1]

Lee.

  • Un cambio de \(3.5\times10^{-4}\) en \(b\) lleva la solución de \((1,1)\) a \((0,2)\): un cambio relativo de \(1\), unas \(2800\) veces mayor, por debajo de la cota \(\kappa_2\approx 4000\).
  • Con aritmética exacta pasa exactamente lo mismo: la solución salta de \(1/1, 1/1\) a \(0/1, 2/1\). No hubo ningún redondeo: la amplificación está en el problema, no en la aritmética de punto flotante.
Las cuentas a mano de la inversa 
U1T4> inversa aExacta
[[MkR 1001 1, MkR -1000 1], [MkR -1000 1, MkR 1000 1]]

\[ x=A^{-1}b=\begin{pmatrix}1001\cdot2-1000\cdot2.001\\-1000\cdot2+1000\cdot2.001\end{pmatrix}=\begin{pmatrix}2002-2001\\-2000+2001\end{pmatrix}=\begin{pmatrix}1\\1\end{pmatrix}. \]

Para obtener un resultado de tamaño \(1\) se restan números del orden de \(2000\). Es la huella de un problema mal condicionado: la cancelación está en el problema, y ningún algoritmo la evita.

Tu turno. Con la matriz de rigidez (\(\kappa_2 = 201\)), compara dos experimentos en los que \(b_2\) cambia en \(0.01\):

  • soluciona (rigidez 1 100) [1, 1] contra [1, 1.01];
  • soluciona (rigidez 1 100) [1, -1] contra [1, -0.99].

¿En cuál se amplifica el cambio y en cuál no? (Pista: \((1,1)\) y \((1,-1)\) son los modos en fase y en contrafase de la nota conceptual. \(\kappa_2\) es una cota: el peor caso posible, que no siempre se alcanza.)

Idea. La suma en punto flotante es estable hacia atrás: el resultado calculado es la suma exacta de dos datos perturbados en, a lo más, \(\varepsilon_{mach}\). Con Racional podemos construir esos datos perturbados y comprobarlo.

Añade a U1T4.idr:

-- δ tal que fl(x + y) = (x + y)(1 + δ), calculado en ℚ
deltaSuma : Double -> Double -> Racional
deltaSuma x y =
  let exacta = aRacional x + aRacional y
  in (aRacional (x + y) - exacta) / exacta

Predice. Para \(a = 0.1\) y \(b = 0.2\), ¿cuánto vale \(\delta\), y es cierto que \(a(1+\delta) + b(1+\delta)\) da exactamente \(\text{fl}(a+b)\)?

Ejecuta.

U1T4> aDouble (deltaSuma 0.1 0.2)
9.25185853854297e-17
U1T4> let d = deltaSuma 0.1 0.2 in aRacional 0.1 * (1 + d) + aRacional 0.2 * (1 + d) == aRacional (the Double (0.1 + 0.2))
True

Lee. El resultado calculado es la suma exacta de \(\tilde a = a(1+\delta)\) y \(\tilde b = b(1+\delta)\), que difieren de los datos en \(\delta\approx 9\times10^{-17}\), menos que \(\varepsilon_{mach}\). Eso es ser estable hacia atrás: el error del algoritmo cabe en un error de los datos del tamaño del redondeo.

En la siguiente pestaña aplicamos la misma pregunta, “¿de qué datos es solución exacta mi resultado?”, a un algoritmo que no pasa la prueba.

Idea. La raíz pequeña de \(x^2 + 10^8x + 1 = 0\) es un problema bien condicionado. Aun así, la fórmula clásica la calcula mal, porque introduce una resta catastrófica que el problema no tiene.

Añade a U1T4.idr. Las dos funciones devuelven (raíz grande, raíz pequeña) y suponen \(b > 0\), como en el ejemplo:

raicesIngenuas : Double -> Double -> Double -> (Double, Double)
raicesIngenuas a b c = ((negate b - sqrt d) / (2 * a), (negate b + sqrt d) / (2 * a))
  where
    d : Double
    d = b * b - 4 * a * c

signo : Double -> Double
signo x = if x < 0 then -1 else 1

raicesEstables : Double -> Double -> Double -> (Double, Double)
raicesEstables a b c = (x1, c / (a * x1))            -- Vieta: x1·x2 = c/a
  where
    x1 : Double                                       -- sin cancelación
    x1 = (negate b - signo b * sqrt (b * b - 4 * a * c)) / (2 * a)

Predice. La raíz pequeña verdadera es \(\approx -10^{-8}\). ¿Cuántas cifras correctas dará cada fórmula?

Ejecuta.

U1T4> raicesIngenuas 1 1.0e8 1
(-100000000.0, -7.450580596923828e-9)
U1T4> raicesEstables 1 1.0e8 1
(-100000000.0, -1e-8)

Lee. La raíz grande sale bien con las dos fórmulas. La pequeña:

  • Fórmula ingenua: \(-7.45\times10^{-9}\). Tiene un error del \(25\%\); ni una cifra es correcta.
  • Fórmula estable: \(-10^{-8}\), correcta.

El problema es el mismo; solo cambió la composición de operaciones.

¿De qué polinomio es raíz exacta cada resultado?

La raíz pequeña depende casi solo de \(c\) (\(x_2 \approx -c/b\)). Buscamos el \(\tilde c\) que hace exacta la raíz calculada, \(\tilde c = -(a\hat x^2 + b\hat x)\), y medimos cuánto se aleja de \(c\). Lo calculamos en \(\mathbb{Q}\), para que esta medición no añada errores propios. Añade a U1T4.idr:

cambioRelativoEnC : Double -> Double -> Double -> Double -> Double
cambioRelativoEnC a b c x =
  let a' = aRacional a; b' = aRacional b; c' = aRacional c; x' = aRacional x
      cTilde = negate (a' * x' * x' + b' * x')
  in aDouble (abs (cTilde - c') / abs c')
U1T4> cambioRelativoEnC 1 1.0e8 1 (snd (raicesIngenuas 1 1.0e8 1))
0.25494194030761724
U1T4> cambioRelativoEnC 1 1.0e8 1 (snd (raicesEstables 1 1.0e8 1))
7.907743916987154e-17

Lee.

  • La raíz ingenua es la raíz exacta de un polinomio con \(c\) cambiado en un \(25\%\). Ningún error de redondeo en los datos explica eso: el algoritmo no es estable hacia atrás.
  • La raíz estable es la raíz exacta de un polinomio con \(c\) cambiado en \(8\times10^{-17}\), menos que \(\varepsilon_{mach}\): es estable hacia atrás.

Es la definición de la nota conceptual, \(\tilde f(x) = f(\tilde x)\), medida con números concretos.

Otro ejemplo: √(x² + 1) − x

Sea \(f(x)=\sqrt{x^2+1}-x\). Su número de condición es

\[ \kappa(f,x)=\frac{|x|}{\sqrt{x^2+1}}\;\longrightarrow\;1, \]

así que el problema está bien condicionado. Racionalizando, \(\sqrt{x^2+1}-x = \dfrac{1}{\sqrt{x^2+1}+x}\), que es la misma función calculada sin resta. Añade a U1T4.idr:

fIngenua : Double -> Double
fIngenua x = sqrt (x * x + 1) - x

fEstable : Double -> Double
fEstable x = 1 / (sqrt (x * x + 1) + x)
U1T4> fIngenua 1.0e8
0.0
U1T4> fEstable 1.0e8
5e-9

El valor verdadero es \(\approx 5\times10^{-9}\). En fIngenua, x * x + 1 vale \(10^{16}+1\), que se redondea a \(10^{16}\) (el espaciado ahí es \(2\)); la resta da \(0\). Es un error relativo del \(100\%\) en un problema con \(\kappa\approx1\).

Dos límites que conviene conocer: para \(x<0\) es la versión “estable” la que cancela (y la original no), y para \(|x|\gtrsim10^{154}\), x * x desborda en ambas.

Tu turno. Prueba raicesIngenuas 1 1.0e10 1. ¿Qué devuelve para la raíz pequeña? Usa cambioRelativoEnC para averiguar de qué polinomio es raíz exacta ese resultado.
