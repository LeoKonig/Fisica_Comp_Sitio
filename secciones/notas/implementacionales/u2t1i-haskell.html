Una idea para toda la nota. Cada método de interpolación recibe una lista de datos [(x, y)] y devuelve una función Double -> Double. Fíjate en los tipos: interpolarLineal datos (con un solo argumento) ya es una función que se puede evaluar, pasar a map, o entregar más adelante a un integrador (/u2/t4). El código que use el interpolante no necesita saber con qué método se construyó.

  • Polinomio de Lagrange
  • Interpolación de Newton
  • Runge y Chebyshev
  • Splines cúbicos

Idea. La interpolación más simple une cada par de puntos consecutivos con una recta. Con los datos \((0,0)\), \((1,2)\), \((3,3)\) de la nota conceptual, \(p(x) = 2x\) en \([0,1]\) y \(p(x) = 2 + \tfrac12(x-1)\) en \([1,3]\).

Archivo U2T1.hs:

import Data.Ratio
import Data.List (zip4)   -- solo para el material opcional de splines

datos :: [(Double, Double)]
datos = [(0, 0), (1, 2), (3, 3)]

-- Recorre los tramos hasta encontrar el que contiene a x.
-- Supone nodos ordenados de menor a mayor.
interpolarLineal :: [(Double, Double)] -> Double -> Double
interpolarLineal ((x0, y0) : (x1, y1) : resto) x
  | x <= x1   = y0 + (y1 - y0) * (x - x0) / (x1 - x0)
  | otherwise = interpolarLineal ((x1, y1) : resto) x
interpolarLineal _ _ = errorWithoutStackTrace "x fuera del intervalo de los datos"

La primera ecuación es la recta que pasa por \((x_0,y_0)\) y \((x_1,y_1)\). Si \(x\) queda a la derecha de \(x_1\), se descarta el primer punto y se busca en el tramo siguiente. Si se acaban los tramos, \(x\) está fuera de los datos.

Predice. ¿Cuánto vale \(p(0.5)\)? ¿Y \(p(2)\)? ¿Qué pasa si pides \(p(4)\)?

Ejecuta.

ghci> interpolarLineal datos 0.5
1.0

ghci> map (interpolarLineal datos) [0, 0.5, 1, 2, 3]
[0.0,1.0,2.0,2.5,3.0]

ghci> interpolarLineal datos 4
*** Exception: x fuera del intervalo de los datos

Lee.

  • En los nodos (\(0\), \(1\), \(3\)) se recuperan los datos: \(p(x_i) = y_i\).
  • map (interpolarLineal datos) funciona porque interpolarLineal datos es una función de Double en Double.
  • Fuera de \([0, 3]\) la función se niega a responder. Es una decisión de diseño: extrapolar con rectas sería fácil, pero no hay ningún dato que lo respalde.

Tu turno. Esta versión no detecta un \(x\) a la izquierda del primer nodo: interpolarLineal datos (-1) responde algo. ¿Qué responde y por qué? Añade una guarda que lo impida.

Idea. \(p_n(x) = \sum_i y_i\,\ell_i(x)\), donde cada función base \(\ell_i(x) = \prod_{j\ne i}(x - x_j)/(x_i - x_j)\) vale \(1\) en su nodo y \(0\) en los demás. El código es la fórmula, casi letra por letra.

Añade a U2T1.hs:

-- ℓᵢ(x) = ∏_{j≠i} (x − xⱼ) / (xᵢ − xⱼ)
baseLagrange :: Fractional a => [a] -> Int -> a -> a
baseLagrange xs i x = product [ (x - xj) / (xi - xj) | (j, xj) <- zip [0 ..] xs, j /= i ]
  where
    xi = xs !! i

-- p(x) = Σᵢ yᵢ ℓᵢ(x)
lagrange :: Fractional a => [(a, a)] -> a -> a
lagrange puntos x = sum [ yi * baseLagrange xs i x | (i, yi) <- zip [0 ..] ys ]
  where
    xs = map fst puntos
    ys = map snd puntos

datosRaiz :: [(Double, Double)]
datosRaiz = [(1, 1), (4, 2), (9, 3)]

El tipo Fractional a => … dice que lagrange funciona con cualquier tipo que sepa dividir: Double para calcular en \(\mathbb{F}\), y Rational para calcular exactamente en \(\mathbb{Q}\), como en /u1/t5.

Las funciones base

Predice. Con los nodos \(1, 4, 9\), ¿qué valen \(\ell_0, \ell_1, \ell_2\) en \(x = 1\)? ¿Y en \(x = 4\)? ¿Cuánto suman las tres en \(x = 2\)?

Ejecuta.

ghci> map (\i -> baseLagrange [1, 4, 9] i 1) [0, 1, 2]
[1.0,0.0,-0.0]

ghci> map (\i -> baseLagrange [1, 4, 9] i 4) [0, 1, 2]
[-0.0,1.0,0.0]

ghci> map (\i -> baseLagrange [1, 4, 9] i 2) [0, 1, 2]
[0.5833333333333333,0.4666666666666666,-5.0e-2]

ghci> sum (map (\i -> baseLagrange [1, 4, 9] i 2) [0, 1, 2])
0.9999999999999998

Lee.

  • En los nodos se obtiene \(\ell_i(x_j) = \delta_{ij}\). El -0.0 es el cero con signo de IEEE 754: un producto con un factor negativo y otro igual a \(0\). Vale lo mismo que 0.0.
  • Entre nodos las bases toman valores cualesquiera, y pueden ser negativas.
  • Su suma es \(1\) salvo un error de redondeo: es la identidad \(\ell_0 + \ell_1 + \ell_2 \equiv 1\) de la nota conceptual (el interpolante de los datos \(y = (1,1,1)\) es la constante \(1\)).

Estimar √2

Predice. La nota conceptual obtuvo \(p_2(2) = 164/120 \approx 1.3667\). ¿Lo reproduce lagrange? ¿Y la versión exacta en \(\mathbb{Q}\)?

Ejecuta.

ghci> lagrange datosRaiz 2
1.3666666666666667

ghci> sqrt 2
1.4142135623730951

ghci> map (lagrange datosRaiz . fst) datosRaiz
[1.0,2.0,3.0]

ghci> let datosRaizQ = [(1, 1), (4, 2), (9, 3)] :: [(Rational, Rational)]

ghci> lagrange datosRaizQ 2
41 % 30

ghci> map (lagrange datosRaizQ) [1, 4, 9]
[1 % 1,2 % 1,3 % 1]

Lee.

  • lagrange datosRaiz . fst evalúa el interpolante en cada nodo: devuelve los datos. Esa es la definición de interpolar.
  • En \(\mathbb{Q}\), el resultado es \(41/30 = 164/120\), exactamente el de la nota conceptual. Es el mismo código; solo cambió el tipo de los datos.
  • El error es \(\sqrt2 - 1.3667 \approx 0.0475\): con tres nodos lejanos entre sí, no se puede pedir más.

El interpolante como función

lagrange datosRaiz es una función más. Podemos darle un nombre y evaluarla donde queramos, también fuera de \([1, 9]\):

ghci> let p = lagrange datosRaiz

ghci> map p [0, 1, 2, 9, 16, 25]
[0.6000000000000001,1.0,1.3666666666666667,3.0,3.0,0.6000000000000014]

Dentro de \([1, 9]\) el polinomio sigue a \(\sqrt{x}\) razonablemente. Fuera, no: en \(x = 16\) da \(3\) en vez de \(4\), y en \(x = 25\) da \(0.6\) en vez de \(5\). La parábola baja porque su coeficiente principal es negativo (\(-x^2/60\)), mientras que \(\sqrt x\) sigue subiendo. Esto es extrapolar, y la nota conceptual advierte que es mucho más arriesgado que interpolar.

Tu turno. Calcula lagrange datosRaizQ 2 - 41/30 y lagrange datosRaizQ 0. ¿Coincide el segundo con la constante \(3/5\) del polinomio \(-\frac{x^2}{60}+\frac{5x}{12}+\frac35\)?

Idea. La tabla de diferencias divididas se llena columna por columna, y cada columna se obtiene solo de la anterior. En Haskell eso es una función siguiente aplicada repetidamente. Los coeficientes de Newton son la primera entrada de cada columna.

Añade a U2T1.hs:

-- La tabla de diferencias divididas, como lista de columnas.
-- Columna k: [y_i, …, y_{i+k}] para i = 0, 1, …
tablaDD :: Fractional a => [(a, a)] -> [[a]]
tablaDD puntos = columnas 1 (map snd puntos)
  where
    xs = map fst puntos
    columnas k col
      | length col <= 1 = [col]
      | otherwise       = col : columnas (k + 1) (siguiente k col)
    -- a cada par vecino (u, v) le aplica (v − u) / (x_{i+k} − x_i)
    siguiente k col = zipWith3 (\u v dx -> (v - u) / dx) col (tail col) (zipWith (-) (drop k xs) xs)

coeficientesNewton :: Fractional a => [(a, a)] -> [a]
coeficientesNewton = map head . tablaDD

-- Evaluación anidada (Horner):  c₀ + (x−x₀)(c₁ + (x−x₁)(c₂ + …))
newton :: Fractional a => [(a, a)] -> a -> a
newton puntos x = foldr paso 0 (zip (map fst puntos) (coeficientesNewton puntos))
  where
    paso (xi, c) acumulado = c + (x - xi) * acumulado

En siguiente, la lista zipWith (-) (drop k xs) xs contiene las distancias \(x_{i+k} - x_i\): es la lista de nodos desplazada \(k\) lugares, menos la original. foldr evalúa la forma anidada de dentro hacia fuera: empieza con el último coeficiente y en cada paso multiplica por \((x - x_i)\) y suma \(c_i\).

La tabla

Predice. La nota conceptual calcula la tabla para \(\sqrt{x}\) con los nodos \(1, 4, 9, 16\). ¿Cuáles serán los coeficientes de Newton?

Ejecuta.

ghci> tablaDD datosRaiz
[[1.0,2.0,3.0],[0.3333333333333333,0.2],[-1.6666666666666663e-2]]

ghci> tablaDD (datosRaizQ ++ [(16, 4)])
[[1 % 1,2 % 1,3 % 1,4 % 1],[1 % 3,1 % 5,1 % 7],[(-1) % 60,(-1) % 210],[1 % 1260]]

ghci> coeficientesNewton (datosRaizQ ++ [(16, 4)])
[1 % 1,1 % 3,(-1) % 60,1 % 1260]

Lee.

  • En \(\mathbb{Q}\) la tabla es idéntica a la de la nota conceptual, columna por columna: \(\frac13, \frac15, \frac17\); luego \(-\frac1{60}, -\frac1{210}\); luego \(\frac1{1260}\).
  • Cada columna tiene un elemento menos que la anterior, como cada columna de la tabla escrita a mano.
  • En Double, \(-1/60\) aparece como -1.6666666666666663e-2: los dos últimos dígitos ya traen redondeo.

Añadir un punto

Predice. Con Newton, añadir \((16, 4)\) solo agrega el término \(\frac1{1260}(x-1)(x-4)(x-9)\). ¿Cuánto vale esa corrección en \(x = 2\)?

Ejecuta.

ghci> newton datosRaiz 2
1.3666666666666667

ghci> newton datosRaizQ 2
41 % 30

ghci> newton (datosRaizQ ++ [(16, 4)]) 2
62 % 45

ghci> newton (datosRaizQ ++ [(16, 4)]) 2 - newton datosRaizQ 2
1 % 90

ghci> abs (newton (datosRaiz ++ [(16, 4)]) 2 - sqrt 2)
3.643578459531738e-2

Lee.

  • newton datosRaizQ 2 da \(41/30\), lo mismo que lagrange: el polinomio interpolador es único, y Lagrange y Newton son dos maneras de escribirlo.
  • La corrección vale exactamente \(1/90 = 14/1260\), como en la nota conceptual. El error baja de \(0.0475\) a \(0.0364\).
  • Los tres primeros coeficientes de la tabla con cuatro puntos son los mismos que los de la tabla con tres: añadir un dato no cambia lo ya calculado. Esa es la ventaja de Newton.

Tu turno. Añade el quinto punto \((25, 5)\). ¿Cuál es el nuevo coeficiente? ¿Mejora la aproximación de \(\sqrt2\)? (Pista: los nodos nuevos están cada vez más lejos de \(x = 2\).)

Idea. Con nodos equiespaciados, el error de interpolar \(f(x) = 1/(1+25x^2)\) crece con el grado. Con nodos de Chebyshev, decrece. Lo medimos.

Recuerda: la cota de error tiene un factor que depende solo de los nodos, \(\max_x \prod|x - x_i|\). Los nodos de Chebyshev lo minimizan.

Añade a U2T1.hs:

runge :: Double -> Double
runge x = 1 / (1 + 25 * x * x)

-- n + 1 nodos igualmente espaciados en [−1, 1]
nodosEquiespaciados :: Int -> [Double]
nodosEquiespaciados n = [ -1 + 2 * fromIntegral i / fromIntegral n | i <- [0 .. n] ]

-- n + 1 nodos de Chebyshev en [−1, 1]
nodosChebyshev :: Int -> [Double]
nodosChebyshev n =
  [ cos ((2 * fromIntegral k + 1) * pi / (2 * fromIntegral (n + 1))) | k <- [0 .. n] ]

-- los datos (x, f x) en los nodos dados
muestrear :: (Double -> Double) -> [Double] -> [(Double, Double)]
muestrear f xs = [ (x, f x) | x <- xs ]

-- error máximo de p frente a f, medido en 2001 puntos de [−1, 1]
errorMaximo :: (Double -> Double) -> (Double -> Double) -> Double
errorMaximo f p = maximum [ abs (f x - p x) | x <- nodosEquiespaciados 2000 ]

errorMaximo estima el máximo sobre una malla fina; no es el máximo exacto, pero con 2001 puntos basta para ver el fenómeno.

ghci> nodosEquiespaciados 4
[-1.0,-0.5,0.0,0.5,1.0]

ghci> nodosChebyshev 2
[0.8660254037844387,6.123233995736766e-17,-0.8660254037844387]

Los nodos de Chebyshev para \(n = 2\) son \(\pm\frac{\sqrt3}{2}\) y \(0\) (salvo el redondeo de \(\cos(\pi/2)\)), los mismos del caso a mano de la nota conceptual.

Predice. ¿Qué pasa con el error máximo al subir el grado de \(4\) a \(10\) y a \(20\), con cada tipo de nodos?

Ejecuta.

ghci> [ errorMaximo runge (lagrange (muestrear runge (nodosEquiespaciados n))) | n <- [4, 10, 20] ]
[0.4383566395255679,1.91564305021925,59.822308710727924]

ghci> [ errorMaximo runge (lagrange (muestrear runge (nodosChebyshev n))) | n <- [4, 10, 20, 40] ]
[0.402016741937909,0.10915326641231027,1.533291731815506e-2,2.8940672794297573e-4]

Lee.

  • Son los números de la tabla de la nota conceptual: con nodos equiespaciados el error pasa de \(0.44\) a \(1.9\) y a \(60\); con Chebyshev baja de \(0.40\) a \(0.11\) y a \(0.015\).
  • Con Chebyshev se puede seguir: con \(41\) nodos el error es \(3\times10^{-4}\).
  • La línea es la misma para los dos experimentos. Solo cambia la función que genera los nodos. Separar “dónde muestreo” de “cómo interpolo” permite comparar métodos cambiando un solo argumento.

¿Dónde está el error?

ghci> let p20 = lagrange (muestrear runge (nodosEquiespaciados 20))

ghci> map p20 [0, 0.5, 0.9, 0.95]
[1.0,0.13793103448275862,4.7058823529374606e-2,-39.95244903304185]

Idea. El spline natural de la nota conceptual, para \((0,0)\), \((1,1)\), \((2,0)\), es \(S_0(x) = \tfrac32x - \tfrac12x^3\) en \([0,1]\) y \(S_1(x) = S_0(2-x)\) en \([1,2]\). Lo escribimos como función por tramos y comprobamos las condiciones que lo definen.

Añade a U2T1.hs:

-- El spline de la nota conceptual, escrito a mano
splineEjemplo :: Double -> Double
splineEjemplo x
  | x <= 1    = s0 x
  | otherwise = s0 (2 - x)
  where
    s0 t = 1.5 * t - 0.5 * t ^ 3

-- S' y S'', derivadas a mano tramo por tramo
derivadaSplineEjemplo :: Double -> Double
derivadaSplineEjemplo x
  | x <= 1    = 1.5 - 1.5 * x ^ 2
  | otherwise = -(1.5 - 1.5 * (2 - x) ^ 2)

segundaSplineEjemplo :: Double -> Double
segundaSplineEjemplo x
  | x <= 1    = -3 * x
  | otherwise = -3 * (2 - x)

En el segundo tramo, la regla de la cadena aplicada a \(S_0(2-x)\) cambia el signo de \(S'\), pero no el de \(S''\): el factor \((-1)\) aparece dos veces.

Lee.

  • Interpolación: pasa por los tres datos.
  • Pegado en \(x = 1\): como \(x = 1\) cae en la primera guarda, la consulta da los valores del tramo izquierdo, \(S_0'(1) = 0\) y \(S_0''(1) = -3\). Al sustituir \(x = 1\) en las fórmulas del segundo tramo se obtiene lo mismo: \(S\), \(S'\) y \(S''\) son continuas.
  • Condición natural: \(S''(0) = S''(2) = 0\).
  • La simetría respecto a \(x = 1\) se ve en \(S(0.5) = S(1.5)\).

Tu turno. Escribe terceraSplineEjemplo y comprueba que la tercera derivada salta de \(-3\) a \(+3\) en \(x = 1\). ¿Por qué ese salto es inevitable?

Para saber más: el spline natural para cualquier conjunto de datos

Para más de tres puntos ya no se resuelve a mano. Se toman como incógnitas las curvaturas \(M_i = S''(x_i)\), con \(M_0 = M_n = 0\) (condición natural). Con \(h_i = x_{i+1} - x_i\), la continuidad de \(S'\) en cada nodo interior da una ecuación que solo involucra a tres curvaturas vecinas:

\[h_{i-1}M_{i-1} + 2(h_{i-1}+h_i)\,M_i + h_i M_{i+1} = 6\left(\frac{y_{i+1}-y_i}{h_i} - \frac{y_i-y_{i-1}}{h_{i-1}}\right).\]

Es un sistema tridiagonal, que se resuelve en \(O(n)\) operaciones con el algoritmo de Thomas (la eliminación gaussiana de /u1/t5, sin las entradas que ya son cero). Conocidas las \(M_i\), en cada tramo \([x_a, x_b]\) con \(h = x_b - x_a\):

\[S(x) = \frac{M_a(x_b-x)^3 + M_b(x-x_a)^3}{6h} + \left(\frac{y_a}{h} - \frac{M_a h}{6}\right)(x_b - x) + \left(\frac{y_b}{h} - \frac{M_b h}{6}\right)(x - x_a).\]

Añade a U2T1.hs (el import Data.List (zip4) ya está al inicio del archivo):

-- Spline cúbico natural para nodos ordenados.
splineNatural :: [(Double, Double)] -> Double -> Double
splineNatural puntos x = tramo (head ([t | t <- tramos, x <= limiteDerecho t] ++ [last tramos]))
  where
    xs = map fst puntos
    ys = map snd puntos
    hs = zipWith (-) (tail xs) xs
    pendientes = zipWith (/) (zipWith (-) (tail ys) ys) hs
    -- curvaturas: M₀ = 0, las interiores resolviendo el sistema, Mₙ = 0
    ms = [0] ++ thomas (init (tail hs))
                       (zipWith (\a b -> 2 * (a + b)) hs (tail hs))
                       (init (tail hs))
                       (map (6 *) (zipWith (-) (tail pendientes) pendientes))
             ++ [0]
    tramos = zip3 (zip xs (tail xs)) (zip ys (tail ys)) (zip ms (tail ms))
    limiteDerecho ((_, xb), _, _) = xb
    tramo ((xa, xb), (ya, yb), (ma, mb)) =
      let h = xb - xa
      in  ma * (xb - x) ^ 3 / (6 * h) + mb * (x - xa) ^ 3 / (6 * h)
          + (ya / h - ma * h / 6) * (xb - x) + (yb / h - mb * h / 6) * (x - xa)

-- Algoritmo de Thomas: resuelve un sistema tridiagonal.
-- inferior y superior tienen un elemento menos que la diagonal.
thomas :: [Double] -> [Double] -> [Double] -> [Double] -> [Double]
thomas inferior diagonal superior derecha =
  foldr atras [] (tail (scanl adelante (0, 0) filas))
  where
    filas = zip4 (0 : inferior) diagonal (superior ++ [0]) derecha
    -- eliminación hacia adelante: deja cada fila como x_i + c'_i x_{i+1} = d'_i
    adelante (c', d') (a, b, c, d) = let m = b - a * c' in (c / m, (d - a * d') / m)
    -- sustitución hacia atrás, desde la última fila
    atras (c', d') []          = [d']
    atras (c', d') xs@(x : _) = (d' - c' * x) : xs

Con los tres puntos de la pestaña, splineNatural reproduce el spline escrito a mano. Con la función de Runge, el error baja al refinar, sin oscilaciones:

ghci> map (splineNatural [(0, 0), (1, 1), (2, 0)]) [0.5, 1.5]
[0.6875,0.6875]

ghci> [ errorMaximo runge (splineNatural (muestrear runge (nodosEquiespaciados n))) | n <- [4, 10, 20, 40] ]
[0.2793115923694134,2.1973825749581732e-2,3.1827727617368406e-3,2.7796797808532503e-4]

Con los mismos \(21\) nodos equiespaciados con los que Lagrange daba un error de \(60\), el spline da \(3\times10^{-3}\). Al duplicar los nodos de \(21\) a \(41\), el error baja unas \(11\) veces, cerca del factor \(2^4 = 16\) que se espera de un error \(O(h^4)\); en /u2/t5 aprenderemos a medir ese orden.

Requiere GHC 9.x (probado en 9.4.7) y solo bibliotecas estándar. Experimenta con un caso físico: toma la tabla de la presión de vapor del agua (o cualquier tabla de tu laboratorio), interpólala con lagrange y con interpolarLineal, y compara sus valores a medio camino entre los datos. ¿Cuál te parece más confiable? Después prueba lagrange con los nodos de Chebyshev sobre otra función de tu elección, como abs en \([-1, 1]\): ¿baja el error tan rápido como con la función de Runge?
