La malla como lista de filas. Una malla de \(N\times N\) puntos interiores se guarda con su frontera, como una lista de \(N+2\) filas de \(N+2\) valores. Así, cada punto interior tiene a sus cuatro vecinos en la misma estructura, y los valores de la frontera simplemente no se tocan. Los tipos son polimórficos: con Racional, los métodos iterativos dan fracciones exactas.

module U4T3

import Exacto
import Data.List
import Data.Maybe
import Data.Stream

%default total

-- (N + 2) filas de (N + 2) valores, con la frontera incluida
Malla : Type -> Type
Malla a = List (List a)

-- N×N puntos interiores en cero; la fila de arriba (la frontera superior) vale `arriba`
mallaInicial : Num a => Nat -> a -> Malla a
mallaInicial n arriba = replicate (n + 2) arriba :: replicate (n + 1) (replicate (n + 2) 0)

-- quita el primer y el último elemento de una lista
recortar : List a -> List a
recortar xs = take (length xs `minus` 2) (drop 1 xs)

-- solo los puntos interiores
interior : Malla a -> Malla a
interior m = map recortar (recortar m)

-- la mayor diferencia entre dos mallas, punto a punto
diferencia : Malla Double -> Malla Double -> Double
diferencia a b = foldl max 0 (zipWith (\x, y => abs (x - y)) (concat a) (concat b))

-- (anterior, actual, siguiente) en cada posición que tiene a ambos lados
ventanas : List a -> List (a, a, a)
ventanas xs = zip3 xs (drop 1 xs) (drop 2 xs)

-- una lista con solo el último elemento (vacía si xs lo es)
ultima : List a -> List a
ultima xs = drop (length xs `minus` 1) xs

-- el elemento (i, j) de una malla (0 si no existe)
en : Num a => Nat -> List a -> a
en i xs = fromMaybe 0 (getAt i xs)

elemento : Num a => Nat -> Nat -> Malla a -> a
elemento i j m = en j (fromMaybe [] (getAt i m))

La frontera superior vale arriba y las otras tres, \(0\): es el problema de la placa con un lado caliente de la nota conceptual. ventanas es la herramienta de toda la nota: aplicada a la lista de filas da, para cada fila interior, la de arriba, ella misma y la de abajo; aplicada a una fila da, para cada punto interior, su vecino oeste, él mismo y su vecino este.

Idea. Comprobamos que la solución del problema de \(2\times2\), \(a = \frac38\) y \(b = \frac18\), cumple exactamente la ecuación discreta (cada punto es el promedio de sus vecinos), y que es el mínimo de la energía discreta: cualquier perturbación la aumenta.

Recuerda: la plantilla de cinco puntos dice \(\phi_{i,j} = \frac14(\phi_{i+1,j} + \phi_{i-1,j} + \phi_{i,j+1} + \phi_{i,j-1})\), y la energía discreta es la mitad de la suma de las diferencias al cuadrado entre vecinos.

-- el problema de 2×2: a en los dos puntos de arriba, b en los de abajo
mallaCon : Num a => a -> a -> Malla a
mallaCon a b = [[1, 1, 1, 1], [0, a, a, 0], [0, b, b, 0], [0, 0, 0, 0]]

-- en cada punto interior: valor − promedio de sus cuatro vecinos (cero si se cumple la ecuación)
residuoLaplace : Fractional a => Neg a => Malla a -> Malla a
residuoLaplace m = map fila (ventanas m)
  where
    fila : (List a, List a, List a) -> List a
    fila (arr, cen, aba) =
      zipWith3 (\no, su, (oe, ce, es) => ce - (no + su + oe + es) / 4) (drop 1 arr) (drop 1 aba) (ventanas cen)

-- energía discreta: la mitad de la suma de (φ − φ_vecino)² sobre todos los pares de vecinos
energiaMalla : Fractional a => Neg a => Malla a -> a
energiaMalla m = (sum (map horizontales m) + sum (zipWith verticales m (drop 1 m))) / 2
  where
    cuadrado : a -> a
    cuadrado x = x * x
    horizontales : List a -> a
    horizontales fila = sum (zipWith (\x, y => cuadrado (x - y)) fila (drop 1 fila))
    verticales : List a -> List a -> a
    verticales f1 f2 = sum (zipWith (\x, y => cuadrado (x - y)) f1 f2)

residuoLaplace recorre las filas de tres en tres (la de arriba, la central y la de abajo) con ventanas m y, dentro de cada una, los puntos con sus vecinos con ventanas cen. drop 1 arr y drop 1 aba quedan alineados con los centros, así que zipWith3 ve en cada posición el vecino norte, el sur y la terna (oeste, centro, este).

Predice. ¿Cuánto vale el residuo de la malla con \(a = \frac38\), \(b = \frac18\)? Si se cambia \(a\) por \(\frac38 \pm \frac1{100}\), ¿la energía sube o baja?

Ejecuta.

U4T3> :exec printLn (residuoLaplace (mallaCon (3 // 8) (1 // 8)))
[[0, 0], [0, 0]]
U4T3> :exec printLn (residuoLaplace (mallaCon (1 // 2) (1 // 8)))
[[3/32, 3/32], [-1/32, -1/32]]
U4T3> :exec printLn [ energiaMalla (mallaCon a (1 // 8)) | a <- [3 // 8 - 1 // 100, 3 // 8, 3 // 8 + 1 // 100] ]
[16253/10000, 13/8, 16253/10000]

3 // 8 es la fracción exacta \(\frac38\) (de Exacto.idr), y :exec printLn la imprime como 3/8.

Lee.

  • Con \(a = \frac38\) y \(b = \frac18\), el residuo es exactamente cero en los cuatro puntos: es la solución de la ecuación discreta.
  • Con \(a = \frac12\), los puntos de arriba quedan por encima del promedio de sus vecinos (residuo positivo), y los de abajo, por debajo.
  • La energía en la solución, \(\frac{13}8\), es la menor de las tres, y las dos perturbaciones la aumentan exactamente en la misma cantidad: la solución es el mínimo de la energía, y la energía es una parábola alrededor de él. Resolver \(A\boldsymbol\phi = \mathbf b\) y minimizar la energía son el mismo problema.

Idea. Cada método es una función de malla a malla, y su sucesión de aproximaciones es el Stream iterate metodo m0: la sucesión infinita de la nota conceptual. Gauss-Seidel es SOR con \(\omega = 1\). Medimos la razón de convergencia \(\rho\) como el cociente entre dos diferencias consecutivas, contamos iteraciones, y comprobamos con la matriz \(K\) la condición de convergencia de la iteración de Richardson.

Recuerda: el error de una iteración de punto fijo lineal se multiplica en cada paso, a la larga, por el radio espectral \(\rho\); para el laplaciano, \(\rho_J = \cos(\pi h)\), \(\rho_{GS} = \rho_J^2\) y \(\rho_{SOR} = \omega_{\text{ópt}} - 1\).

Añade a U4T3.idr:

-- Jacobi: cada punto interior pasa a ser el promedio de sus cuatro vecinos VIEJOS
jacobi : Fractional a => Malla a -> Malla a
jacobi m = take 1 m ++ map fila (ventanas m) ++ ultima m
  where
    fila : (List a, List a, List a) -> List a
    fila (arr, cen, aba) =
      take 1 cen ++ zipWith3 (\no, su, (oe, _, es) => (no + su + oe + es) / 4) (drop 1 arr) (drop 1 aba) (ventanas cen)
                 ++ ultima cen

-- SOR: se recorre en orden, usando cada valor nuevo en cuanto se calcula,
-- y se exagera la corrección por el factor w
sor : Fractional a => Neg a => a -> Malla a -> Malla a
sor w [] = []
sor w (primera :: resto) = primera :: barrer primera resto
  where
    -- izq: el vecino oeste, ya actualizado; viejo: el valor anterior del punto
    paso : a -> (a, a, (a, a, a)) -> a
    paso izq (no, su, (_, viejo, es)) = viejo + w * ((no + su + izq + es) / 4 - viejo)
    -- recorre una fila de oeste a este, pasando cada valor nuevo al punto siguiente
    recorrer : a -> List (a, a, (a, a, a)) -> List a
    recorrer _   []        = []
    recorrer izq (v :: vs) = let x = paso izq v in x :: recorrer x vs
    -- recorre las filas de arriba abajo, pasando cada fila nueva a la siguiente
    barrer : List a -> Malla a -> Malla a
    barrer arribaNueva (cen :: rs@(aba :: _)) =
      let vecinos : List (a, a, (a, a, a))
          vecinos = zip3 (drop 1 arribaNueva) (drop 1 aba) (ventanas cen)
          nueva = take 1 cen ++ recorrer (en 0 cen) vecinos ++ ultima cen
      in nueva :: barrer nueva rs
    barrer _ rs = rs                                  -- la última fila (frontera) no cambia

-- Gauss-Seidel es SOR sin exagerar la corrección
gaussSeidel : Fractional a => Neg a => Malla a -> Malla a
gaussSeidel = sor 1

En jacobi, todos los promedios usan la malla vieja m. En sor, barrer pasa a cada fila la fila de arriba ya actualizada (arribaNueva), y dentro de la fila, recorrer lleva el valor recién calculado del vecino oeste (izq). Esa es toda la diferencia entre Jacobi y Gauss-Seidel: de dónde salen los vecinos. El patrón rs@(aba :: _) nombra rs a la lista que empieza con aba; como rs es una parte de la lista original, Idris ve que barrer nueva rs termina.

Predice. En el problema de \(2\times2\), ¿por qué factor se reduce el error en cada paso con Jacobi, Gauss-Seidel y SOR óptimo (\(h = \frac13\), \(\omega = \frac{2}{1 + \sin(\pi/3)} = 1.072\))? ¿Converge Jacobi a \(\frac38\) y \(\frac18\)?

Añade a U4T3.idr:

-- las diferencias entre iterados consecutivos, como Stream: d₀ = ‖x₁ − x₀‖, d₁ = ‖x₂ − x₁‖, …
diferencias : (Malla Double -> Malla Double) -> Malla Double -> Stream Double
diferencias paso m0 = let xs = iterate paso m0 in zipWith diferencia xs (tail xs)

-- la razón d_k / d_(k−1) en el problema de 2×2: tiende a ρ
razon : (Malla Double -> Malla Double) -> Nat -> Double
razon paso k = let ds = diferencias paso (mallaInicial 2 1) in index k ds / index (k `minus` 1) ds

Lee.

  • En \(\mathbb{Q}\), Jacobi da \(a = \frac14, \frac5{16}, \frac{11}{32}, \frac{23}{64}, \ldots, \frac{383}{1024}\) (cada terna se imprime como (k, (a, b))): es la tabla de la nota conceptual (\(0.25,\ 0.3125,\ 0.3438,\ 0.3594,\ \ldots,\ 0.3740\)), y el error en \(a\), \(\frac38 - a\), es \(\frac18, \frac1{16}, \frac1{32}, \ldots\): exactamente se divide entre 2 en cada paso.
  • Gauss-Seidel llega a \((0.375,\ 0.125)\): la solución \(a = \frac38\), \(b = \frac18\).
  • Las razones medidas son \(0.5\) para Jacobi y \(0.25\) para Gauss-Seidel: \(\rho_J = \cos\frac\pi3\) y \(\rho_{GS} = \rho_J^2\).
  • SOR da una razón de \(0.08\), cerca del \(0.072\) predicho. Con el \(\omega\) óptimo, la matriz de iteración tiene un valor propio repetido y el error decrece como \(k\rho^k\), así que la razón medida se acerca a \(\rho\) más despacio.

Contar iteraciones en una malla de 10×10

Añade a U4T3.idr:

-- cuántos pasos hacen falta para reducir el error un factor dado (a lo más 100 000)
iteracionesPara : (Malla Double -> Malla Double) -> Malla Double -> Malla Double -> Double -> Nat
iteracionesPara paso m0 sol factor = contar 100000 (iterate paso m0)
  where
    e0 : Double
    e0 = diferencia m0 sol
    contar : Nat -> Stream (Malla Double) -> Nat
    contar Z     _         = 0
    contar (S f) (m :: ms) = if diferencia m sol > factor * e0 then S (contar f ms) else 0

-- la solución de la malla de 10×10: 400 pasos de SOR óptimo
sol10 : Malla Double
sol10 = index 400 (iterate (sor (2 / (1 + sin (pi / 11)))) (mallaInicial 10 1))

contar es el consumidor que detiene el Stream. Recorrer una sucesión infinita “hasta que pase algo” no es total, porque nada garantiza que pase; con un máximo de pasos, contar siempre termina, y si el método no convergiera devolvería ese máximo.

Predice. La nota conceptual calcula, a partir de los radios espectrales, \(334\), \(167\) y \(24\) iteraciones para reducir el error un factor \(10^{-6}\) con \(N = 10\). ¿Cuántas hacen falta de verdad, partiendo de cero?

Ejecuta.

U4T3> :exec printLn [ iteracionesPara p (mallaInicial 10 1) sol10 1.0e-6 | p <- [jacobi, gaussSeidel, sor (2 / (1 + sin (pi / 11)))] ]
[317, 157, 28]

Lee. \(317\), \(157\) y \(28\): del orden de las predicciones, y en la misma proporción (\(2:1\) entre Jacobi y Gauss-Seidel; diez veces menos con SOR). Las predicciones suponen que el error está dominado por el modo más lento desde el principio; el error inicial real es una mezcla de modos, y los rápidos desaparecen antes. sol10 es la solución calculada con 400 pasos de SOR, exacta a precisión de máquina.

Cuándo converge: la iteración de Richardson con K

Añade a U4T3.idr:

punto : Num a => List a -> List a -> a
punto u v = sum (zipWith (*) u v)

longitud : List Double -> Double
longitud x = sqrt (punto x x)

matVec : Num a => List (List a) -> List a -> List a
matVec m v = [ punto fila v | fila <- m ]

matrizK : Num a => Neg a => List (List a)
matrizK = [[2, -1, 0], [-1, 2, -1], [0, -1, 2]]

-- un paso de Richardson: x ← x + w (b − A x); `op` es la función x ↦ A x
richardson : Num a => Neg a => a -> (List a -> List a) -> List a -> List a -> List a
richardson w op b x = zipWith (+) x (map (w *) (zipWith (-) b (op x)))

richardson no recibe la matriz, sino la función \(\mathbf x \mapsto A\mathbf x\). Es todo lo que necesita un método iterativo, y lo que usaremos también con el laplaciano, que nunca se escribe como matriz.

Predice. Con \(\omega = 0.5\) el radio espectral es \(0.707\) y con \(\omega = 0.6\) es \(1.049\). ¿Qué pasará con cada iteración, partiendo de \(\mathbf x = 0\) con \(\mathbf b = (1, 0, 1)\)?

Ejecuta.

[0.9999990463256836, 0.9999990463256836, 0.9999990463256836]
U4T3> [ longitud (index k (iterate (richardson 0.6 (matVec matrizK) [1, 0, 1]) [0, 0, the Double 0])) | k <- [10, 50, 100] ]

Lee. Con \(\omega = 0.5\), en 40 pasos la iteración llega a \((1, 1, 1)\) con un error de \(10^{-6}\), como predice \(0.707^{40}\). Con \(\omega = 0.6\), la longitud de \(\mathbf x\) pasa de \(1.7\) a \(3.3\) y a \(33\): el modo de mayor frecuencia se multiplica por \(-1.049\) en cada paso y crece sin cota. La misma ecuación de punto fijo, con un \(\omega\) demasiado grande, tiene un punto fijo repulsivo.

Tu turno. Encuentra con experimentos el \(\omega\) que hace converger más rápido la iteración de Richardson sobre \(K\). Compara con la fórmula \(\omega = \frac{2}{\lambda_{\min} + \lambda_{\max}} = 0.5\) y explica por qué es el óptimo.

Idea. El gradiente conjugado es otro Stream, ahora de estados (solución, residuo, dirección), y solo necesita la función \(\mathbf x\mapsto A\mathbf x\). Con Racional reproducimos los dos pasos exactos de la nota conceptual; con el laplaciano escrito como función, contamos las iteraciones para \(N = 10, 30, 100\).

Recuerda: CG elige direcciones \(A\)-ortogonales y, en cada paso, el punto de menor energía del subespacio de Krylov; su número de iteraciones crece como \(\sqrt{\kappa_2}\).

Añade a U4T3.idr:

-- el estado del gradiente conjugado
record EstadoCG a where
  constructor MkEstado
  solucion  : List a
  residuo   : List a
  direccion : List a

-- la sucesión de estados de CG, desde x₀ = 0; `op` es x ↦ A x
gradienteConjugado : Fractional a => Neg a => (List a -> List a) -> List a -> Stream (EstadoCG a)
gradienteConjugado op b = iterate paso (MkEstado (map (const 0) b) b b)
  where
    paso : EstadoCG a -> EstadoCG a
    paso (MkEstado x r p) =
      let ap   = op p
          alfa = punto r r / punto p ap               -- longitud del paso
          x'   = zipWith (+) x (map (alfa *) p)
          r'   = zipWith (-) r (map (alfa *) ap)
          beta = punto r' r' / punto r r
          p'   = zipWith (+) r' (map (beta *) p)      -- nueva dirección, A-ortogonal a las anteriores
      in MkEstado x' r' p'

-- parte una lista en trozos de n elementos
trozos : Nat -> List a -> List (List a)
trozos n xs = ir (length xs) xs
  where
    ir : Nat -> List a -> List (List a)
    ir Z     _  = []
    ir _     [] = []
    ir (S f) ys = take n ys :: ir f (drop n ys)

-- el laplaciano discreto de N×N (multiplicado por h²) como FUNCIÓN: φ ↦ Aφ, con frontera cero
laplaciano : Num a => Neg a => Nat -> List a -> List a
laplaciano n v =
  let cero = replicate (n + 2) 0
      g = cero :: [ 0 :: f ++ [0] | f <- trozos n v ] ++ [cero]
  in concat (map fila (ventanas g))
  where
    fila : (List a, List a, List a) -> List a
    fila (arr, cen, aba) =
      zipWith3 (\no, su, (oe, ce, es) => 4 * ce - no - su - oe - es) (drop 1 arr) (drop 1 aba) (ventanas cen)

-- iteraciones de CG hasta ‖r‖ ≤ 10⁻⁶ ‖b‖, con b = 1 en todos los puntos (carga uniforme)
iteracionesCG : Nat -> Nat
iteracionesCG n = contar 10000 (gradienteConjugado (laplaciano n) b)
  where
    b : List Double
    b = replicate (n * n) 1
    contar : Nat -> Stream (EstadoCG Double) -> Nat
    contar Z     _         = 0
    contar (S f) (e :: es) = if longitud (residuo e) > 1.0e-6 * longitud b then S (contar f es) else 0

laplaciano n nunca construye la matriz de \(N^2\times N^2\): rodea el vector, partido en filas, con un marco de ceros, y aplica la plantilla de cinco puntos. Es una matriz dispersa en su forma más pura, una función. El consumidor de iteracionesCG mide el residuo, como recomienda la nota conceptual, y lleva un máximo de pasos para ser total. En trozos, el combustible es la longitud de la lista: cada llamada quita al menos un elemento.

Predice. Para \(K\mathbf x = (1, 0, 1)\), la nota conceptual llega a \((1,1,1)\) en dos pasos. ¿Lo reproduce el código en aritmética exacta? Para el laplaciano, la nota conceptual midió \(14\), \(48\) y \(159\) iteraciones con \(N = 10, 30, 100\): ¿cuántas da nuestro CG?

Lee.

  • En \(\mathbb{Q}\), los iterados son \((0,0,0)\), \((\frac12, 0, \frac12)\) y \((1, 1, 1)\), exactos: los dos pasos de la nota conceptual, sin redondeo. En el tercer estado el residuo es exactamente cero: CG en aritmética exacta termina; en punto flotante lo detiene la tolerancia.
  • Para el laplaciano, \(14\), \(48\) y \(159\) iteraciones: los mismos números de la tabla de la nota conceptual. Al triplicar \(N\) (y multiplicar por 9 el número de incógnitas), las iteraciones se triplican, como \(\sqrt{\kappa_2} = O(N)\). Con \(N = 100\) son \(10^4\) incógnitas y 159 iteraciones, frente a las \(28\,554\) de Jacobi.

Idea. Medimos las dos observaciones de la nota conceptual que explican por qué funcionan multigrid y por qué hay que cuidar el criterio de parada: Jacobi amortiguado elimina rápido el error oscilatorio y despacio el suave, y una iteración lenta se detiene lejos de la solución si solo se mira la diferencia entre iterados.

Recuerda: Jacobi amortiguado con \(\omega = \frac23\) multiplica el modo \(k\) del error por \(1 - \frac43\sin^2\frac{k\pi h}{2}\), y el error real de una iteración con razón \(\rho\) es \(\approx\frac{\rho}{1-\rho}\) veces la diferencia entre iterados.

Añade a U4T3.idr:

-- factor por iteración de Jacobi amortiguado (ω = 2/3) sobre el modo k, en 1D con n puntos
factorSuavizado : Nat -> Nat -> Double
factorSuavizado n k =
  let h = 1 / cast (n + 1)
      s = sin (cast k * pi * h / 2)
  in 1 - 4 / 3 * s * s

-- el consumidor de la nota conceptual: el primer iterado que dista menos de tol del anterior
-- (Nothing si no ocurre en `maximo` pasos)
hasta : Nat -> Double -> Stream (Malla Double) -> Maybe (Nat, Malla Double)
hasta maximo tol xs = ir maximo 1 xs
  where
    ir : Nat -> Nat -> Stream (Malla Double) -> Maybe (Nat, Malla Double)
    ir Z     _ _         = Nothing
    ir (S f) k (x :: ys) = let y = head ys in if diferencia x y <= tol then Just (k, y) else ir f (S k) ys

-- la solución de la malla de 20×20: 1000 pasos de SOR óptimo
sol20 : Malla Double
sol20 = index 1000 (iterate (sor (2 / (1 + sin (pi / 21)))) (mallaInicial 20 1))

hasta devuelve un Maybe: si en maximo pasos los iterados nunca se acercan lo suficiente, lo dice con Nothing en lugar de seguir para siempre. Es la versión total del criterio de parada.

Predice. Con \(n = 31\), ¿qué factor tienen los modos \(k = 31\), \(16\) y \(1\)? Con Jacobi en una malla de \(N = 20\) (\(\rho = \cos\frac{\pi}{21} = 0.9888\)), si se para cuando la diferencia es \(10^{-6}\), ¿de qué tamaño será el error real?

Ejecuta.

U4T3> [ factorSuavizado 31 k | k <- [31, 16, 1] ]
[-0.33012315111479795, 0.3333333333333335, 0.9967898177814646]
U4T3> let rho = cos (pi / 21) in rho / (1 - rho)
88.53213730542991
U4T3> :exec printLn (map fst (hasta 5000 1.0e-6 (iterate jacobi (mallaInicial 20 1))))
Just 750
U4T3> :exec printLn (map (\(_, m) => diferencia m sol20) (hasta 5000 1.0e-6 (iterate jacobi (mallaInicial 20 1))))
Just 8.814624815112193e-5

Lee.

  • El modo más oscilatorio se multiplica por \(-0.33\) y el intermedio por \(+0.33\) en cada pasada: la mitad oscilatoria del error se reduce a un tercio. El más suave, por \(0.997\): casi no cambia. Jacobi es un buen suavizador y un mal método de resolución, y multigrid usa justo lo primero.
  • El factor \(\frac{\rho}{1-\rho}\) vale \(88.5\). Jacobi se detiene en la iteración 750, cuando la diferencia es \(10^{-6}\), pero su error real es \(8.8\times10^{-5}\): unas 88 veces mayor. Es la advertencia de la nota conceptual, medida: avanzar poco no significa haber llegado. map actúa dentro del Maybe, así que los dos resultados vienen envueltos en Just: la parada sí ocurrió antes del máximo.
