Vectores y matrices como listas. Un vector es una lista de números y una matriz, una lista de filas. No usamos ninguna biblioteca: cada operación de álgebra lineal es una función de pocas líneas, y todas son polimórficas. La misma matVec sirve con Double y con Racional, las fracciones exactas de Exacto.idr. Con Racional, la eliminación gaussiana se hace en \(\mathbb{Q}\), sin redondeo: es el patrón contra el que mediremos lo que hace Double.

Archivo U4T1.idr:

module U4T1

import Exacto
import Data.List
import Data.Maybe

%default total

-- un vector es una lista; una matriz, una lista de filas
Vector : Type -> Type
Vector a = List a

Matriz : Type -> Type
Matriz a = List (List a)

-- producto escalar
punto : Num a => Vector a -> Vector a -> a
punto u v = sum (zipWith (*) u v)

-- A·v: el producto escalar de cada fila con v
matVec : Num a => Matriz a -> Vector a -> Vector a
matVec m v = [ punto fila v | fila <- m ]

-- A·B: filas de A contra columnas de B (las columnas de B son las filas de su transpuesta)
matMul : Num a => Matriz a -> Matriz a -> Matriz a
matMul a b = [ [ punto fila col | col <- transpose b ] | fila <- a ]

identidad : Num a => Nat -> Matriz a
identidad n = [ [ (if i == j then 1 else 0) | j <- [1 .. n] ] | i <- [1 .. n] ]

-- la matriz de rigidez de tres masas y cuatro resortes
matrizK : Num a => Neg a => Matriz a
matrizK = [[2, -1, 0], [-1, 2, -1], [0, -1, 2]]

-- norma euclidiana
norma : Vector Double -> Double
norma v = sqrt (punto v v)

-- el elemento i de una lista (0 si no existe)
en : Num a => Nat -> List a -> a
en i xs = fromMaybe 0 (getAt i xs)

Vector y Matriz son funciones que reciben un tipo y devuelven un tipo: Matriz Double es List (List Double). transpose (de Data.List) convierte filas en columnas. matrizK tiene el tipo Num a => Neg a => Matriz a: es la misma matriz en Double, en Racional o en cualquier tipo con suma, producto y negativos, y the (Matriz Racional) matrizK elige el tipo. en i xs es el elemento \(i\) (contando desde \(0\)) de una lista. getAt devuelve un Maybe, porque la lista puede ser más corta, y fromMaybe 0 lo convierte en \(0\): así en es total, como pide %default total.

Idea. Para el sistema de \(2\times2\) de la nota conceptual medimos la amplificación de los errores relativos, y la comparamos con \(\kappa_2 = \sigma_{\max}/\sigma_{\min}\), calculando los valores singulares como raíces de los valores propios de \(A^TA\). Comprobamos también que \(\sigma_{\max}\) es el mayor estiramiento de un vector unitario.

Añade a U4T1.idr:

-- un sistema de 2×2, por la regla de Cramer, en cualquier tipo fraccionario
resolver2 : Fractional a => Neg a => Matriz a -> Vector a -> Vector a
resolver2 [[a, b], [c, d]] [e, f] = let det = a * d - b * c in [(e * d - b * f) / det, (a * f - e * c) / det]
resolver2 _ _ = []

-- (cambio relativo en x) / (cambio relativo en b), al pasar de b a b'
amplificacion : Matriz Double -> Vector Double -> Vector Double -> Double
amplificacion m b b' =
  let x  = resolver2 m b
      x' = resolver2 m b'
  in (norma (zipWith (-) x' x) / norma x) / (norma (zipWith (-) b' b) / norma b)

-- valores singulares de una matriz 2×2: raíces de los valores propios de AᵀA
valoresSingulares2 : Matriz Double -> (Double, Double)
valoresSingulares2 m =
  case matMul (transpose m) m of
    [[a, b], [_, d]] => let tr   = a + d
                            disc = sqrt ((a - d) * (a - d) + 4 * b * b)
                        in (sqrt ((tr + disc) / 2), sqrt ((tr - disc) / 2))
    _ => (0, 0)

kappa2 : Matriz Double -> Double
kappa2 m = let (s1, s2) = valoresSingulares2 m in s1 / s2

-- el mayor estiramiento ‖Av‖ sobre 100 001 vectores unitarios v = (cos t, sin t)
estiramientoMax : Matriz Double -> Double
estiramientoMax m = foldl max 0 [ norma (matVec m [cos t, sin t]) | k <- [0 .. the Integer 100000], let t = pi * cast k / 100000 ]

-- el sistema de la nota conceptual
sistema : Matriz Double
sistema = [[1, 1], [1, 1.0001]]

resolver2 solo tiene sentido para una matriz de \(2\times2\) y un vector de dos componentes; la segunda ecuación, resolver2 _ _ = [], cubre cualquier otra entrada para que la función sea total. valoresSingulares2 usa la fórmula de los valores propios de una matriz simétrica de \(2\times2\): \(\lambda = \frac{(a+d) \pm \sqrt{(a-d)^2 + 4b^2}}{2}\). estiramientoMax aplica la definición de la norma de una matriz por fuerza bruta: recorre la mitad del círculo unitario (la otra mitad da los mismos estiramientos).

Predice. La nota conceptual da \(\kappa_2 = 40\,002\) y una amplificación de unas \(28\,000\) veces. ¿Lo reproduce el código? ¿Saldrá \(\mathbf x = (1, 1)\) exacto con \(\mathbf b = (2,\ 2.0001)\)? ¿Y si escribimos \(1.0001\) y \(2.0001\) como las fracciones exactas \(\frac{10001}{10000}\) y \(\frac{20001}{10000}\)?

Ejecuta.

U4T1> resolver2 sistema [2, 2.0001]
[0.9999999999977796, 1.0000000000022204]
U4T1> :exec printLn (resolver2 [[1, 1], [1, 10001 // 10000]] [2, 20001 // 10000])
[1, 1]
U4T1> resolver2 sistema [2, 2.0002]
[0.0, 2.0]
U4T1> amplificacion sistema [2, 2.0001] [2, 2.0002]
28284.978363084814
U4T1> valoresSingulares2 sistema
(2.00005000125, 4.999875416230848e-5)
U4T1> kappa2 sistema
40001.99674490561
U4T1> :exec printLn (estiramientoMax sistema)
2.000050001208835

Lee.

  • Con \(\mathbf b' = (2,\ 2.0002)\) la solución salta a \((0, 2)\), y la amplificación es \(28\,285\), por debajo de \(\kappa_2 = 40\,002\), como en la nota conceptual.
  • Con \(\mathbf b = (2,\ 2.0001)\) no sale \((1, 1)\) exacto, sino \((1, 1)\) con un error de \(2\times10^{-12}\). Con las fracciones exactas, el mismo resolver2 da [1, 1]. El número \(2.0001\) no es representable en binario (/u1/t1): su error relativo de \(\sim10^{-16}\) es un \(\delta\mathbf b\) diminuto que \(\kappa_2 = 4\times10^4\) amplifica hasta \(\sim10^{-12}\). La regla de los dígitos ya actúa en la entrada.
  • estiramientoMax da \(2.00005\), el mismo \(\sigma_{\max}\) que la fórmula: la norma de una matriz es su mayor estiramiento. Lo pedimos con :exec printLn, que compila el cálculo antes de ejecutarlo; el REPL, que evalúa paso a paso, tardaría mucho con 100 001 ángulos.

Idea. Escribimos la eliminación gaussiana como una sola función, factorizar, que recibe como argumento la estrategia de pivoteo: tomar siempre la primera fila, o la de mayor pivote. Devuelve la permutación, \(L\) y \(U\). Con Racional reproducimos exactamente el ejemplo a mano de \(K\); con Double vemos por qué hay que pivotear, y medimos la regla de los dígitos con la matriz de Hilbert.

Recuerda: la eliminación anula lo que está bajo cada pivote restando múltiplos de la fila del pivote; los multiplicadores forman \(L\) y lo que queda forma \(U\).

Añade a U4T1.idr:

-- (permutación, L, U), con P·A = L·U
Factorizacion : Type -> Type
Factorizacion a = (List Nat, Matriz a, Matriz a)

-- una fila en proceso: (índice original, multiplicadores ya calculados, lo que queda de la fila)
Fila : Type -> Type
Fila a = (Nat, List a, List a)

cabeza : Num a => List a -> a
cabeza = en 0

-- restar a la fila el múltiplo de la fila del pivote que anula su primer elemento
reducir : Fractional a => Neg a => List a -> Fila a -> Fila a
reducir pivote (j, mj, r) =
  let mult = cabeza r / cabeza pivote
  in (j, mj ++ [mult], zipWith (\x, y => x - mult * y) (drop 1 r) (drop 1 pivote))

-- eliminación gaussiana; `elegir` decide qué fila es el siguiente pivote
factorizar : Fractional a => Neg a => (Fila a -> List (Fila a) -> Fila a) -> Matriz a -> Factorizacion a
factorizar elegir m = ir (length m) 0 [ (i, [], fila) | (i, fila) <- zip [0 .. length m] m ]
  where
    n : Nat
    n = length m
    -- c: cuántas filas quedan (el "combustible" que garantiza que ir termina); k: columna actual
    ir : Nat -> Nat -> List (Fila a) -> Factorizacion a
    ir Z     _ _         = ([], [], [])
    ir _     _ []        = ([], [], [])
    ir (S c) k (f :: fs) =
      let (i, ms, pivote) = elegir f fs
          filaL = ms ++ [1] ++ replicate (n `minus` (k + 1)) 0    -- multiplicadores, 1 en la diagonal
          filaU = replicate k 0 ++ pivote                          -- la fila del pivote
          otras = filter (\(j, _, _) => j /= i) (f :: fs)
          (perm, ls, us) = ir c (S k) (map (reducir pivote) otras)
      in (i :: perm, filaL :: ls, filaU :: us)

-- las dos estrategias
sinPivoteo : Fila a -> List (Fila a) -> Fila a
sinPivoteo f _ = f

pivoteoParcial : Num a => Abs a => Ord a => Fila a -> List (Fila a) -> Fila a
pivoteoParcial f fs = foldl (\m, g => if tam g >= tam m then g else m) f fs
  where
    tam : Fila a -> a
    tam (_, _, r) = abs (cabeza r)

-- sustitución hacia adelante: L·y = b, con unos en la diagonal de L
adelante : Num a => Neg a => Matriz a -> Vector a -> Vector a
adelante l b = foldl paso [] (zip l b)
  where
    paso : List a -> (List a, a) -> List a
    paso ys (fila, bi) = ys ++ [bi - punto (take (length ys) fila) ys]

-- sustitución hacia atrás: U·x = y, de la última incógnita a la primera
atras : Fractional a => Neg a => Matriz a -> Vector a -> Vector a
atras u y = foldr paso [] (zip u y)
  where
    paso : (List a, a) -> List a -> List a
    paso (fila, yi) xs = let i = length u `minus` S (length xs)
                         in (yi - punto (drop (S i) fila) xs) / en i fila :: xs

-- con la factorización hecha, cada lado derecho cuesta solo dos sustituciones
resolverCon : Fractional a => Neg a => Factorizacion a -> Vector a -> Vector a
resolverCon (perm, l, u) b = atras u (adelante l [ en i b | i <- perm ])

resolver : Fractional a => Neg a => Abs a => Ord a => Matriz a -> Vector a -> Vector a
resolver m = resolverCon (factorizar pivoteoParcial m)

Cada fila en proceso lleva su índice original, para registrar la permutación, y sus multiplicadores, que acaban siendo su fila de \(L\). En cada paso, elegir recibe las filas que quedan, separadas en la primera y el resto (así nunca recibe una lista vacía), y devuelve el pivote; las demás filas se reducen, y se repite con una columna menos. factorizar sinPivoteo es la eliminación de los libros; factorizar pivoteoParcial, la de los programas reales. Cambiar de estrategia es cambiar un argumento.

Idris no puede ver por sí solo que map (reducir pivote) otras tiene una fila menos que la lista original, así que ir lleva un contador c que empieza en el número de filas y baja en cada llamada: es el combustible que ya usamos en unidades anteriores para que el compilador acepte que la recursión termina.

resolverCon f es la evaluación parcial de la nota conceptual: con la factorización f ya calculada, queda una función \(\mathbf b \mapsto \mathbf x\) que solo hace las dos sustituciones.

El pivoteo existe para proteger a los Double.

La regla de los dígitos, medida

Añade a U4T1.idr:

-- la matriz de Hilbert, Hᵢⱼ = 1/(i + j − 1), en cualquier tipo fraccionario
hilbert : Fractional a => Nat -> Matriz a
hilbert n = [ [ 1 / fromInteger (cast (i + j) - 1) | j <- [1 .. n] ] | i <- [1 .. n] ]

-- error máximo al resolver Hx = b en Double, con b elegido para que x = (1, …, 1)
errorHilbert : Nat -> Double
errorHilbert n =
  let h = hilbert n
  in foldl max 0 (map (\x => abs (x - 1)) (resolver h (matVec h (replicate n 1))))

Predice. Con \(\kappa_2(H) = 4.8\times10^5\), \(1.6\times10^{13}\) y \(5.6\times10^{17}\) para \(n = 5, 10, 13\), ¿cuántos dígitos correctos quedarán? ¿Y en \(\mathbb{Q}\)?

Ejecuta.

U4T1> :exec printLn (map errorHilbert [5, 10, 13])
[5.546674231027282e-13, 1.3982024365821744e-4, 0.45183640373017386]
U4T1> :exec printLn (resolver (the (Matriz Racional) (hilbert 13)) (matVec (hilbert 13) (replicate 13 1)))

Lee.

  • En Double, los errores son \(6\times10^{-13}\), \(10^{-4}\) y \(0.45\): unos 12, 4 y ningún dígito correctos, como predice \(16 - \log_{10}\kappa\). Los valores exactos difieren de los de la nota conceptual, calculados con otra implementación de la misma eliminación, porque el redondeo depende del orden de las operaciones; los dígitos perdidos son los mismos.
  • En Racional, el mismo código da exactamente \((1, \ldots, 1)\) para \(n = 13\). El problema no es el algoritmo: es la aritmética finita frente a un problema mal condicionado.

Tu turno. Escribe la matriz de \(3\times3\) \(\begin{pmatrix}0&1&1\\1&1&0\\1&0&1\end{pmatrix}\), cuyo primer pivote es cero, en Racional. ¿Qué pasa con factorizar sinPivoteo? (Mira qué devuelve / de Exacto.idr al dividir entre cero.) ¿Y con pivoteoParcial?

Idea. Calculamos la inversa como dice la nota conceptual: una sola factorización y \(n\) resoluciones, una por cada columna de la identidad. Con Racional, \(K^{-1}\) sale exacta y la leemos como función de Green. Comparamos cuántos elementos distintos de cero tienen una matriz tridiagonal y su inversa, y calculamos exactamente el número de condición de la matriz de Hilbert.

Recuerda: resolverCon f reutiliza la factorización f para cualquier lado derecho.

Añade a U4T1.idr:

-- la columna j de A⁻¹ resuelve A·x = eⱼ; una factorización, n resoluciones
inversa : Fractional a => Neg a => Abs a => Ord a => Matriz a -> Matriz a
inversa m =
  let f = factorizar pivoteoParcial m
  in transpose [ resolverCon f e | e <- identidad (length m) ]

-- la matriz tridiagonal (−1, 2, −1) de tamaño n
tridiagonal : Num a => Neg a => Nat -> Matriz a
tridiagonal n = [ [ (if i == j then 2 else if i == j + 1 || j == i + 1 then -1 else 0) | j <- [1 .. n] ] | i <- [1 .. n] ]

-- número de elementos distintos de cero
noCeros : Eq a => Num a => Matriz a -> Nat
noCeros m = length (filter (/= 0) (concat m))

-- norma infinito: la mayor suma de valores absolutos de una fila
normaInf : Num a => Abs a => Ord a => Matriz a -> a
normaInf m = foldl max 0 [ sum (map abs fila) | fila <- m ]

identidad n es la lista de las filas de \(I\), que también son sus columnas \(\mathbf e_j\). Cada resolverCon f e es una columna de \(A^{-1}\), y transpose las acomoda como filas. En tridiagonal, los índices son Nat, sin negativos, así que “vecinos” se escribe i == j + 1 || j == i + 1 en lugar de \(|i - j| = 1\). Para el número de condición usamos la norma infinito, \(\lVert A\rVert_\infty\), que es fácil de calcular exactamente; da un número de condición \(\kappa_\infty = \lVert A\rVert_\infty\lVert A^{-1}\rVert_\infty\) del mismo orden que \(\kappa_2\).

Predice. La nota conceptual da \(K^{-1} = \frac14\begin{pmatrix}3&2&1\\2&4&2\\1&2&3\end{pmatrix}\). ¿Cuál es el desplazamiento de las tres masas si se empuja la primera con fuerza unitaria? ¿Cuántos elementos distintos de cero tendrá la inversa de una tridiagonal de \(10\times10\)?

Lee.

  • \(K^{-1}\) sale exacta, \(\frac14\begin{pmatrix}3&2&1\\2&4&2\\1&2&3\end{pmatrix}\), y \(KK^{-1} = I\) sin redondeo.
  • Empujar la primera masa con fuerza unitaria la desplaza \(\frac34\), a la segunda \(\frac12\) y a la tercera \(\frac14\): la primera columna de \(K^{-1}\), la función de Green de la nota conceptual.
  • La tridiagonal de \(10\times10\) tiene 28 elementos distintos de cero, y su inversa, los 100: es completamente densa.
  • Calculado en \(\mathbb{Q}\), el número de condición \(\kappa_\infty\) de la matriz de Hilbert vale \(9.4\times10^5\), \(3.5\times10^{13}\) y \(1.3\times10^{18}\): del mismo orden que los \(\kappa_2\) de la nota conceptual. aDouble convierte el resultado exacto a decimal solo al final. Calcularlo en Double sería inútil para \(n = 13\), porque la propia inversa saldría sin dígitos correctos.

Idea. Escribimos Cholesky fila por fila. Como puede fallar, devuelve un Maybe: Just el factor \(L\) si la matriz es definida positiva, y Nothing si no lo es. Es la prueba de positividad de la nota conceptual, expresada en el tipo. Comprobamos también que \(\mathbf x^TK\mathbf x\) es la energía de los resortes y que en las coordenadas \(L^T\mathbf x\) se vuelve una suma de cuadrados.

Recuerda: \(l_{jj} = \sqrt{a_{jj} - \sum_{k<j} l_{jk}^2}\) y \(l_{ij} = \big(a_{ij} - \sum_{k<j} l_{ik}l_{jk}\big)/l_{jj}\) para \(i > j\).

Añade a U4T1.idr:

-- Cholesky: Just L con A = L·Lᵀ, o Nothing si A no es definida positiva
cholesky : Matriz Double -> Maybe (Matriz Double)
cholesky a = map (map rellenar) (ir a [])
  where
    n : Nat
    n = length a
    rellenar : List Double -> List Double
    rellenar fila = fila ++ replicate (n `minus` length fila) 0
    -- previas: las filas de L ya calculadas
    ir : Matriz Double -> Matriz Double -> Maybe (Matriz Double)
    ir []              previas = Just previas
    ir (filaA :: resto) previas =
      let i = length previas
          -- los elementos de la fila i de L a la izquierda de la diagonal, de izquierda a derecha
          fuera = foldl (\acc, (j, lj) => acc ++ [(en j filaA - punto (take j acc) lj) / en j lj])
                        [] (zip [0 .. i] previas)
          d = en i filaA - punto fuera fuera
      in if d <= 0 then Nothing                                   -- no hay raíz real: no es SPD
                   else ir resto (previas ++ [fuera ++ [sqrt d]])

-- la forma cuadrática xᵀAx
energia : Matriz Double -> Vector Double -> Double
energia m x = punto x (matVec m x)

La lista fuera, los elementos de la fila \(i\) de \(L\) a la izquierda de la diagonal, se construye con foldl de izquierda a derecha: el elemento \(j\) usa take j acc, los que ya se calcularon. Es la fórmula de \(l_{ij}\), escrita en el orden en que se puede evaluar. Si en algún paso el número bajo la raíz no es positivo, ir devuelve Nothing y el cálculo se detiene. map (map rellenar) actúa dentro del Maybe: rellena con ceros las filas de \(L\) si hay resultado, y deja Nothing como está.

Lee.

  • cholesky matrizK da el \(L\) de la nota conceptual: \(\sqrt2 = 1.4142\), \(-0.7071\), \(1.2247\), \(-0.8165\), \(1.1547\). \(LL^T\) reconstruye \(K\) salvo un redondeo en la última cifra.
  • Para \(\begin{pmatrix}1&2\\2&1\end{pmatrix}\), Nothing: el segundo pivote sería \(1 - 4 = -3\), y la matriz no es definida positiva. El tipo Maybe obliga a quien use el resultado a considerar ese caso.
  • \(\mathbf x^TK\mathbf x = 12\), igual a \(x_1^2 + (x_1-x_2)^2 + (x_2-x_3)^2 + x_3^2 = 1 + 1 + 9 + 1\): el doble de la energía de los cuatro resortes.
  • En las coordenadas \(\mathbf z = L^T\mathbf x\), la misma energía es \(\lVert\mathbf z\rVert^2 = 12\) (salvo el último bit): Cholesky es el cambio de variables que convierte la energía en una suma de cuadrados, la “manera de medir” de la nota conceptual.
