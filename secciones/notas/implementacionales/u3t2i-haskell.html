Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con GHCi 9.4.7.

Todas las definiciones (bloques sin ghci>) van en un solo archivo, U3T2.hs. Cárgalo con ghci U3T2.hs y usa :reload cada vez que añadas algo. Las consultas (bloques con ghci>) se escriben en GHCi, sin el ghci>.

El estado de esta nota. Todos los ejemplos son ecuaciones escalares \(\dot y = f(t, y)\), así que el estado de un método de un paso es el par \((t, y)\). Un campo es una función de dos argumentos.

Archivo U3T2.hs:

import Data.Complex

-- el campo de una EDO escalar: y' = f(t, y)
type CampoT = Double -> Double -> Double

-- avanza n pasos
final :: Int -> (a -> a) -> a -> a
final n paso x = iterate paso x !! n

orden :: (Int -> Double) -> Int -> Double

Idea. Un paso de Euler implícito es la raíz de \(G(Y) = Y - y_n - h\,f(t_{n+1}, Y)\). Lo construimos componiendo dos piezas que ya conocemos: la predicción de Euler explícito, como punto de partida, y el método de Newton de /u2/t6, como resolvedor.

Añade a U3T2.hs:

-- Newton, como lista infinita de aproximaciones (ver /u2/t6)
newtonIter :: (Double -> Double) -> (Double -> Double) -> Double -> [Double]
newtonIter g dg = iterate (\x -> x - g x / dg x)

-- consume la lista: primer valor que ya no cambia (o el 50º, si no converge)
resolver :: (Double -> Double) -> (Double -> Double) -> Double -> Double
resolver g dg x0 = head ([ b | (a, b) <- zip xs (tail xs), abs (b - a) <= 1e-14 * abs b ] ++ [last xs])
  where
    xs = take 50 (newtonIter g dg x0)

eulerExplicito :: Double -> CampoT -> (Double, Double) -> (Double, Double)
eulerExplicito h f (t, y) = (t + h, y + h * f t y)

-- Euler implícito: dfdy es ∂f/∂y, necesaria para Newton
eulerImplicito :: Double -> CampoT -> CampoT -> (Double, Double) -> (Double, Double)
eulerImplicito h f dfdy (t, y) = (t1, resolver g dg prediccion)
  where
    t1         = t + h
    prediccion = y + h * f t y                 -- Euler explícito como predictor
    g  yy      = yy - y - h * f t1 yy           -- G(Y)
    dg yy      = 1 - h * dfdy t1 yy             -- G'(Y)

eulerImplicito no despeja nada: le pasa la ecuación \(G(Y) = 0\) a resolver, que a su vez consume la lista de Newton. Es la composición de la nota conceptual.

El caso lineal

Predice. Para \(\dot y = -50y\) con \(h = 0.1\), Euler explícito multiplica por \(1 - 5\) en cada paso, e implícito por \(\frac16\). ¿Qué le pasa a cada uno en 4 pasos?

Ejecuta.

ghci> [ ((1 - 5) ^ n, (1 / 6) ^ n, exp (-5 * fromIntegral n)) | n <- [1 .. 4 :: Int] ]
[(-4,0.16666666666666666,6.737946999085467e-3),(16,2.7777777777777776e-2,4.5399929762484854e-5),(-64,4.629629629629629e-3,3.059023205018258e-7),(256,7.716049382716049e-4,2.061153622438558e-9)]

Lee. Es la tabla de la nota conceptual: el explícito oscila y explota (\(-4, 16, -64, 256\)), el implícito decae (\(0.17, 0.028, \ldots\)), como la solución exacta, aunque sin mucha precisión con este \(h\).

El caso no lineal, con Newton

Añade a U3T2.hs:

-- y' = −y³ y su derivada respecto a y
cubico, dcubico :: CampoT
cubico _ y  = - y ^ 3
dcubico _ y = -3 * y ^ 2

Predice. Para \(\dot y = -y^3\), \(y_0 = 1\), \(h = 0.5\), la ecuación del paso es \(G(Y) = Y + 0.5\,Y^3 - 1 = 0\). Desde el predictor \(0.5\), ¿cuántas iteraciones de Newton hacen falta? ¿Y con la iteración de punto fijo \(Y \leftarrow 1 - 0.5\,Y^3\)?

Ejecuta.

ghci> take 4 (newtonIter (\yy -> yy + 0.5 * yy ^ 3 - 1) (\yy -> 1 + 1.5 * yy ^ 2) 0.5)
[0.5,0.8181818181818181,0.7722586691658857,0.7709180970357612]

ghci> map (\yy -> yy + 0.5 * yy ^ 3 - 1) (take 4 (newtonIter (\yy -> yy + 0.5 * yy ^ 3 - 1) (\yy -> 1 + 1.5 * yy ^ 2) 0.5))
[-0.4375,9.20360631104431e-2,2.53981468225728e-3,2.0805734513018592e-6]

ghci> eulerImplicito 0.5 cubico dcubico (0, 1)
(0.5,0.7709169970592481)

ghci> take 8 (iterate (\yy -> 1 - 0.5 * yy ^ 3) 0.5)
[0.5,0.9375,0.5880126953125,0.8983446798656587,0.6375075171166747,0.8704534252536671,0.670233435290867,0.8494612615760393]

Lee.

  • Son las columnas de la tabla de Newton de la nota conceptual: el residuo pasa de \(10^{-1}\) a \(10^{-3}\) a \(10^{-6}\), el doble de dígitos en cada iteración.
  • eulerImplicito hace todo el proceso y entrega \(y_1 = 0.770917\).
  • El punto fijo oscila alrededor de la solución y se acerca muy despacio: \(|g'| \approx 0.89\), casi \(1\).

Euler implícito en el oscilador: la geometría

En el oscilador, \(\dot q = p\), \(\dot p = -q\), cada paso implícito es un sistema lineal \(2\times2\), que se despeja a mano. Añade a U3T2.hs:

-- Euler explícito e implícito en el oscilador; el implícito resuelve q' = q + h p', p' = p − h q'
eulerExplicitoOsc, eulerImplicitoOsc :: Double -> (Double, Double) -> (Double, Double)
eulerExplicitoOsc h (q, p) = (q + h * p, p - h * q)
eulerImplicitoOsc h (q, p) = ((q + h * p) / (1 + h * h), (p - h * q) / (1 + h * h))

-- punto medio implícito: y' = y + h f((y + y')/2), despejado con a = h/2
puntoMedioOsc :: Double -> (Double, Double) -> (Double, Double)
puntoMedioOsc h (q, p) = (((1 - a * a) * q + 2 * a * p) / (1 + a * a), ((1 - a * a) * p - 2 * a * q) / (1 + a * a))
  where
    a = h / 2

-- determinante de un mapa lineal del plano (ver /u3/t1) y energía del oscilador
determinante :: ((Double, Double) -> (Double, Double)) -> Double
determinante paso = a * d - b * c
  where
    (a, c) = paso (1, 0)
    (b, d) = paso (0, 1)

energiaOsc :: (Double, Double) -> Double
energiaOsc (q, p) = (q * q + p * p) / 2

Predice. Euler explícito multiplica las áreas por \(1 + h^2\). La nota conceptual dice que Euler implícito las multiplica por \(\frac{1}{1+h^2}\) y que el punto medio, que es medio paso implícito seguido de medio paso explícito, las conserva. ¿Qué energía queda tras 1000 pasos de cada uno con \(h = 0.1\)?

Ejecuta.

ghci> map determinante [eulerExplicitoOsc 0.1, eulerImplicitoOsc 0.1, puntoMedioOsc 0.1]
[1.01,0.9900990099009901,1.0000000000000002]

ghci> [ energiaOsc (final 1000 paso (1, 0)) | paso <- [eulerExplicitoOsc 0.1, eulerImplicitoOsc 0.1, puntoMedioOsc 0.1] ]
[10479.577818906859,2.3855922854922222e-5,0.500000000000106]

ghci> (puntoMedioOsc 0.1 (1, 0), eulerExplicitoOsc 0.05 (eulerImplicitoOsc 0.05 (1, 0)))
((0.9950124688279303,-9.975062344139651e-2),(0.9950124688279303,-9.975062344139651e-2))

Lee.

  • Los determinantes son \(1.01\), \(0.990099 = \frac1{1.01}\) y \(1\): el explícito infla las áreas, el implícito las encoge por el mismo factor, y el punto medio las conserva.
  • Tras 1000 pasos, la energía explota a \(10\,480\) con el explícito, se apaga a \(2.4\times10^{-5}\) con el implícito, y se queda en \(0.5\) con el punto medio. Ninguno de los dos Euler está en el grupo de los mapas simplécticos de /u3/t1; el punto medio, sí.
  • La última consulta comprueba la composición: medio paso de Euler implícito seguido de medio paso de Euler explícito es el punto medio implícito, salvo redondeo. Sus errores opuestos se cancelan, como en Verlet.

Idea. El predictor-corrector AB2/trapecio predice con Adams-Bashforth, evalúa \(f\) en la predicción y corrige con la regla del trapecio. Su estado guarda los dos últimos puntos, porque AB2 necesita \(f_n\) y \(f_{n-1}\).

Añade a U3T2.hs:

-- un paso de predictor-corrector; el estado es la ventana (t₀, y₀, t₁, y₁)
ab2pc :: Double -> CampoT -> (Double, Double, Double, Double) -> (Double, Double, Double, Double)
ab2pc h f (t0, y0, t1, y1) = (t1, y1, t2, y2)
  where
    f0 = f t0 y0
    f1 = f t1 y1
    t2 = t1 + h
    yp = y1 + h * (3 / 2 * f1 - 1 / 2 * f0)     -- predecir (AB2)
    y2 = y1 + h / 2 * (f1 + f t2 yp)           -- evaluar y corregir (trapecio)

decaimiento :: CampoT
decaimiento _ y = - y

-- error en t = 1 con n pasos, arrancando con el valor exacto y₁ = e^(−h)
errorPC :: Int -> Double
errorPC n = abs (y - exp (-1))
  where
    h            = 1 / fromIntegral n
    (_, _, _, y) = iterate (ab2pc h decaimiento) (0, 1, h, exp (- h)) !! (n - 1)

La salida de ab2pc tiene la misma forma que la entrada: el punto más viejo sale, el nuevo entra. Esa es la ventana deslizante de la nota conceptual.

Predice. La nota conceptual hace un paso a mano para \(\dot y = -y\) con \(h = 0.1\) y obtiene \(y_2 = 0.818640\). ¿Qué orden tendrá el método?

Ejecuta.

ghci> ab2pc 0.1 decaimiento (0, 1, 0.1, exp (-0.1))
(0.1,0.9048374180359595,0.2,0.8186399568676332)

ghci> exp (-0.2)
0.8187307530779818

ghci> map errorPC [10, 20, 40]
[3.6801196285257687e-4,8.432068039387897e-5,2.0119529428208605e-5]

ghci> orden errorPC 20
2.067289945682643

Lee.

  • \(y_2 = 0.818640\), el valor de la nota conceptual: error \(9.1\times10^{-5}\), sin resolver ninguna ecuación.
  • El orden medido es \(2\): el de la regla del trapecio, aunque se haya usado la predicción en lugar del valor exacto de \(f_{n+1}\).
  • Cada paso evalúa \(f\) dos veces: f t1 y1 y f t2 yp. (f t0 y0 se recalcula aquí por simplicidad; una implementación cuidadosa la guardaría en la ventana.)

Tu turno. Escribe ab2, solo el predictor, y mide su orden con orden. ¿Cuánto mayor es su error que el del predictor-corrector? Compara con el cociente \(\frac{5/12}{1/12} = 5\) de las constantes de error.

Idea. AB4 necesita una ventana de 4 puntos. La representamos con una 4-tupla, de modo que el tipo dice el tamaño. El problema del arranque es construir la primera ventana a partir de \(y_0\), con un método de un paso que se pasa como argumento.

Recuerda: el orden global resultante es \(\min(p,\ q+1)\), donde \(q\) es el orden del arrancador.

Añade a U3T2.hs:

-- la ventana de AB4: exactamente 4 puntos (t, y)
type Ventana = ((Double, Double), (Double, Double), (Double, Double), (Double, Double))

ab4 :: Double -> CampoT -> Ventana -> Ventana
ab4 h f ((t0, y0), (t1, y1), (t2, y2), (t3, y3)) = ((t1, y1), (t2, y2), (t3, y3), (t3 + h, y4))
  where
    y4 = y3 + h / 24 * (55 * f t3 y3 - 59 * f t2 y2 + 37 * f t1 y1 - 9 * f t0 y0)

-- el arranque: tres pasos de un método de un paso llenan la ventana
arrancar :: ((Double, Double) -> (Double, Double)) -> (Double, Double) -> Ventana
arrancar paso p0 = (p0, p1, p2, p3)
  where
    p1 = paso p0
    p2 = paso p1
    p3 = paso p2

rk4T :: Double -> CampoT -> (Double, Double) -> (Double, Double)
rk4T h f (t, y) = (t + h, y + h / 6 * (k1 + 2 * k2 + 2 * k3 + k4))
  where
    k1 = f t y
    k2 = f (t + h / 2) (y + h / 2 * k1)
    k3 = f (t + h / 2) (y + h / 2 * k2)
    k4 = f (t + h) (y + h * k3)

heunT :: Double -> CampoT -> (Double, Double) -> (Double, Double)
heunT h f (t, y) = (t + h, y + h / 2 * (k1 + k2))
  where
    k1 = f t y
    k2 = f (t + h) (y + h * k1)

-- y' = −y + sin t, y(0) = 1, y su solución exacta
forzado :: CampoT
forzado t y = - y + sin t

exactaForzado :: Double -> Double
exactaForzado t = (sin t - cos t) / 2 + 1.5 * exp (- t)

-- error de AB4 en t = 2 con n pasos, usando el arrancador dado
errorAB4 :: (Double -> (Double, Double) -> (Double, Double)) -> Int -> Double
errorAB4 arrancador n = abs (y - exactaForzado 2)
  where
    h                 = 2 / fromIntegral n
    (_, _, _, (_, y)) = iterate (ab4 h forzado) (arrancar (arrancador h) (0, 1)) !! (n - 3)

arrancar es la estrategia 1 de la nota conceptual en una línea de tipos: recibe un mapa de un paso y un punto, y devuelve una Ventana. Es imposible empezar a iterar ab4 sin pasar por ella, porque ab4 no acepta otra cosa. Las 3 llamadas a arrancar más los \(n-3\) pasos de AB4 dan \(n\) pasos en total.

Predice. Con arranques de RK4 (\(q = 4\)), Heun (\(q = 2\)) y Euler (\(q = 1\)), ¿qué orden global medirás para AB4?

Ejecuta.

ghci> [ errorAB4 a n | a <- [\h -> rk4T h forzado, \h -> heunT h forzado, \h -> eulerExplicito h forzado], n <- [40, 80, 160] ]
[1.2347655697908522e-7,7.213709629638743e-9,4.330991121292982e-10,1.7029644152732892e-5,2.1240480936324246e-6,2.6498882488290576e-7,1.0449701733594718e-3,2.576623589380933e-4,6.393631489720608e-5]

ghci> [ orden (errorAB4 a) 80 | a <- [\h -> rk4T h forzado, \h -> heunT h forzado, \h -> eulerExplicito h forzado] ]

  • Son las columnas de la tabla de la nota conceptual, en orden: RK4, Heun, Euler, cada una para \(n = 40, 80, 160\).
  • Los órdenes son \(4\), \(3\) y \(2\): \(\min(4,\ q+1)\). Con arranque de Euler, AB4 se comporta como un método de orden 2 durante toda la integración, aunque solo 3 de los pasos usaron Euler.

Idea. BDF2 es implícito y multipaso a la vez: su estado es una ventana de 2 puntos, y cada paso resuelve una ecuación con Newton. Lo comparamos con Euler explícito en el problema rígido de la nota conceptual.

Añade a U3T2.hs:

-- y' = −1000 (y − cos t) − sin t, con solución exacta y = cos t
rigido, drigido :: CampoT
rigido t y  = -1000 * (y - cos t) - sin t
drigido _ _ = -1000

-- BDF2: y₂ = 4/3 y₁ − 1/3 y₀ + 2/3 h f(t₂, y₂), resuelto con Newton
bdf2 :: Double -> CampoT -> CampoT -> ((Double, Double), (Double, Double)) -> ((Double, Double), (Double, Double))
bdf2 h f dfdy ((t0, y0), (t1, y1)) = ((t1, y1), (t2, resolver g dg prediccion))
  where
    t2         = t1 + h
    prediccion = y1 + h * f t1 y1
    g  yy      = yy - 4 / 3 * y1 + 1 / 3 * y0 - 2 / 3 * h * f t2 yy
    dg yy      = 1 - 2 / 3 * h * dfdy t2 yy

Predice. Euler explícito necesita \(h < 0.002\). ¿Qué pasa con \(h = 0.01\), \(0.0021\) y \(0.0019\)? ¿Y con BDF1 (Euler implícito) y BDF2 con \(h = 0.1\)?

Ejecuta.

[1.3280686162497558e90,5.2979468932524305e13,5.140598764441506e-7]

ghci> abs (snd (final 10 (eulerImplicito 0.1 rigido drigido) (0, 1)) - cos 1)

ghci> let v1 = ((0, 1), eulerImplicito 0.1 rigido drigido (0, 1))

ghci> abs (snd (snd (final 9 (bdf2 0.1 rigido drigido) v1)) - cos 1)

Lee.

  • Euler explícito: \(10^{90}\), \(5\times10^{13}\) y \(5\times10^{-7}\). El umbral entre explotar y funcionar está entre \(0.0021\) y \(0.0019\), en \(2/1000\).
  • BDF1 y BDF2, con solo 10 pasos de \(h = 0.1\), dan errores de \(2.8\times10^{-5}\) y \(2.7\times10^{-6}\), los de la nota conceptual.
  • La ventana inicial de BDF2, v1, se llenó con un paso de BDF1: la estrategia 2 del arranque (la propia familia, a orden creciente).

Tu turno. Repite BDF2 con \(h = 0.05\) y 20 pasos. ¿Se divide el error entre \(4\)?

Idea. Los coeficientes de cualquier BDF salen de las diferencias hacia atrás, y se pueden calcular exactamente con Rational. Con ellos medimos el factor de amplificación de BDF1 a BDF6 sobre la ecuación de prueba \(\dot y = \lambda y\), con números complejos.

Recuerda: un método es estable para \(z = h\lambda\) si su factor de amplificación es \(\le 1\).

BDF\(k\) es \(\sum_{j=1}^{k} \frac1j \nabla^j y_{n+1} = h\,f_{n+1}\), donde \(\nabla y_{n+1} = y_{n+1} - y_n\) es la diferencia hacia atrás. Desarrollando con el binomio, el coeficiente de \(y_{n+1-i}\) es \(c_i = \sum_j \frac1j(-1)^i\binom{j}{i}\). Aplicado a \(\dot y = \lambda y\), el método se vuelve la recurrencia

\[(c_0 - z)\,y_{n+1} = -\sum_{i\ge1} c_i\, y_{n+1-i}.\]

Añade a U3T2.hs:

-- coeficientes c₀ … c_k de BDFk, exactos
coeficientesBDF :: Integer -> [Rational]
coeficientesBDF k =
  [ sum [ (1 % j) * fromInteger ((-1) ^ i * binom j i) | j <- [1 .. k], i <= j ] | i <- [0 .. k] ]
  where
    binom n r = product [n - r + 1 .. n] `div` product [1 .. r]

-- factor de amplificación de BDFk en z: tras muchos pasos, |y_{n+1}| / |y_n|
factorBDF :: Integer -> Complex Double -> Double
factorBDF k z = magnitude (ys !! 1) / magnitude (ys !! 0)
  where
    c = map fromRational (coeficientesBDF k) :: [Double]
    -- la ventana es [y_n, y_{n−1}, …]; entra el nuevo, sale el más viejo
    paso ventana = nuevo : init ventana
      where
        nuevo = negate (sum (zipWith (\ci yi -> (ci :+ 0) * yi) (tail c) ventana)) / ((head c :+ 0) - z)
    ys = map head (drop 400 (iterate paso (replicate (fromInteger k) 1)))

Data.Complex escribe el número complejo \(a + bi\) como a :+ b, y magnitude es su módulo. Tras 400 pasos, el modo dominante (el de mayor factor) ha dejado atrás a todos los demás, y el cociente de dos valores consecutivos es su factor.

Predice. En \(z = i\), una oscilación pura, el factor exacto es \(1\). La nota conceptual dice que BDF1 y BDF2 amortiguan y que BDF3 a BDF6 amplifican. ¿Lo confirmarás?

Ejecuta.
