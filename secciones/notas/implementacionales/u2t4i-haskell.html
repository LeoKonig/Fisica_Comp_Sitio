Integración Numérica: Trapecio, Simpson, Cuadratura Gaussiana · Implementación (Haskell)

Nota Implementacional
λ Implementación en: Haskell
← Nota conceptual · Práctica →

Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con GHCi 9.4.7.

Todas las definiciones (bloques sin ghci>) van en un solo archivo, U2T4.hs. Cárgalo con ghci U2T4.hs y usa :reload cada vez que añadas algo. Las consultas (bloques con ghci>) se escriben en GHCi, sin el ghci>.

Una sola función para toda la nota. La nota conceptual dice que un método de cuadratura queda determinado por sus nodos y sus pesos, y que cambiar de método es cambiar esas listas, no el procedimiento. En Haskell lo hacemos literal: una regla es una lista de pares (nodo, peso), y una sola función la aplica a cualquier \(f\).

Archivo U2T4.hs:

import Data.Bits (shiftR)
import Data.List (foldl')
import Data.Word (Word64)

-- una regla de cuadratura: pares (nodo xᵢ, peso wᵢ)
type Regla = [(Double, Double)]

-- Q[f] = Σ wᵢ f(xᵢ)
integrarCon :: Regla -> (Double -> Double) -> Double
integrarCon regla f = sum [ w * f x | (x, w) <- regla ]

integrarCon regla (con un solo argumento) es una función de orden superior: recibe \(f\) y devuelve un número. Todas las reglas de esta nota, incluso Monte Carlo, pasan por ella.

  • Trapecio y Simpson
  • Cuadratura gaussiana
  • Monte Carlo

Idea. El trapecio y Simpson usan los mismos nodos equiespaciados y distintos pesos. Construimos las dos reglas como listas y comprobamos los órdenes \(2\) y \(4\).

Añade a U2T4.hs:

-- n + 1 nodos equiespaciados en [a, b]
nodos :: Double -> Double -> Int -> [Double]
nodos a b n = [ a + fromIntegral i * (b - a) / fromIntegral n | i <- [0 .. n] ]

-- pesos h · (½, 1, 1, …, 1, ½)
reglaTrapecio :: Double -> Double -> Int -> Regla
reglaTrapecio a b n = zip (nodos a b n) [ h * c | c <- coeficientes ]
  where
    h = (b - a) / fromIntegral n
    coeficientes = [0.5] ++ replicate (n - 1) 1 ++ [0.5]

-- pesos (h/3) · (1, 4, 2, 4, …, 2, 4, 1), con n par
reglaSimpson :: Double -> Double -> Int -> Regla
reglaSimpson a b n
  | odd n     = errorWithoutStackTrace "Simpson requiere n par"
  | otherwise = zip (nodos a b n) [ h / 3 * c | c <- coeficientes ]
  where
    h = (b - a) / fromIntegral n
    coeficientes = [1] ++ take (n - 1) (cycle [4, 2]) ++ [1]

trapecio, simpson :: (Double -> Double) -> Double -> Double -> Int -> Double
trapecio f a b n = integrarCon (reglaTrapecio a b n) f
simpson  f a b n = integrarCon (reglaSimpson a b n) f

cycle [4, 2] es la lista infinita 4, 2, 4, 2, …; take (n - 1) toma solo los coeficientes interiores. Gracias a la evaluación perezosa, la lista infinita nunca se construye completa.

Las dos reglas, lado a lado

Predice. Para \([0, 1]\) con \(n = 4\), ¿qué nodos y qué pesos tendrá cada regla? ¿Cuánto suman los pesos?

Ejecuta.

ghci> reglaTrapecio 0 1 4
[(0.0,0.125),(0.25,0.25),(0.5,0.25),(0.75,0.25),(1.0,0.125)]

ghci> reglaSimpson 0 1 4
[(0.0,8.333333333333333e-2),(0.25,0.3333333333333333),(0.5,0.16666666666666666),(0.75,0.3333333333333333),(1.0,8.333333333333333e-2)]

Lee.

  • Los nodos son idénticos: \(0, \frac14, \frac12, \frac34, 1\). Solo cambian los pesos: \(\frac18, \frac14, \frac14, \frac14, \frac18\) para el trapecio y \(\frac1{12}, \frac13, \frac16, \frac13, \frac1{12}\) para Simpson.
  • En los dos casos los pesos suman \(1 = b - a\): las dos reglas integran exactamente la función constante \(1\).

Los órdenes, medidos

Predice. La nota conceptual da \(Q^T_4 = 1.896119\) y \(Q^S_4 = 2.004560\) para \(\int_0^\pi \sin x\,dx = 2\). Al duplicar \(n\), ¿entre cuánto se divide cada error?

Ejecuta.

ghci> trapecio sin 0 pi 4
1.8961188979370398

ghci> simpson sin 0 pi 4
2.0045597549844207

ghci> [ (n, abs (trapecio sin 0 pi n - 2), abs (simpson sin 0 pi n - 2)) | n <- [4, 8, 16] ]
[(4,0.1038811020629602,4.5597549844207386e-3),(8,2.5768398054449193e-2,2.6916994838721564e-4),(16,6.429656227660896e-3,1.6591047935499148e-5)]

ghci> [ abs (trapecio sin 0 pi n - 2) / abs (trapecio sin 0 pi (2 * n) - 2) | n <- [4, 8] ]
[4.031337215586981,4.007741182738742]

ghci> [ abs (simpson sin 0 pi n - 2) / abs (simpson sin 0 pi (2 * n) - 2) | n <- [4, 8] ]
[16.940059660231025,16.2238063221603]

Lee.

  • Son los valores de la tabla de la nota conceptual.
  • Los cocientes se acercan a \(4 = 2^2\) para el trapecio y a \(16 = 2^4\) para Simpson: órdenes \(2\) y \(4\). En /u2/t5 convertiremos estos cocientes en una medida sistemática del orden.

Simpson es exacto para cúbicas

Predice. Con un solo par de subintervalos en \([0, 1]\), ¿qué dará Simpson para \(\int_0^1 x^3\,dx = \frac14\) y para \(\int_0^1 x^4\,dx = \frac15\)?

Ejecuta.

ghci> simpson (^ 3) 0 1 2
0.25

ghci> simpson (^ 4) 0 1 2
0.20833333333333331

Lee. Con \(x^3\) el resultado es exacto, aunque Simpson se construye con parábolas: el grado extra viene de la simetría de la regla. Con \(x^4\) ya falla: \(0.2083\) en lugar de \(0.2\), como en la nota conceptual. ((^ 3) es la función “elevar al cubo”: una sección del operador ^.)

Tu turno. Pide simpson sin 0 pi 5. ¿Qué ocurre y por qué? Después calcula sum (map snd (reglaSimpson 0 pi 16)): ¿qué número esperas antes de ejecutarlo?

Idea. En Gauss–Legendre los nodos y los pesos se eligen juntos, en \([-1, 1]\). Una regla de Gauss es otra Regla: no hace falta ningún código nuevo para aplicarla, solo una función que la traslade a \([a, b]\).

Recuerda: con \(n\) nodos libres y \(n\) pesos libres, una regla tiene \(2n\) parámetros, y Gauss los usa para integrar exactamente hasta el grado \(2n - 1\).

Añade a U2T4.hs:

-- reglas de Gauss–Legendre en [−1, 1]: nodos = raíces de Pₙ
gauss2, gauss3, gauss5 :: Regla
gauss2 = [ (-1 / sqrt 3, 1), (1 / sqrt 3, 1) ]
gauss3 = [ (-sqrt (3 / 5), 5 / 9), (0, 8 / 9), (sqrt (3 / 5), 5 / 9) ]
gauss5 = [ (-x2, w2), (-x1, w1), (0, 128 / 225), (x1, w1), (x2, w2) ]
  where
    x1 = sqrt (5 - 2 * sqrt (10 / 7)) / 3
    x2 = sqrt (5 + 2 * sqrt (10 / 7)) / 3
    w1 = (322 + 13 * sqrt 70) / 900
    w2 = (322 - 13 * sqrt 70) / 900

-- traslada una regla de [−1, 1] a [a, b]:  x = m + r t,  peso r w
enIntervalo :: Double -> Double -> Regla -> Regla
enIntervalo a b regla = [ (m + r * t, r * w) | (t, w) <- regla ]
  where
    m = (a + b) / 2
    r = (b - a) / 2

gauss2 es la regla que la nota conceptual deduce a mano: nodos \(\pm 1/\sqrt3\) y pesos \(1\). Los nodos y pesos de gauss5 tienen forma cerrada; los escribimos así en lugar de copiar decimales de una tabla. El factor \(r = \frac{b-a}{2}\) de enIntervalo es el del cambio de variable de la nota conceptual.

El límite de exactitud

Predice. gauss2 debería integrar exactamente \(x^2\) y \(x^3\) en \([-1, 1]\) y fallar con \(x^4\) (da \(\frac29\) en vez de \(\frac25\)). Con gauss5, ¿en qué grado empieza a fallar?

Ejecuta.

ghci> integrarCon gauss2 (^ 2)
0.6666666666666669

ghci> integrarCon gauss2 (^ 3)
0.0

ghci> integrarCon gauss2 (^ 4)
0.22222222222222235

ghci> [ integrarCon gauss5 (^ k) | k <- [8, 9, 10] ]
[0.22222222222222218,0.0,0.17888636936255978]

ghci> [ 2 / 9, 0, 2 / 11 ]
[0.2222222222222222,0.0,0.18181818181818182]

Lee.

  • gauss2 integra \(x^2\) (\(\frac23\)) y \(x^3\) (\(0\)) salvo el último dígito, y con \(x^4\) da \(\frac29\): falla justo en el grado \(2n = 4\).
  • gauss5 acierta en \(x^8\) y \(x^9\) y falla en \(x^{10}\): exacta hasta el grado \(2\cdot5 - 1 = 9\).
  • Los últimos dígitos distintos (…669 en lugar de …667) son redondeo de los nodos irracionales, no error del método.

Gauss contra trapecio y Simpson

Predice. Con 5 evaluaciones de \(\sin\), ¿superará Gauss a Simpson con 17?

Ejecuta.

ghci> enIntervalo 0 pi gauss2
[(0.6638966446777875,1.5707963267948966),(2.4776960089120057,1.5707963267948966)]

ghci> [ integrarCon (enIntervalo 0 pi r) sin | r <- [gauss2, gauss3, gauss5] ]
[1.9358195746511366,2.001388913607743,2.0000001102844718]

ghci> [ abs (integrarCon (enIntervalo 0 pi r) sin - 2) | r <- [gauss2, gauss3, gauss5] ]
[6.418042534886337e-2,1.3889136077431807e-3,1.102844717770779e-7]

Lee.

  • Los nodos trasladados ya no son “bonitos” (\(0.66\) y \(2.48\)), y los pesos son \(\pi/2\).
  • Son las filas de Gauss de la tabla de la nota conceptual. Con 5 evaluaciones, el error es \(1.1\times10^{-7}\), más de cien veces menor que el de Simpson con 17 (\(1.7\times10^{-5}\)).

Tu turno. Aplica gauss5 a \(\int_0^1 \sqrt{x}\,dx = \frac23\). ¿Sigue siendo tan precisa? (La pista está en \(\sqrt{x}\) cerca de \(0\); volveremos a esta función en /u2/t5.)

Idea. Monte Carlo también es una Regla: nodos aleatorios uniformes en \([a, b]\), todos con peso \((b-a)/N\). En dimensión \(d\), el promedio se hace sobre puntos de \([0,1]^d\), y el error típico \(\sigma/\sqrt N\) se estima con las mismas muestras.

Números pseudoaleatorios reproducibles

Para que tus resultados coincidan con los de esta nota, no usamos una biblioteca externa de números aleatorios. Escribimos un generador congruencial lineal: una función siguiente que, aplicada repetidamente a una semilla, produce una sucesión de enteros de 64 bits que “parecen” aleatorios. Añade a U2T4.hs:

-- generador congruencial lineal: x ↦ a·x + c  (mód 2⁶⁴)
siguiente :: Word64 -> Word64
siguiente x = 6364136223846793005 * x + 1442695040888963407

-- lista infinita de números uniformes en [0, 1): los 53 bits altos de cada estado
uniformes :: Word64 -> [Double]
uniformes semilla = [ fromIntegral (x `shiftR` 11) / 2 ^ 53 | x <- tail (iterate siguiente semilla) ]

Word64 es un entero sin signo de 64 bits: sus operaciones se hacen módulo \(2^{64}\), así que el desbordamiento no es un error sino parte del generador. Se toman los 53 bits más altos porque un Double tiene 53 bits de mantisa (/u1/t1).

ghci> take 3 (uniformes 42)
[0.5682303266439076,0.2254634289477513,0.41283831882951183]

ghci> take 3 (uniformes 43)
[0.913230842638327,0.6331721115346789,0.4558743901677089]

La misma semilla da siempre la misma lista; otra semilla, otra lista.

Monte Carlo en una dimensión

Añade a U2T4.hs:

-- N nodos aleatorios uniformes en [a, b], todos con peso (b − a)/N
reglaMonteCarlo :: Word64 -> Double -> Double -> Int -> Regla
reglaMonteCarlo semilla a b n =
  [ (a + (b - a) * u, (b - a) / fromIntegral n) | u <- take n (uniformes semilla) ]

Predice. Para \(\int_0^\pi \sin x\,dx = 2\), Gauss con 5 puntos dio 7 cifras. ¿Cuántas dará Monte Carlo con \(N = 10^6\)?

Ejecuta.

ghci> [ integrarCon (reglaMonteCarlo 42 0 pi n) sin | n <- [100, 10000, 1000000] ]
[2.0317487842856043,2.007373519185554,1.998599715162712]

ghci> [ integrarCon (reglaMonteCarlo 7 0 pi n) sin | n <- [100, 10000, 1000000] ]
[1.9808962625239876,1.9968979829503097,2.001096977386755]

Lee.

  • Con un millón de evaluaciones, Monte Carlo da unas 3 cifras. En una dimensión es un mal método: Gauss logró 7 con cinco.
  • Con otra semilla salen otros números. \(\hat I_N\) es una variable aleatoria: lo que se controla es su error típico, no su valor exacto.

Diez dimensiones

Para \(I = \int_{[0,1]^{10}} (x_1^2 + \cdots + x_{10}^2)\,d\mathbf{x} = \frac{10}{3}\) agrupamos los uniformes de \(10\) en \(10\): cada grupo es un punto del hipercubo. Añade a U2T4.hs:

-- parte una lista (infinita) en bloques de d elementos
bloques :: Int -> [a] -> [[a]]
bloques d xs = take d xs : bloques d (drop d xs)

-- (estimación, error típico estimado σ/√N) en [0, 1]^d
monteCarlo :: Int -> ([Double] -> Double) -> Word64 -> Int -> (Double, Double)
monteCarlo d f semilla n = (media, sqrt (varianza / fromIntegral n))
  where
    valores = map f (take n (bloques d (uniformes semilla)))
    -- suma de los valores y de sus cuadrados, en una sola pasada
    (s, s2) = foldl' acumular (0, 0) valores
    acumular (p, q) v = let p' = p + v; q' = q + v * v in p' `seq` q' `seq` (p', q')
    media = s / fromIntegral n
    varianza = s2 / fromIntegral n - media * media

sumaCuadrados :: [Double] -> Double
sumaCuadrados xs = sum [ x * x | x <- xs ]

La varianza se calcula como \(\overline{f^2} - \bar f^{\,2}\) con las mismas muestras, así que el error típico no requiere conocer \(I\). Los seq obligan a sumar en cada paso, en lugar de acumular un millón de sumas pendientes en memoria.

Predice. La nota conceptual calcula \(\sigma = \sqrt{40/45} \approx 0.943\). ¿Qué errores típicos esperas para \(N = 10^2, 10^4, 10^6\)?

Ejecuta. (La consulta con \(N = 10^6\) tarda unos 15 segundos en GHCi. Si cargas el archivo con ghci -fobject-code -O U2T4.hs, tarda menos de uno.)

ghci> sqrt (40 / 45)
0.9428090415820634

ghci> [ monteCarlo 10 sumaCuadrados 42 n | n <- [100, 10000, 1000000] ]
[(3.4122910210968094,9.36175340269981e-2),(3.329424963126183,9.513155527633745e-3),(3.3326918175871443,9.432832208770461e-4)]

ghci> [ abs (fst (monteCarlo 10 sumaCuadrados 42 n) - 10 / 3) | n <- [100, 10000, 1000000] ]
[7.895768776347589e-2,3.908370207150291e-3,6.415157461892029e-4]

Lee.

  • El error típico estimado es \(\approx 0.94/\sqrt N\): \(0.094\), \(0.0095\), \(0.00094\). Multiplicar \(N\) por \(100\) lo divide entre \(10\), la tasa \(N^{-1/2}\).
  • El error real (\(0.079\), \(0.0039\), \(0.00064\)) fluctúa alrededor del error típico, como en la tabla de la nota conceptual; con nuestra semilla los números son otros, pero el comportamiento es el mismo.
  • La dimensión no apareció en ninguna parte del cálculo del error. Con \(10^6\) puntos hay tres cifras en \(d = 10\); una malla de \(10^6\) puntos tendría apenas \(4\) puntos por eje.

Tu turno. Repite el experimento en \(d = 100\) con monteCarlo 100 sumaCuadrados 42 10000 (ahora \(I = 100/3\)). ¿Cambió la tasa \(N^{-1/2}\)? ¿Cambió \(\sigma\)? Compara con \(\sqrt{400/45}\).

Para saber más: ¿qué tan aleatorio es un generador congruencial?

La sucesión \(x_{k+1} = a x_k + c \pmod{2^{64}}\) es completamente determinista: conocida la semilla, se conoce toda la lista. Se llama pseudoaleatoria porque pasa muchas pruebas estadísticas de aleatoriedad. Las constantes de siguiente son las del generador MMIX de Knuth; con ellas el período es \(2^{64}\), el máximo posible.

Los bits bajos de un generador congruencial módulo una potencia de \(2\) son poco aleatorios (el último bit alterna \(0, 1, 0, 1, \ldots\)), por eso uniformes descarta los \(11\) bits bajos con shiftR. Para simulaciones serias se usan generadores mejores (PCG, xoshiro, Mersenne Twister), como los del paquete random de Haskell; la idea, una función de estado a estado aplicada con iterate, es la misma.
