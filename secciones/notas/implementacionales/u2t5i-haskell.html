Comparación Numérica/Analítica, Errores y Convergencia · Implementación (Haskell)

Nota Implementacional
λ Implementación en: Haskell
← Nota conceptual · Práctica →

Cómo leer esta nota. Cada pestaña corresponde a una pestaña de la nota conceptual y sigue el esquema Idea → Predice → Ejecuta → Lee → Tu turno. Todas las salidas se obtuvieron con GHCi 9.4.7.

Todas las definiciones (bloques sin ghci>) van en un solo archivo, U2T5.hs. Cárgalo con ghci U2T5.hs y usa :reload cada vez que añadas algo. Las consultas (bloques con ghci>) se escriben en GHCi, sin el ghci>.

Los métodos que vamos a evaluar. Usamos el trapecio y Simpson de /u2/t4, en una versión compacta para que este archivo no dependa del anterior. Lo nuevo es el tipo Metodo: una aproximación vista como función del número de subintervalos \(n\). Al refinar (\(h \to h/2\)) basta con evaluar en \(2n\).

Archivo U2T5.hs:

nodos :: Double -> Double -> Int -> [Double]
nodos a b n = [ a + fromIntegral i * (b - a) / fromIntegral n | i <- [0 .. n] ]

trapecio :: (Double -> Double) -> Double -> Double -> Int -> Double
trapecio f a b n = h * sum (zipWith (*) pesos (map f (nodos a b n)))
  where
    h = (b - a) / fromIntegral n
    pesos = [0.5] ++ replicate (n - 1) 1 ++ [0.5]

simpson :: (Double -> Double) -> Double -> Double -> Int -> Double
simpson f a b n = h / 3 * sum (zipWith (*) pesos (map f (nodos a b n)))
  where
    h = (b - a) / fromIntegral n
    pesos = [1] ++ take (n - 1) (cycle [4, 2]) ++ [1]

-- un método: número de subintervalos n ↦ aproximación
type Metodo = Int -> Double

-- el trapecio sobre ∫₀^π sin x dx = 2
trapSin :: Metodo
trapSin = trapecio sin 0 pi

trapecio sin 0 pi es aplicación parcial: falta \(n\), así que es un Metodo. Todas las herramientas de esta nota reciben un Metodo y no les importa cómo se calcula.

  • Orden de convergencia
  • El dominio de la ley O(hᵖ)
  • Extrapolación de Richardson

Idea. El orden se mide con \(p \approx \log_2[e(h)/e(h/2)]\) si conocemos la respuesta, y con el test de Cauchy, \(p \approx \log_2[(\hat f_h - \hat f_{h/2})/(\hat f_{h/2} - \hat f_{h/4})]\), si no la conocemos.

Añade a U2T5.hs:

-- p ≈ log₂ (e(h) / e(h/2)),  conociendo el valor exacto
ordenConExacta :: Double -> Metodo -> Int -> Double
ordenConExacta exacta q n = logBase 2 (abs (q n - exacta) / abs (q (2 * n) - exacta))

-- test de Cauchy: p ≈ log₂ ((q_n − q_2n) / (q_2n − q_4n)),  sin el valor exacto
ordenCauchy :: Metodo -> Int -> Double
ordenCauchy q n = logBase 2 (abs (q n - q (2 * n)) / abs (q (2 * n) - q (4 * n)))

-- e(h/2) ≈ |q_2n − q_n| / (2ᵖ − 1)
errorEstimado :: Double -> Metodo -> Int -> Double
errorEstimado p q n = abs (q (2 * n) - q n) / (2 ** p - 1)

Con la solución exacta

Predice. Para el trapecio, ¿qué valores de \(p\) esperas con \(n = 2, 4, 8\)?

Ejecuta.

ghci> map trapSin [2, 4, 8, 16]
[1.5707963267948966,1.8961188979370398,1.9742316019455508,1.9935703437723395]

ghci> [ abs (trapSin n - 2) | n <- [2, 4, 8, 16] ]
[0.42920367320510344,0.1038811020629602,2.5768398054449193e-2,6.429656227660452e-3]

ghci> map (ordenConExacta 2 trapSin) [2, 4, 8]
[2.0467291984005467,2.0112584676114675,2.002789343254819]

Lee. Son las columnas de la primera tabla de la nota conceptual: el orden medido es \(2.047\), \(2.011\), \(2.003\), y se acerca a \(2\) al refinar.

Sin la solución exacta

Predice. Supón que no sabes que la integral vale \(2\). ¿Sigue saliendo \(p \approx 2\) con el test de Cauchy? ¿Qué tan buena es la estimación del error con \(n = 4\) y \(n = 8\)?

Ejecuta.

ghci> [ trapSin n - trapSin (2 * n) | n <- [2, 4, 8] ]
[-0.32532257114214325,-7.8112704008511e-2,-1.933874182678874e-2]

ghci> map (ordenCauchy trapSin) [2, 4]
[2.0582418131759463,2.0140632663811537]

ghci> errorEstimado 2 trapSin 4
2.6037568002837002e-2

ghci> abs (trapSin 8 - 2)
2.5768398054449193e-2

Lee.

  • Las diferencias son las de la segunda tabla de la nota conceptual, y el orden sale \(2.058\) y \(2.014\), usando solo cantidades calculadas.
  • La estimación del error de \(\hat f_8\), \(0.02604\), está a un \(1\%\) del error real, \(0.02577\). Fue calculada sin conocer la respuesta.

El test detecta errores de programación…

La nota conceptual dice que si te equivocas en los pesos \(\tfrac12\) del trapecio, el test da \(p \approx 1\). Añade a U2T5.hs una versión con ese error:

-- ERROR deliberado: todos los pesos valen h (faltan los ½ de los extremos)
trapecioMalo :: (Double -> Double) -> Double -> Double -> Int -> Double
trapecioMalo f a b n = h * sum (map f (nodos a b n))
  where
    h = (b - a) / fromIntegral n

Predice. ¿Qué orden dará el test para trapecioMalo con \(\int_0^1 e^x\,dx\)? ¿Y con \(\int_0^\pi \sin x\,dx\)?

Ejecuta.

ghci> map (ordenCauchy (trapecioMalo exp 0 1)) [8, 16, 32]
[1.0102996810748743,1.005179762837096,1.0025971496921244]

ghci> map (ordenCauchy (trapecioMalo sin 0 pi)) [8, 16, 32]
[2.0034860769756975,2.0008696803813852,2.000217305466992]

Lee.

  • Con \(e^x\), el orden cae a \(1\): el test delata el error. Los pesos de más en los extremos suman \(\frac h2[f(a) + f(b)]\), un error \(O(h)\).
  • Con \(\sin\) en \([0, \pi]\), el test dice “orden 2” y el error pasa inadvertido, porque \(\sin 0 = \sin\pi = 0\): los pesos equivocados multiplican ceros.

…si la prueba es buena. Una función de prueba que se anula en los extremos no puede detectar un error en los pesos de los extremos. Para verificar un código, elige funciones que no tengan simetrías especiales.

Tu turno. Calcula map (ordenCauchy (simpson exp 0 1)) [2, 4, 8]. ¿Sale \(4\)? Después introduce un error en los pesos de Simpson (por ejemplo, cycle [2, 4] en lugar de cycle [4, 2]) y mide el orden otra vez.

Idea. La ley \(e(h) \approx Ch^p\) vale solo en una ventana de \(h\), y solo para funciones suaves. Medimos el orden aparente de Simpson en dos casos donde no es \(4\): la función de Runge (régimen pre-asintótico) y \(\sqrt{x}\) (función poco suave).

Recuerda: acepta el orden medido solo cuando se estabiliza durante varios refinamientos seguidos.

Añade a U2T5.hs:

runge :: Double -> Double
runge x = 1 / (1 + 25 * x * x)

h demasiado grande: la función de Runge

Predice. Simpson es de orden \(4\). Para \(\int_{-1}^1 \frac{dx}{1+25x^2} = \frac25\arctan 5\), ¿qué orden aparente esperas con \(n = 2, 4, \ldots, 128\)?

Ejecuta.

ghci> let exactaRunge = 0.4 * atan 5

ghci> exactaRunge
0.5493603067780064

ghci> [ abs (simpson runge (-1) 1 n - exactaRunge) | n <- [2, 4, 8, 16, 32, 64, 128, 256] ]
[0.8096140521963524,1.9298414647148765e-2,2.588374291829698e-2,2.696499907336336e-3,1.8163379657321066e-5,9.099849540561422e-9,5.213512954682642e-10,3.260258729653742e-11]

ghci> map (ordenConExacta exactaRunge (simpson runge (-1) 1)) [2, 4, 8, 16, 32, 64, 128]
[5.390680089651108,-0.4235639174586738,3.2628863639289643,7.213911504390126,10.962902357616928,4.125514973583712,3.9991974484833093]

Lee.

  • Es la tabla de la nota conceptual: el orden aparente pasa por \(5.4\), \(-0.4\) (de \(n = 4\) a \(n = 8\) el error crece), \(3.3\), \(7.2\) y \(11\), y solo se estabiliza en \(4\) a partir de \(n = 128\).
  • Con \(n = 128\), \(h = 2/128 \approx 0.016\), bastante menor que el ancho \(\sim\frac15\) del pico central. Antes de eso, la malla no “ve” la forma de la función.

Una función poco suave: √x

Predice. \(\sqrt{x}\) es continua y acotada en \([0, 1]\). ¿Converge Simpson? ¿Con qué orden?

Ejecuta.

ghci> [ abs (simpson sqrt 0 1 n - 2 / 3) | n <- [4, 8, 16, 32] ]
[1.0140401874095928e-2,3.5873865816431483e-3,1.2684780385139316e-3,4.4848392048701946e-4]

ghci> map (ordenConExacta (2 / 3) (simpson sqrt 0 1)) [4, 8, 16]
[1.4991097033376362,1.499834678578545,1.4999703756902505]

ghci> map (ordenCauchy (simpson sqrt 0 1)) [4, 8, 16, 32]
[1.4987129767168197,1.4997604556065982,1.4999570475471034,1.4999923791197052]

Lee.

  • El orden se estabiliza limpiamente en \(1.5\), no en \(4\). No es un régimen pre-asintótico: es el orden verdadero para esta función, porque sus derivadas divergen en \(x = 0\).
  • El test de Cauchy da el mismo \(1.5\) sin conocer el valor exacto. Este es el número que necesitaremos en la pestaña siguiente.

El remedio: cambiar de variable

Con \(x = u^2\), \(\int_0^1 \sqrt x\,dx = \int_0^1 2u^2\,du\), un polinomio de grado \(2\):

ghci> simpson (\u -> 2 * u * u) 0 1 2
0.6666666666666666

Con tres evaluaciones, Simpson da \(2/3\) salvo el último bit. A veces mejorar la formulación del problema vale más que refinar la malla.

Tu turno. El tercer modo de salir de la ventana, el redondeo, ya lo viste en /u2/t2. Allí, ordenObservado errorCentrada 1e-6 daba un orden negativo. ¿Por qué con la cuadratura es tan difícil llegar a ese régimen? (Pista: compara el número de evaluaciones necesarias para que \(h^4 \approx \varepsilon_{\text{mach}}\).)

Idea. Si el error es \(\approx Ch^p\) con \(p\) conocido, \(\hat f^* = (2^p\hat f_{h/2} - \hat f_h)/(2^p - 1)\) cancela el término dominante. En Haskell, extrapolar un método da otro método, al que se le puede volver a medir el orden, o volver a extrapolar.

Recuerda: \(\hat f_h \approx f + Ch^p\) y \(\hat f_{h/2} \approx f + Ch^p/2^p\).

Añade a U2T5.hs:

-- f* = (2ᵖ f_{h/2} − f_h) / (2ᵖ − 1)
richardson :: Double -> Double -> Double -> Double
richardson p gruesa fina = (2 ** p * fina - gruesa) / (2 ** p - 1)

-- extrapolar un método produce otro método
extrapolar :: Double -> Metodo -> Metodo
extrapolar p q n = richardson p (q n) (q (2 * n))

El tipo Double -> Metodo -> Metodo dice lo importante: extrapolar p transforma un método en otro, y el resultado se puede pasar a ordenConExacta, a ordenCauchy o a extrapolar otra vez.

Simpson es el trapecio extrapolado

Predice. La nota conceptual dice que Richardson con \(p = 2\) aplicado al trapecio con \(n = 2\) y \(n = 4\) da exactamente Simpson con \(n = 4\). ¿Coincidirán todas las cifras?

Ejecuta.

ghci> richardson 2 (trapSin 2) (trapSin 4)
2.0045597549844207

ghci> simpson sin 0 pi 4
2.0045597549844207

ghci> richardson 4 (simpson sin 0 pi 4) (simpson sin 0 pi 8)
1.999983130945986

ghci> abs (simpson sin 0 pi 8 - 2)
2.691699483881038e-4

Lee.

  • Coinciden en todas las cifras: Simpson es el trapecio extrapolado, como afirma la nota conceptual.
  • Un nivel más (Romberg): extrapolar Simpson con \(p = 4\) da \(Q^{**} = 1.999983\), con error \(1.7\times10^{-5}\), unas \(16\) veces menor que el de \(Q^S_8\), sin evaluar \(f\) en ningún punto nuevo.

Medir el orden del método extrapolado

Predice. Para Simpson, cuyo error solo tiene potencias pares, extrapolar con \(p = 4\) debería dar orden \(6\). Compruébalo con ordenConExacta.

Ejecuta.

ghci> let rs = extrapolar 4 (simpson sin 0 pi)

ghci> [ abs (rs n - 2) | n <- [2, 4, 8, 16] ]
[1.429268176164289e-3,1.6869054014101437e-5,2.475454281558598e-7,3.809155435519074e-9]

ghci> map (ordenConExacta 2 rs) [2, 4, 8]
[6.404753754900992,6.09054195711883,6.022078335224068]

Lee. Es la tabla “caso suave” de la nota conceptual: orden \(6.40\), \(6.09\), \(6.02\), que tiende a \(p + 2 = 6\). Medimos el orden del método nuevo con la misma función que usamos para el trapecio, porque rs también es un Metodo.

Con el p incorrecto

Predice. Para \(\sqrt{x}\), con \(n = 16\) y \(n = 32\), ¿cuánto mejora Richardson si supones \(p = 4\) (el del libro)? ¿Y con \(p = 1.5\) (el medido)?

Ejecuta.

ghci> abs (simpson sqrt 0 1 32 - 2 / 3)
4.4848392048701946e-4

ghci> abs (extrapolar 4 (simpson sqrt 0 1) 16 - 2 / 3)
3.938176459519216e-4

ghci> abs (extrapolar 1.5 (simpson sqrt 0 1) 16 - 2 / 3)
1.4245688850778038e-8

Lee.

  • Con \(p = 4\), el error baja de \(4.5\times10^{-4}\) a \(3.9\times10^{-4}\): casi nada.
  • Con \(p = 1.5\), baja a \(1.4\times10^{-8}\): unas \(30\,000\) veces.

La fórmula cancela \(Ch^p\) solo si ese es el término que realmente domina. El orden que hay que usar es el medido.

Tu turno. No hace falta escribir 1.5 a mano: usa el orden que mide el test de Cauchy, extrapolar (ordenCauchy (simpson sqrt 0 1) 8) (simpson sqrt 0 1) 16. ¿Qué error obtienes? ¿Por qué es algo peor que con exactamente \(1.5\)?

Para saber más: la tabla de Romberg

Romberg aplica Richardson una y otra vez: la primera columna son trapecios con \(n, 2n, 4n, \ldots\); la segunda, sus extrapolaciones con \(p = 2\) (que son Simpson); la tercera, extrapolaciones con \(p = 4\); y así, subiendo \(p\) de \(2\) en \(2\). Igual que la tabla de diferencias divididas de /u2/t1, cada columna sale solo de la anterior. Añade a U2T5.hs:

-- columnas de Romberg; la columna k se extrapola con p = 2k
romberg :: Metodo -> Int -> Int -> [[Double]]
romberg q n niveles = columnas 2 [ q (n * 2 ^ k) | k <- [0 .. niveles - 1] ]
  where
    columnas p col
      | length col <= 1 = [col]
      | otherwise       = col : columnas (p + 2) (zipWith (richardson p) col (tail col))
ghci> map last (romberg trapSin 2 5)
[1.998393360970144,2.0000010333694123,1.9999999961908441,2.000000000059674,1.9999999999960334]

ghci> map (abs . subtract 2 . last) (romberg trapSin 2 5)
[1.6066390298559163e-3,1.033369412262175e-6,3.809155879608284e-9,5.967404348439231e-11,3.966604822380759e-12]

La mejor aproximación de cada columna mejora de \(10^{-3}\) a \(4\times10^{-12}\). El cálculo más fino es un trapecio con \(n = 32\): con solo \(33\) evaluaciones de \(\sin\), Romberg da casi doce cifras.

Para saber más: la diferencia centrada como Richardson

La nota conceptual muestra que promediar las diferencias hacia adelante con pasos \(h\) y \(-h\) da la diferencia centrada. Compruébalo:

ghci> let adelante h f x = (f (x + h) - f x) / h

ghci> (adelante 0.1 exp 0 + adelante (-0.1) exp 0) / 2
1.001667500198441

ghci> (exp 0.1 - exp (-0.1)) / 0.2
1.001667500198441

Coinciden en todas las cifras: dos estimadores de orden \(1\) cuyos errores dominantes tienen signos opuestos se combinan en uno de orden \(2\).
