Condición y Estabilidad · Implementación (Agda)

Nota Implementacional
✦ Implementación en: Agda (cambiar)
← Conceptual u1t4 · ← Conceptual u1t5 · Práctica →

Las notas conceptuales u1t4 y u1t5 trazan la distinción que organiza todo el análisis numérico: la condición es una propiedad del problema (cuánto amplifica la función matemática los errores de entrada), la estabilidad es una propiedad del algoritmo (si introduce amplificación de más). Y culminan en una promesa que el preámbulo del curso hace explícita: existe “el tipo de un integrador que garantiza conservación de energía”, y terminar el módulo en Agda significa haberlo demostrado, no observado. Esta nota es donde esa promesa se cobra. El tipo Conserva es el certificado; construir un término de ese tipo es la demostración. El compilador, obtuso e insistente, no acepta el certificado sin la prueba — y sabe distinguir lo que se puede demostrar (la conservación exacta) de lo que solo se puede medir (la ausencia de deriva).

El núcleo: un integrador y su invariante, lado a lado

El sistema de prueba es el oscilador armónico adimensional ẍ + x = 0, cuyo estado es (posición, velocidad). El archivo Propagation.agda define un paso de Euler simpléctico — una variante que, por el orden en que actualiza las variables, casi conserva la energía.

{-# OPTIONS --erasure #-}
module Propagation where
open import Haskell.Prelude

record State : Type where
  constructor MkState
  field pos vel : Double
open State public
{-# COMPILE AGDA2HS State #-}

-- Euler SIMPLÉCTICO: v' = v − dt·x ; x' = x + dt·v'
-- (primero la velocidad con la x vieja, luego la posición con la v nueva:
--  ese orden es lo que lo hace simpléctico y casi-conservativo.)
stepSymplectic : Double → State → State
stepSymplectic dt (MkState x v) =
  let v' = v - dt * x
      x' = x + dt * v'
  in MkState x' v'
{-# COMPILE AGDA2HS stepSymplectic #-}

El detalle físico está en el orden: la posición nueva usa la velocidad ya actualizada. Ese pequeño desajuste respecto al Euler ingenuo es lo que distingue un algoritmo que conserva estructura de uno que la destruye — exactamente la diferencia entre condición y estabilidad que u1t4 pide tener presente.

La energía sombra: lo que el método conserva exactamente

El integrador no conserva la energía verdadera ½(x² + v²). Conserva una energía sombra ligeramente distinta — y la conserva de forma exacta, paso a paso. El archivo la define:

-- La energía sombra que el método conserva EXACTAMENTE paso a paso.
shadowEnergy : Double → State → Double
shadowEnergy dt (MkState x v) = v * v + x * x - dt * x * v
{-# COMPILE AGDA2HS shadowEnergy #-}

El término extra − dt·x·v es la corrección que el análisis de error hacia atrás (u1t5) predice: el método no resuelve tu problema, sino uno perturbado en O(dt), cuyo invariante es esta sombra. Y ahora viene lo característico de la vía de Agda — enunciar la conservación como un tipo:

-- PROPOSICIÓN: el paso preserva la energía sombra. Enunciar el tipo ES
-- afirmar la conservación; habitarlo es DEMOSTRARLA.
Conserva : Double → State → Set
Conserva dt s = shadowEnergy dt (stepSymplectic dt s) ≡ shadowEnergy dt s

Lee Conserva dt s como la frase física que es: “tras un paso de tamaño dt desde el estado s, la energía sombra es la misma que antes”. Es una proposición — un Set — parametrizada por el paso y el estado. El preámbulo del curso prometía “el tipo de un integrador que garantiza conservación”; este es ese tipo, escrito.

La diferencia entre demostrar y observar

Aquí el estudiante obtuso e insistente impone una disciplina que ninguna corrida impone. La afirmación ∀ dt s → Conserva dt s es una identidad algebraica: hay que verificar que

\[v'^2 + x'^2 - dt\,x'v' \;=\; v^2 + x^2 - dt\,x v\]

tras sustituir v' = v − dt·x y x' = x + dt·v'. Esto sí es demostrable —no depende del redondeo, es álgebra pura— y por eso el tipo Conserva puede habitarse. Lo verificamos sobre aritmética racional exacta, donde la igualdad es literal:

Lo que responde el verificador racional (ℚ, sin redondeo) 
¿ΔH_sombra = 0 exacto bajo un paso de Euler simpléctico?
  estado (2,5)     : ΔH = 0 % 1
  estado (1,0)     : ΔH = 0 % 1
  estado (-3,4)    : ΔH = 0 % 1
  estado (7/2,-1/3): ΔH = 0 % 1
  → la energía sombra es invariante EXACTO. Conserva es habitable.

ΔH = 0 exacto, para todo estado: la sombra no se mueve ni un racional. Por eso Conserva es un teorema genuino y no un deseo. La nota es honesta en algo importante: un Euler explícito ingenuo no admitiría un habitante de este tipo — su energía sombra deriva con el número de pasos, y el compilador, al no poder cerrar la prueba, lo delataría. El tipo separa los buenos integradores de los que “parecen funcionar en los tests”.

La energía verdadera: esto solo se observa

La conservación exacta es de la sombra. La energía verdadera ½(x²+v²) oscila —acotada, sin derivar, pero oscila— y eso ya no es una identidad algebraica: es el comportamiento de la trayectoria a lo largo de muchos pasos. No se demuestra con un refl; se mide ejecutando. El archivo extrae el iterador para eso:

-- Iterar el integrador n pasos. SÍ se extrae: produce la trayectoria
-- cuya energía imprimimos para VER la conservación.
iterate' : Nat → Double → State → State
iterate' zero    _  s = s
iterate' (suc n) dt s = iterate' n dt (stepSymplectic dt s)
{-# COMPILE AGDA2HS iterate' #-}

Al correr el programa extraído sobre una trayectoria larga:

Lo que responde el programa extraído (Haskell) 
== 6. INTEGRADOR que CERTIFICA conservacion (oscilador x'' + x = 0)
  Euler simplectico: la energia SOMBRA es invariante por paso (teorema en Agda).
  paso    0:  H_sombra = 1.000000000000
  paso  100:  H_sombra = 1.000000000000
  paso  500:  H_sombra = 1.000000000000
  paso 1000:  H_sombra = 1.000000000000
  paso 5000:  H_sombra = 1.000000000000
  H_sombra no deriva: el invariante @0 que Agda exigio se cumple al correr.

La energía sombra se queda clavada en 1.000000000000 durante 5000 pasos — la contraparte ejecutable del teorema Conserva. Lo demostrado (la sombra es invariante exacto) y lo observado (la trayectoria larga no deriva) coinciden: el número que corre confirma la prueba que el compilador verificó.

Condición vs estabilidad, vistos en el código

La distinción central de u1t4-u1t5 queda encarnada en esta separación de capas:

Concepto Quién lo decide Dónde vive en el código
Condición del problema la función matemática (κ de u1t3) kappa — se mide sobre la traza dual
Estabilidad del algoritmo el integrador (stepSymplectic) Conserva — se demuestra como tipo
Estabilidad hacia atrás (u1t5) que el método resuelve un problema vecino la energía sombra, no la verdadera

La regla de oro de u1t5 —estabilidad hacia atrás + problema bien condicionado ⟹ error hacia adelante pequeño— tiene aquí su ilustración: stepSymplectic es estable (conserva exactamente la sombra, un problema vecino en O(dt)), y como el oscilador está bien condicionado, la energía verdadera no puede derivar. El tipo Conserva captura la primera mitad de esa implicación, y el compilador garantiza que se cumple antes de dejar correr una sola iteración.

Ejecuta tú

agda Propagation.agda            # el tipo Conserva debe ser habitable
agda2hs Propagation.agda -o .    # extrae stepSymplectic, shadowEnergy, iterate'
runghc MainU1.hs                 # mide la energia sombra a lo largo de 5000 pasos

Requiere Agda 2.6.x con agda2hs. El experimento que enseña la diferencia: define un Euler ingenuo stepNaive dt (MkState x v) = MkState (x + dt*v) (v - dt*x) (nota el orden: ambos usan los valores viejos) e intenta habitar Conserva para él. No podrás — su energía sombra no se conserva, y el compilador no cerrará la prueba. Luego córrelo en el harness y verás su energía derivar con los pasos. El estudiante obtuso te avisó en compilación lo que la corrida confirma después.
